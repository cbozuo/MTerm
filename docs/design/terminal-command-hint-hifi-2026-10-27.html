敲命令时，提示框贴在光标那一格上，
发现下方不够就自己翻到上面去。

这是给 MTerm 终端写的命令提示信息框方案：一个贴光标、会翻边、四段式的浮层。 它不做「替你敲字」的自动补全器，而做「告诉你这条命令是什么、接下来该填什么」的信息框—— 候选列表与键盘脚注是它的全部，命中危险命令才多出一条红色告警。 它与 shell 的 Tab 补全分工共存：Tab 永远是 shell 的，提示框只占 ↑↓Enter→（Shift+Enter 是 Enter 的填入变体）； ↑↓ 选中后 Enter＝执行那条命令，鼠标点击行＝填入，只填入不执行走 →（鬼影）或 Shift+Enter。 下面 §1 是可以直接打字试的活沙盘，§2–§7 是位置规则、内容清单、触发抑制、键盘契约与落地分期。

位置 锚定光标单元格，不是锚定输入框 横向对齐光标、越界夹紧；纵向优先向下，下方放不下整盒才向上翻。终端里「下方」通常是空白行，代价最小。
内容 两段 + 一条条件告警 候选列表与键盘脚注是常驻的全部；命中危险命令才出现红色告警条。头部与 94px 详情区已砍——上下文提示符里就有，一句话说明行内就有。
克制 候选 1→3 条时锁 3 行高 从 1 条变 3 条，列表区高度不变＝不跳；超过 3 条才按行长高，到 5 行为止。Esc 之后整行不再自动弹。
分工 Tab 永远是 shell 的 提示框只占 ↑ ↓ Enter → 四个键，Tab 透传给 shell 做路径/文件补全，两套补全系统零打架（§5）。

去重：三道闸，重复的候选一行都不该出现

闸口规则说明
① 历史写入侧同一条命令全局去重，只存一条，保留最近时间戳与累计频次已有 MTerm 历史本就全局去重；要守住的是「去重 ≠ 丢弃频次」——频次是排序权重（见下），去重只合并条目不抹掉计数
② 跨来源合并同一命令文本同时命中快捷命令与历史 → 合并为一条，tag 取来源优先级更高的一边（快捷 > 内置 > 历史），分数取两边最大需新增 JetBrains/Warp 口径：一条命令只占一行、来源可标注。沙盘数据里 git commit -m "fix: …" 与 tail -n 200 … 就各撞了一次，合并后只剩快捷那条
③ 词与行不互斥内置命令名（git）与历史整行（git status）文本不同，不算重复，两条都保留重复判据是整段填入文本完全一致，不是「看起来像」——词补全和整行预测服务的是两种意图

04什么时候弹、什么时候忍住不弹

业界经验很一致：默认「边打边弹」的补全器都会在成熟前先被关掉（VS Code 的 quickSuggestions 默认全 off，Warp 的输入时补全菜单也是可开关项）。所以本方案把「弹出」拆成两条独立通路：自动弹只是加速器，显式唤起才是保底。

触发/抑制条件行为
自动弹 · 命令阶段当前是第一个词，且累计输入 ≥ 2 字符，距上次按键 ≥ 90ms弹；列表高度按 min(max(n,3),5) 行锁定，所以 1→3 条时高度不变。单字符时忍住——敲一个 l 就弹一屏是补全器被关掉的头号原因；显式唤起不受此限
自动弹 · 参数阶段已输入空格，且第一条命令在知识库里有 spec弹；无 spec 的命令（自建脚本）不弹，避免弹空壳
自动弹 · 路径阶段当前 token 含 / 或 ~/弹，先出缓存命中项，异步结果回来只替换内容、不改高度
显式唤起Ctrl+Space（macOS ⌃Space）任何时候强制弹，并解除本行的抑制。必须允许改绑——这个组合常被输入法占用
抑制 · Esc用户按过 Esc本行剩余输入不再自动弹；行清空后重置
抑制 · 全屏应用is-alt-screen 为真（vim / htop / btop / less）完全不弹——那些界面里没有 shell 行可补
抑制 · 密码输入上一条可见输出匹配 password / passphrase / sudo 提示完全不弹，且提示框若已开则立刻关——避免在密码位置旁显示历史命令
抑制 · 批量粘贴单次输入 > 1 行，或 200ms 内 > 24 个字符不弹，直到下一次真实按键
关闭 · 内容消失候选为 0 且非「显式唤起」直接关，不画「无匹配」空壳（沿用现有 #cmdbar-suggest-empty 口径）
为什么是 90ms 而不是 300ms：这是「按键停止」的判据，不是「让人思考」的判据。人连续打字的间隔通常在 120–200ms，取 90ms 能把「词内连打」合并成一次重排，又不会在第一个字符上明显延迟。真值应在实现时实测，这里给的是起点。

05键盘契约：每个键都要能说清「被谁吃了」

终端里加浮层最大的风险不是长得丑，是抢键。原则：提示框只在「已经打开」时接管按键，且永远不碰 Tab；遇到边界要「穿透」回 shell，而不是把方向键吞掉。

Tab 的归属：三种主流模式，MTerm 选「分工共存」

模式代表Tab 给谁对 MTerm
全接管Warp、Amazon Q（原 Fig）建议窗口——它把命令、子命令、参数、路径全部包圆，shell 补全被整体取代不适用 P3 之前没有自己的路径数据源，接不住 Tab
分工共存Fish autosuggestions、PSReadLine 预测永远 shell——建议用 → / Enter 接受，Tab 永远是路径/文件补全采用 键位一句话说得清，与两大 shell 的肌肉记忆兼容
编辑器模式VS Code / JetBrains 的输入下拉建议窗口（编辑器里没有 shell，Tab 无主）不适用 终端里 Tab 有主人
分工一句话：「选命令」用提示框（↑ ↓ Enter →），「补路径/文件」用 Tab（shell）。 提示框可见时按 Tab，按键照样透传给 PTY；shell 补全的回显会改变当前行，提示框按新行重新匹配——它不吞 shell 的结果，只在自己的数据源（快捷命令 / 历史 / 内置知识库）里找活干。 代价是「敲 gi 想补成 git」要多按一次键（→ 接受鬼影，或 ↑↓ 选中后 Shift+Enter 填入）；换来的是敲 cd doc + Tab 想补路径时，永远不会被一条恰好匹配的历史命令截胡——后者才是终端里真正高频的场景。
按键提示框打开时提示框关闭时边界处理
↑ / ↓进入/移动导航选中：新弹出时无选中项（默认不高亮），首按选中当前指向的候选交给 shell（历史）首项再按 ↑ → 穿透：关闭提示框，并把这次 ↑ 交给 shell 历史（沙盘里直接回填上一条历史命令）；末项再按 ↓ → 关闭（shell 的 ↓ 在空提示符上没有动作，不必透传）。列表内到头即停，不循环——循环会让「已经看到最后一行」的人多按很多次
Tab仍交给 shell（透传），提示框保持打开；shell 补全的回显改变当前行后，按新行重算候选交给 shell（原生补全）提示框永不接管 Tab。路径/文件补全是 shell 的看家本领，MTerm 在 P3 之前没有自己的路径数据源，抢 Tab 只会把最准、最常用的补全弄坏
→光标在行尾且有鬼影 → 接受：整行预测（历史/快捷）替换整行，词级补全（命令名/子命令/参数）只补当前词shell（移动光标）光标不在行尾时不接管，避免和「光标右移」冲突。任何阶段都有鬼影——命令阶段补命令名、参数阶段补参数词、有整行历史前缀时补整行，这是「Tab 归 shell」之后命令补全的捷径
Enter未导航（无选中项）→ 执行当前输入；已导航（↑↓ 选过）→ 执行选中候选（整行替换为候选后执行）执行当前输入「选中即执行」是本稿定稿：看到对的命令，一次 Enter 就跑，不再要求「先填入、再回车」两步。防误执行只保留一条底线：没导航过就回车，执行的永远是你敲的那条——敲 shutdown -h now 回车执行的是 now，绝不被候选偷换成历史里的 15:00。危险命令执行前有红色告警条压阵
Shift+Enter已导航 → 仅填入选中项（不执行），选中态复位、提示框继续；未导航 → 同 Enter 执行当前输入—给「想接着敲参数」的人留的填入口：填入后行尾补空格＝阶段落定信号，提示框切到下一阶段（子命令 → 参数 → 路径）继续。词级填入用 →（鬼影）
Esc关闭 + 抑制本行shell关闭后第二次 Esc 才归 shell
Ctrl+Space—强制唤起需实现为可改绑；默认不绑——该组合常被输入法占用，macOS 上 ⌘Space 是系统 Spotlight，按不到应用内
鼠标点击行选中 + 填入（不执行）—与历史面板「点行＝填入」同口径，执行只交给 Enter——点击落进输入行后，直接回车即执行。悬停只高亮不选中，避免列表跟着鼠标抖

四个高频疑问

场景行为
敲两个字母，匹配就弹、不匹配就不弹？是。自动弹的门槛是 ≥ 2 字符；匹配数 ≥ 1 即弹、= 0 直接不画框（连「无匹配」空壳都没有）。Esc 后本行不再自动弹，清空行才重置。
选中命令后想继续敲参数，提示框还会出现吗？会，且内容升维。Enter 是执行，想「填入后继续敲」用 Shift+Enter（填入整条）或 →（补当前词）——填入后行尾自动补一个空格＝阶段落定信号，提示框立即切到下一阶段（命令 → 子命令 → 参数 → 路径）重新匹配。同时整行历史始终在场：敲 git commit -m "，只要历史里有 git commit -m "fix: …"，框就继续弹。只有 0 匹配 / 被抑制时才消失。
Tab 到底听谁的？永远听 shell 的。提示框打开时按 Tab，被补的仍是 shell 的路径/文件；提示框按回显后的新行重算自己的候选。想用提示框补命令：→（鬼影一步补全）或 ↑↓ 选中后 Shift+Enter（仅填入）。
同一条命令既是历史又存了快捷命令，会出两行吗？不会。候选先按「整段填入文本」合并去重：一条命令只占一行，tag 取最高优先级来源（快捷 > 内置 > 历史），频次与新旧取两边最大值参与排序。列表里的每一行都对应一条可独立执行的命令，没有重复项。

06状态机：五个状态，两条退出路径

状态少是刻意的。每个状态都能被一个按键或一个事件明确终结，不存在「既开着又关着」的中间态。

Idle无框、无鬼影。按键 → 判定阶段
→

07落地路径：为什么不能一步做到「终端内」

这部分是读完现有代码之后写的，决定了方案能不能落地。核心事实：MTerm 现在读不到「终端里正在敲的那一行」。

三个必须正视的现实（均已在代码里核实）：
① 终端按键在 key-pressed 里逐键 send-key 直发 PTY，ime-input 用完即清，Slint 与 Rust 两侧都没有行缓冲（ui/terminal_view.slint:1938-1954）。
② 没有任何 OSC 133（提示符开始 / 命令开始标记）。现有 shell 钩子只发 OSC 7（cwd）、OSC 697（命令执行完后回报）、OSC 699（安装完成），见 src/ssh/impls/ssh.rs:208-209。
③ 终端光标的 cell-w / cell-h 是 Slint 私有 property（ui/terminal_view.slint:1211-1212），UI 之外拿不到，要外露才能算锚点。
阶段宿主前置条件风险产出
P0命令栏（cmd-bar 输入框） 零后端 文本完全已知，suggest_models 现成 低。需要把 300px 窄列表升级成四段式，并把锚点从「贴命令栏上沿、只跟横向」改成完整二维跟随（现有只缓存了 cmd-caret-x，没缓存 y） 组件 + 键盘契约 + 回归测试全部在这轮定型
P1终端内联（只读降级） 启发式 从 vt100 网格反推「提示符之后到现在光标」的文本 中。提示符是用户自定义的（PS1 可以是任意串），靠正则必然有漏；识别不出就不弹，绝不猜 覆盖默认 bash/zsh 提示符的绝大多数用户
P2终端内联（精确） 扩展 shell 钩子 在 PROMPT_BODY 里补 OSC 133 风格的 A/C 标记 低。现有钩子已经在注入并处理回声抑制，加标记是一条增量；需同时改 prompt_setup_supported 的白名单与回声剥离 100% 准确的行边界，且能顺带做「命令起止」高亮
P3远端路径 + 参数 spec 异步 SFTP 列目录 + 知识库补全 中。SFTP 是异步命令-事件配对，必须带缓存与「过期即丢弃」，不能阻塞按键 路径与参数级建议

一句话总结：位置跟光标格走（不是跟随输入框）、内容两段半（列表+脚注+条件告警，头部与详情区已砍）、弹出靠词边界而非计时（≥2 字符才弹）、键盘只在打开时接管且永不碰 Tab（Enter 选中即执行、Shift+Enter 与 → 才是填入，鼠标点击＝填入，其余按键全部透传）、落到代码上先做命令栏再动终端。这份稿子可以直接作为 ui/command_hint.slint 的验收基准。
