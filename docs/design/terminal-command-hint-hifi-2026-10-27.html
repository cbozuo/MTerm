敲命令时，提示框贴在光标那一格上，
发现下方不够就自己翻到上面去。

这是给 MTerm 终端写的命令提示信息框方案：一个贴光标、会翻边、四段式的浮层。 它不做「替你敲字」的自动补全器，而做「告诉你这条命令是什么、接下来该填什么」的信息框—— 候选列表在上，当前选中项的语法签名与说明在下，键盘契约钉在脚注上。 下面 §1 是可以直接打字试的活沙盘，§2–§7 是位置规则、内容清单、触发抑制、键盘契约与落地分期。

位置 锚定光标单元格，不是锚定输入框 横向对齐光标、越界夹紧；纵向优先向下，下方放不下整盒才向上翻。终端里「下方」通常是空白行，代价最小。
内容 四段：上下文 / 候选 / 详情 / 键盘 详情区固定 94px 高，换选中项不推动布局；命中危险命令时整块换成红色告警条，复用现有 danger 语言。
克制 候选 1→3 条时锁 3 行高 从 1 条变 3 条，列表区高度不变＝不跳；超过 3 条才按行长高，到 5 行为止。Esc 之后整行不再自动弹。

④ 压终端上不能用 popup-bg

popup-bg = slot-panel，而终端底 term-bg = slot-tbg，两套 MTerm 主题里这两个值完全相同。压终端必须升到 slot-elev + border-strong 描边 + 投影。亮色档 tbg 与 panel 同样相等（#FAF8F4），两档都一样：描边不是装饰，是唯一的分隔手段。

第 4 条为什么值得单列：现有命令栏补全浮层用的是 Theme.popup-bg（ui/terminal_view.slint:2962）。它坐在命令栏（zone-sidebar-alt = #1B1D21）上方，与底色差 3 个色阶，靠描边还能看；一旦搬到终端区上，底色就是 #181A1D 对 #181A1D——框会“消失”，只剩一圈边框。这不是审美问题，是 token 语义问题。

03界面内容：四段，每段都能说出「为什么有它」

提示框刻意只做四段。多做一段（比如标签筛选、搜索框）就会变成「第二个命令管理面板」，而用户此刻只想补一个参数。

    上下文条（27px）回答「我在哪儿、现在补什么」。左边是 user@host : cwd（数据现成：OSC 7 已解析成 CwdChanged）；中间阶段胶囊在命令 / 子命令 / 参数 / 路径之间切换，让用户知道框为什么弹；右边计数让人有「还有多少」的量感。
  2. 2
    候选列表（3–5 行）每行三段：类型图标（⚡快捷命令 / 🕘历史 / 📖内置 / 📁路径）、等宽主文本（命中片段 accent 高亮，不用底色块）、一句话副标题与来源标签。副标题是「扫视时可跳过」的信息，宽度不够先丢它。
  3. 3
    详情区（固定 94px）只有选中项需要解释。语法签名用等宽体，参数占位走 accent、可选参数走 warning；说明最多两行；底行是来源与使用频次。高度固定——换行、换选中项都不推动上下两段，这是「不跳」的关键。
  4. 4
    键盘脚注（23px）四个动作常驻，不用记。它同时也是「这个框是给键盘用的」的声明，减少鼠标用户被劫持的困惑。

04什么时候弹、什么时候忍住不弹

业界经验很一致：默认「边打边弹」的补全器都会在成熟前先被关掉（VS Code 的 quickSuggestions 默认全 off，Warp 的输入时补全菜单也是可开关项）。所以本方案把「弹出」拆成两条独立通路：自动弹只是加速器，显式唤起才是保底。

触发/抑制条件行为
自动弹 · 命令阶段当前是第一个词，且累计输入 ≥ 1 字符，距上次按键 ≥ 90ms弹；列表高度按 min(max(n,3),5) 行锁定，所以 1→3 条时高度不变
自动弹 · 参数阶段已输入空格，且第一条命令在知识库里有 spec弹；无 spec 的命令（自建脚本）不弹，避免弹空壳
自动弹 · 路径阶段当前 token 含 / 或 ~/弹，先出缓存命中项，异步结果回来只替换内容、不改高度
显式唤起Ctrl+Space（macOS ⌃Space）任何时候强制弹，并解除本行的抑制。必须允许改绑——这个组合常被输入法占用
抑制 · Esc用户按过 Esc本行剩余输入不再自动弹；行清空后重置
抑制 · 全屏应用is-alt-screen 为真（vim / htop / btop / less）完全不弹——那些界面里没有 shell 行可补
抑制 · 密码输入上一条可见输出匹配 password / passphrase / sudo 提示完全不弹，且提示框若已开则立刻关——避免在密码位置旁显示历史命令
抑制 · 批量粘贴单次输入 > 1 行，或 200ms 内 > 24 个字符不弹，直到下一次真实按键
关闭 · 内容消失候选为 0 且非「显式唤起」直接关，不画「无匹配」空壳（沿用现有 #cmdbar-suggest-empty 口径）
为什么是 90ms 而不是 300ms：这是「按键停止」的判据，不是「让人思考」的判据。人连续打字的间隔通常在 120–200ms，取 90ms 能把「词内连打」合并成一次重排，又不会在第一个字符上明显延迟。真值应在实现时实测，这里给的是起点。

05键盘契约：每个键都要能说清「被谁吃了」

终端里加浮层最大的风险不是长得丑，是抢键。原则：提示框只在「已经打开」时接管按键，关闭时一个键都不多占；遇到边界要「穿透」回 shell，而不是把方向键吞掉。

按键提示框打开时提示框关闭时边界处理
↑ / ↓移动选中项交给 shell（历史）穿透：在首项再按 ↑ → 关闭提示框，并把这次 ↑ 交给 shell 历史（沙盘里直接回填上一条历史命令）
Tab把选中项填入（不执行）交给 shell（原生补全）只在有可见候选时接管；0 候选时放行给 shell 的原生补全。填完保持提示框打开以继续补参数
→若光标在行尾且有鬼影 → 接受鬼影shell（移动光标）光标不在行尾时不接管，避免和「光标右移」冲突
Enter选中项已等于当前输入 → 执行；否则 先填入执行当前输入两段式，防误执行。判据是行尾是否已落定（行尾有空格＝已落定→执行；否则先填入并补空格），不是拿单词比整行
Esc关闭 + 抑制本行shell关闭后第二次 Esc 才归 shell
Ctrl+Space—强制唤起需实现为可改绑；默认不绑——该组合常被输入法占用，macOS 上 ⌘Space 是系统 Spotlight，按不到应用内
Ctrl+↑/↓收起/展开详情区（临时让出 94px）—给「想多看几行候选」的人一个出口。实现时组合键必须先于裸方向键判断，否则永远走不到
鼠标点击行选中 + 填入—单击填入不执行；悬停只高亮不选中，避免列表跟着鼠标抖

06状态机：五个状态，两条退出路径

状态少是刻意的。每个状态都能被一个按键或一个事件明确终结，不存在「既开着又关着」的中间态。

Idle无框、无鬼影。按键 → 判定阶段
→
Suggesting框已开、有候选、详情区显示选中项。↑↓ Tab → ↵ Esc
↔
Empty0 候选且非危险 → 不画框，与 Idle 外观相同（只有危险命令的告警会在 0 候选时仍然显示）
→
Suppressed本行静默，只响应显式唤起。只有「行被清空」才解除，打字不清除
→
Executing瞬态（不落状态字段）：框先关，命令才发往 PTY
「执行」必须先关框再发键。 反过来的话，PTY 回显和提示框重绘会抢同一帧，视觉上就是「命令已经跑了，框还挂在屏幕上」。这一条在实现时是硬顺序，不是风格问题。

07落地路径：为什么不能一步做到「终端内」

这部分是读完现有代码之后写的，决定了方案能不能落地。核心事实：MTerm 现在读不到「终端里正在敲的那一行」。

三个必须正视的现实（均已在代码里核实）：
① 终端按键在 key-pressed 里逐键 send-key 直发 PTY，ime-input 用完即清，Slint 与 Rust 两侧都没有行缓冲（ui/terminal_view.slint:1938-1954）。
② 没有任何 OSC 133（提示符开始 / 命令开始标记）。现有 shell 钩子只发 OSC 7（cwd）、OSC 697（命令执行完后回报）、OSC 699（安装完成），见 src/ssh/impls/ssh.rs:208-209。
③ 终端光标的 cell-w / cell-h 是 Slint 私有 property（ui/terminal_view.slint:1211-1212），UI 之外拿不到，要外露才能算锚点。
阶段宿主前置条件风险产出
P0命令栏（cmd-bar 输入框） 零后端 文本完全已知，suggest_models 现成 低。需要把 300px 窄列表升级成四段式，并把锚点从「贴命令栏上沿、只跟横向」改成完整二维跟随（现有只缓存了 cmd-caret-x，没缓存 y） 组件 + 键盘契约 + 回归测试全部在这轮定型
P1终端内联（只读降级） 启发式 从 vt100 网格反推「提示符之后到现在光标」的文本 中。提示符是用户自定义的（PS1 可以是任意串），靠正则必然有漏；识别不出就不弹，绝不猜 覆盖默认 bash/zsh 提示符的绝大多数用户
P2终端内联（精确） 扩展 shell 钩子 在 PROMPT_BODY 里补 OSC 133 风格的 A/C 标记 低。现有钩子已经在注入并处理回声抑制，加标记是一条增量；需同时改 prompt_setup_supported 的白名单与回声剥离 100% 准确的行边界，且能顺带做「命令起止」高亮
P3远端路径 + 参数 spec 异步 SFTP 列目录 + 知识库补全 中。SFTP 是异步命令-事件配对，必须带缓存与「过期即丢弃」，不能阻塞按键 路径与参数级建议
