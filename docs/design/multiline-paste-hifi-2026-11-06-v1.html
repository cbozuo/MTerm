确认多行粘贴 Confirm multi-line paste

本稿把「粘贴多行文本」从通用 ConfirmDialog（380px、为 SFTP 删除/主机密钥设计的窄卡片） 升级为一个专用评审面：一次看清多少行、多少字符、几处风险、会不会立即执行、粘到哪个会话。 版式继承同一组件家族——同一 popup-bg 卡片、radius-lg、同款 Scrim、 同一 30px / radius-sm 按钮，只做「加宽 + 预览区 + 危险前置」，不另起一套风格。 三档自适应：紧凑 380px（1–3 行 且 ≤600 字符）、标准 640px（4–12 行 且 ≤600 字符）、 评审 min(宽-40px,1160px)（>12 行 或 >600 字符，任一超出即评审档）。权威规则：src/terminal/impls/input.rs:93-104（COMPACT_LINE_LIMIT=12 / COMPACT_CHAR_LIMIT=600）。

事实底稿：docs/design/multiline-paste-spec-2026-11-06.md（§4 色板、§4.4 对比度、§5.1 三档、§5.2 预览七项、§5.3 D1–D5、§6 验收）。 所有颜色值均可追溯到 §4 槽位名（slot-*），页面内逐处注释标注。暗/亮为整页切换，zh/en 为页内切换 + 关键文案并列。

01

设计说明

现状 vs 新设计 · 对标取舍 · D1–D5 结论 · 对比度实测 · 验收对照

现状：380px 通用确认框扛不住多行粘贴

  • 触发：中键 / Ctrl+Shift+V → 文本含 \r/\n 时弹通用 ConfirmDialog（src/app.rs:12759）。
  • 预览是原文整段裸文本：无行号、无等宽约束、无危险标记、无折行策略、无截断出路（src/app.rs:12762）。
  • 没有「只粘贴不执行」出口：尾部换行会被 normalize_pasted_newlines 归一成 CR，粘完就回车、直接执行。
  • 两档切换生硬（380 ↔ 1160），5–12 行的中等内容无档位；控制字符被 encode_pasted_text 静默剥离。
  • confirm-on-enter 让 Enter 直接确认（#392）；危险行与白字红底按钮的对比度也不达标（白字 on slot-dg 仅 3.28:1 ❌）。

新设计：加宽档 + 危险前置 + 默认安全

  • G1 一眼可判：顶部统计条固定宽 N 行 · M 字符 · K 处风险（tabular-nums，1↔47 行不跳动）。
  • G2 危险前置：危险行 = 左 2px 竖标 + 11% 淡染 + 行尾「图标 + 中文类别名」徽标（颜色不是唯一载体）。
  • G3 执行必须显式：主按钮「粘贴（不含末尾回车）」是安全动作（Enter = 主按钮）；「粘贴并执行」是描边式危险按钮，只能点击或按 Alt+P；Esc = 取消。
  • G4 同源：仍是 popup-bg 卡片 + radius-lg + Scrim + 30px 按钮（主/危险 radius-sm，取消 = GhostButton radius-md）+ 可拖动，可看出是「同一家族的加宽档」。
  • G5 三档（紧凑 1–3 行 且 ≤600 字符 / 标准 4–12 行 且 ≤600 字符 / 评审 >12 行 或 >600 字符，任一超出；src/terminal/impls/input.rs:93-104）与 G6 键盘可达：Tab 序 = 视觉序、Esc = 取消、Enter = 安全动作，焦点环 1px accent。
  • 对账完整性：--field-2 / --danger-strong / --popup-bg-inset 三个派生 token 已按权威值逐值对齐（ui/theme.slint:285 / 335 / 251），但全稿 0 引用，仅为 spec §4.2 对账完整性保留，不参与渲染。

比值来源分两类，便于逐项对账。（1）权威脚本逐值复现（node .tmp-lead/contrast.mjs）：9.38 / 12.37（t1→panel）、9.72 / 11.53（t1→root）、5.32 / 5.22（dg→panel）、8.29（ac→panel 暗）/ 5.13（亮）、8.58 / 5.13（实心底上的字）、3.28（白字 on 暗 dg）、4.28 / 4.25（t2）、2.57（亮 t3→palt）、4.00 / 4.14（elev/inset 上的 t1）、3.66 / 3.02（t3）。（2）含 alpha/opacity 合成或文档层变量、权威脚本未覆盖，由本稿按同一 WCAG 2.1 相对亮度公式复算：popup-bg = 暗 rgba(24,26,29,.98) 压 slot-root → rgb(24,26,29)、亮 rgba(250,248,244,.98) 压 slot-root → rgb(250,248,244)；11% danger 淡染合成后 = 暗 rgb(49,32,37)、亮 rgb(242,228,224)；透明度系数 ×.72 / ×.8 / ×.85 按「字色先与底色合成、再算对比」处理；文档层直接取 --doc-* 变量原值。此前手算的 3 处偏差（动作条 8.04、警告 8.23、安全 6.72）已按实算值 9.72 / 8.09 / 6.60 更正。判定阈值取 spec §4.4：正文 ≥4.5、次要/装饰 ≥3、大字号 ≥3。

与主流对标的取舍（依据研究稿 10 家对标）

  • 默认动作（D1 · 终态）：主按钮 = 「粘贴（不含末尾回车）」（安全动作：剥离尾 CR/LF，最后一行留在命令行不执行）；「粘贴并执行」= 描边式危险按钮，等价现状 encode_pasted_text 原样行为；原文末尾无换行时只渲染一个主按钮「粘贴」（无危险按钮）。iTerm2 的 Paste Without Newline 与 VS Code 对单行尾换行的处理正是这个方向的证据。
  • 键盘（D2 · 终态）：主流把 Enter 绑成首选动作（WT DefaultButton="Primary"、Tabby defaultId:0）——本稿保留 Enter 的可用性但把它重定向到安全动作：Enter = 主按钮（不含末尾回车），Alt+P = 粘贴并执行，Esc = 取消。Enter 绝不触发执行。
  • 可记忆（D3）：VS Code 有「Do not ask me again」并持久化为 never；iTerm2 按 identifier 静默；WT / Tabby 无复选框只有设置项。→ 采纳复选框，写回既有 paste_confirm_enabled（不新增设置键）。
  • 危险前置（D4）：10 家全部没有任何危险命令标记（行级语义提示是本稿的增量）。kitty 对危险控制码也只做确认而非拒绝 → 本稿行级标记只提示、不阻断，可容忍误报。
  • bracketed 不等于安全（D5）：WT GH#13014 证明 bracketed paste 可被远端用逃逸序列开启，从而让多行警告失效；PowerShell/cmd 就是「支持该模式但不做多行保护」的反例。→ 故本稿不用「bracketed 已开」免除确认：两种状态都要确认，主按钮文案也不因 bracketed 而改，只用顶部一行说明与徽标调整提示强度（关闭时改说「远端未开启 bracketed paste：整段多行将逐行执行。」）。这与 WT Automatic 的做法相反。
  • 取舍：不引入「逐行复选框」等重交互（SSH 场景要快），复杂度只放在一眼可判与安全默认两件事上。

键盘与焦点（G6 / §5.4）

  • Enter = 主按钮（安全动作「粘贴（不含末尾回车）」）——Enter 绝不触发「粘贴并执行」；执行类动作必须显式点击或按 Alt+P。
  • Alt+P = 粘贴并执行（危险动作的快捷键）；Esc = 取消并关闭（点背板不关闭，与现状 dismiss-on-backdrop=false 一致，#262）。
  • Tab / Shift+Tab = 视觉顺序 = DOM 顺序：关闭 ✕ → 折行开关 → 预览区（tabindex="0"，可聚焦滚动）→ 取消 → 主按钮 → 粘贴并执行 → 不再提示多行粘贴。
  • 默认焦点落在主按钮上（accent 实底 + outline:1px slot-ac 焦点环）——「Enter 命中安全动作」在视觉上可直接读出。
  • 焦点管理：初始化 focus() 到首个未关闭状态帧的主按钮（静态稿用 autofocus + focus() 演示，落地时对应 terminal-focus-sequence += 1）；取消 / 关闭后把焦点交回该帧终端区（tabindex="-1"）；弹框内可聚焦元素均带显式 tabindex，顺序 = 视觉序。
  • 焦点环：outline:1px solid slot-ac + outline-offset:2px，不改变布局尺寸。
1.1

决策点 D1–D5 · 本稿采用结论

研究稿已落地（multiline-paste-research-2026-11-06.md，204 行 / 33 个来源）；D1–D5 以 Lead 终态裁定与 spec §5.3 为准
D1默认动作改造后采纳

终态（Lead 裁定）：主按钮 = 「粘贴（不含末尾回车）」（accent 实底 + 深色字，默认焦点 / Enter）——剥离尾 CR/LF，最后一行留在命令行不执行；「粘贴并执行」是描边式危险按钮（slot-dg 字 + 1px slot-dg 边 + 透明底，Alt+P），等价现状 encode_pasted_text 的原样行为；原文末尾无换行时只渲染一个主按钮「粘贴」（不出现危险按钮）。命中 A 级危险命令时主按钮文案追加后缀 → 「粘贴（已去掉末尾回车）」。三个变体在本页都有实例：无尾换行 = A 帧、有尾换行无 A 级 = D 帧、有尾换行 + A 级 = B / C / E / F / G 帧。

理由：尾换行经 normalize_pasted_newlines 归一成 CR → 粘贴即回车 = 远程执行且不可逆；VS Code 对「单行 + 尾换行」静默去尾以防剪贴板劫持，iTerm2 专门提供 Paste Without Newline——把「执行」从默认路径里拿掉、留一个显式出口，是这两条既有证据的直接延伸。文案：粘贴（不含末尾回车） / Paste without trailing newline · 粘贴并执行 / Paste and run · 取消 / Cancel。

与研究稿的差异说明：研究稿 §③ D1 的建议是「原样粘贴」为主按钮、「去掉尾部回车」并列一等。本页以 Lead 终态裁定为准（spec §5.3 已改写），取更保守的排布：主按钮 = 安全动作「粘贴（不含末尾回车）」，「原样执行」降级为描边式危险按钮「粘贴并执行」并配 Alt+P。理由：终端无法预知远端 shell 语义（研究稿 §②.10 的 bracketed 反例已说明「远端支持该模式」≠「远端不会执行粘贴内容」），默认路径必须是不会执行的那一条；方向与 iTerm2 Paste Without Newline、VS Code 单行去尾一致，只是把它从「并列」提升为「默认」。文案：粘贴（不含末尾回车） / Paste without trailing newline · 粘贴并执行 / Paste and run · 取消 / Cancel。

hover 只变描边、不变底色：主按钮 hover/active 的背景恒为 slot-ac，--ac-hov（暗 #25DDC8 / 亮 #238478）只用于 border-color。因为亮色 --ac-hov 作底时 --on-solid（#FAF8F4）只有 4.26:1 < 4.5 ❌；保持 slot-ac 实底则亮色 5.13:1 ✓、暗色 8.58:1 ✓，与对账表「主按钮 .btn.primary」行（表内第 8 行、HTML 第 1226 行）的静态态一致。

D2回车语义安全默认

终态（Lead 裁定）：Enter = 主按钮（安全动作「粘贴（不含末尾回车）」）——Enter 绝不触发「粘贴并执行」；Alt+P = 粘贴并执行；Esc = 取消（关闭，不粘贴）。

理由：主流把 Enter 绑成首选动作（WT DefaultButton="Primary"、Tabby defaultId:0）——本稿保留 Enter 的可用性但把它重定向到不执行的那一侧，于是「键盘流仍是一下 Enter 就结束」，而误触的代价从「远程执行」降到「多粘了一段文本」。也顺带修掉现状 confirm-on-enter（#392）把 Enter 当确认的过强语义。

可视化：页脚左侧固定一行 Enter = 主按钮「粘贴（不含末尾回车）」（安全动作，绝不执行），按钮本身不带图标、不带快捷键键帽（与项目现状 ui/widgets.slint GhostButton/PrimaryButton 的 dialog-chrome 口径一致，按钮只渲染文字）；快捷键以这行文字说明呈现，主按钮是默认焦点，带 1px accent 焦点环。

D3记住选择采纳

采用（研究稿 D3）：一个复选框「不再提示多行粘贴」，勾选并确认后写回既有设置 paste_confirm_enabled = false（不新增设置键）。

理由：paste_confirm_enabled 已是默认 true 的既有设置项，映射无需新状态；VS Code 也是同类「Do not ask me again」并持久化。

边界（复选框下方常驻小字，Lead 终态要求）：文案写「含危险命令或超过 100 KB 时仍会提示」——即该开关不影响 100 KB 强制复核路径（force_review）与 A/B 级危险命令提示。

D4危险命令清单与文案改造后采纳 · 只提示不阻断

采用（研究稿 D4）：A/B 两级行级标记 + 中文类别名 + 框顶汇总「本段含 N 处危险命令」。

A 级（不可逆破坏）标红（slot-dg 11% 淡染 + 左 2px 竖标 + 行尾「图标 + 中文类别名」徽标）：递归强制删除 rm -rf、格式化文件系统 mkfs、直写块设备 dd of=/dev/、覆盖磁盘设备 >/dev/sd*、fork 炸弹、清空/截断文件 :> file / truncate -s 0、关机或重启 shutdown/reboot/halt/poweroff/init 0|6、数据库破坏 DROP DATABASE|TABLE / dropdb。

B 级（提权 / 管道执行）标黄（slot-wr 同口径）：权限提升 sudo / su -、权限全开 chmod 777 / chown -R、管道执行远端脚本 curl|sh / wget|bash、账户与凭据变更 useradd/usermod/passwd/visudo、防火墙变更 iptables/nft/ufw/firewall-cmd、强制终止进程 kill -9/pkill/killall、痕迹清理与持久化 history -c / crontab -r、丢弃本地改动 git reset --hard / git clean -f、卸载软件包 apt remove|purge / yum|dnf remove。共 16 条模式，逐条表见研究稿 §③（标注为「本设计建议」，非外部权威引用）。

理由：终端无法解析 shell 语义（引号 / 变量 / 别名 / 函数），正则只能提示不能判定；kitty 对危险控制码也只做确认而非拒绝 → 本稿只提示、不阻断，可容忍误报。行级标记可解释，且颜色不是唯一载体（每行都有图标 + 中文类别名，满足 UX 规范第 5 条）。

A 级额外后果（Lead 终态）：存在 A 级行时，主按钮文案追加后缀 → 「粘贴（已去掉末尾回车）」，把「剥离尾回车」从礼貌默认升级为强制默认；要原样执行必须显式走「粘贴并执行」。

D5目标上下文采纳

采用（Lead 终态）：卡片顶部一行 chips —— 粘贴到 <tab 名> · <user@host:port> · Bracketed paste 开/关；只用一行，不放整段会话详情。

bracketed 关（D 帧）：提示句「远端未开启 bracketed paste：整段多行将逐行执行。」（.notice.warn）。bracketed 开（A/B/C/E/F 帧）：提示句「整段会进入编辑缓冲。」（chips 里以徽标形式承载：Bracketed 已启用 · 整段进入编辑缓冲）。两种状态都确认，主按钮文案不因 bracketed 而改。

理由：SSH 场景常在多标签间粘贴，「粘到哪个会话」是 0.5s 内必须可判的信息（G1）。而不能用「bracketed 已开」免除多行确认：WT GH#13014 已证明该模式可被远端用逃逸序列开启，从而使多行警告失效（PowerShell/cmd 就是支持模式但不做多行保护的反例）——故 bracketed 只用来调整顶部说明与提示强度（不改主按钮文案、不免除确认），这与 WT Automatic 的做法相反，也正是研究稿给出的本项目结论。

继承自权威色板的不达标项（未改色值）

  • slot-t2 4.28:1（暗）/ 4.25:1（亮） —— 不达正文 4.5:1。本稿没有让 t2 承载任何正文：预览正文、统计条、标签栏、提示一律 slot-t1。
  • 白字 + slot-dg 实心 = 3.28:1（暗） —— 这正是现状 DangerButton 实心态的问题（ui/confirm_dialog.slint:7-31）。本稿的危险动作改描边式（5.32 / 5.22 ✓），仅 hover 转实心且字色换 slot-root。
  • slot-t3 压 slot-palt 亮色仅 2.57:1 —— 本稿在主按钮与标题栏改用 slot-t1 加透明度系数（6.04–6.96 ✓）。
  • slot-t2 压 slot-palt / slot-elev 只有 4.14 / 4.00:1（slot-t1 压同两个面实为 9.08 / 8.78，可用）—— 本稿把所有承载文字的面退回 popup-bg 或 slot-root，elev/inset 只留给无文字的装饰件（拖动条、关闭图标），且从不让 slot-t2 承载正文。
  • 以上均源自身份色板 src/theme/palettes.rs 自身，按 spec §4.4 第 ⑦ 条，高保真不得为达标而改 §4.1 色值，只能按用法规则选色——此处只做用法规避，色值一字未动。

本稿新增的「用法 token」（非色板值）

  • --on-solid = 暗 #161619 / 亮 #FAF8F4：定义即 slot-root / slot-panel 的原值，只是给「实心底上的字」一个名字，用于 .btn.primary 与危险按钮 hover 态。
  • --dg-ink = 暗 slot-dg 原值 #F75464 / 亮 #8E2F28：唯一非 §4.1 原值的用法色，只用于「压在 11% danger 淡染上的文字」。亮色下 slot-dg 原值压淡染只有 4.47:1（差一点不达标），故压到 #8E2F28 得 6.55:1。它不改变任何既有 slot 的取值，也不出现在危险色实心底/徽标上（那里仍用 slot-dg 原值）。
  • --wr-line / --wr-soft / --ac-hov：都是「既有色 + alpha」或「同相提亮」的派生用法，未引入新色相。
  • 请评审重点确认 --dg-ink 是否被判定为「引入新色值」；若判定为不允许，替代方案是危险提示文字直接用 slot-dg（亮 4.47:1，仅差 0.03）或把提示底改成不透明 popup-bg。
