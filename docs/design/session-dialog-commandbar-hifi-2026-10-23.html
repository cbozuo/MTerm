输入框收窄到 620。一条命令很少超过 60 字符，剩下的空间本来就是空的。收窄后右侧不再挤：范围键能写全「全部标签页」，发送键也不必压到 56 宽。

04

两个决策

初始文案 / 快捷命令的位置

初始文案：别再叫「所有会话」

项目里「会话」已经被侧栏保存的连接占用了。命令栏发的是已打开的标签页， 用同一个词会让用户以为发给了侧栏里所有连接（包括没打开的）。

所有会话 → 全部标签页3

菜单第一项也同步改为「全部标签页 · 3 个」。如果嫌四个字长，退一步用「全部」（配合菜单里的说明），但不要用「会话」。

快捷命令放在最左，不合理

  • 它是输入辅助，不是独立动作 —— 点它是为了「往输入框里塞一条命令」，和右侧的「去哪发」不在一个层级
  • 最左是视线起点、也是最高频位置，但它的使用频率排在「输入命令」之后
  • 它和「历史」是同一种东西（一个来自预置、一个来自记录），却分居两端
  • 窗口变窄时它第一个被挤掉，输入框起点跟着跳

改法：并到输入框右端（⚡ / 🕘），输入框从最左开始。两者都作用于「输入」，位置和语义就对齐了。

05

还能往前走哪几步

按价值排序 · 每张卡都有示意
MUST

危险命令：发送键变红，点完再确认一次

$ rm -rf /var/log/*
⚠这条命令将发往 5 台机器 取消 仍然发送

检测 rm / shutdown / mkfs / dd / 重定向 > 等模式， 发送键转红，点它不是发送而是确认。多目标命令最怕的就是这一条。

HIGH

发送前：悬停发送键，先看发给谁

$systemctl restart nginx
2 个频道5
这条命令将发到：
web-01 · web-02 · db-01 · cache-01 · api-01

悬停发送键浮出目标清单（机器名，不是只写台数）。手一滑能看到这次会打到哪几台，比「5」这个数字有用。

HIGH

输入即补全：不用点开快捷命令面板

$dock
docker compose ps快捷
docker compose logs -f历史 · 3 天前
docker system df历史 · 上周

输入三个字符就开始建议：快捷命令和历史合成一个来源，Tab 接受、↑↓ 选、Esc 关。 比点开面板快一个量级。

MID

「发送」拆成两个动作

$df -h
⌄ 展开：○ 发送到终端（不执行）　● 发送并执行

现在「点击即执行」藏在快捷命令的开关里，发出去才知道执行了。把模式提到发送键旁边， 按 Ctrl+Enter 直接执行、Enter 只发送。

MID

发送后：上方出结果条

✓已发送 4 / 5 台 · db-02 断线 重发这台

选了 5 台、实际送到 4 台时界面必须写出来，不能让用户以为全发了。 失败的机器一键重发，不用重新选范围、重新输命令。

NO

不建议做的

  • 宏录制 / 命令队列：把多条命令排成序列执行。这该用快捷命令组解决，不该塞进命令栏。
  • 分屏结果显示：发送后把命令栏变成结果面板。结果应该出现在各个标签页自己的终端里，不是命令栏。
  • AI 补全：命令预测模型。本地命令词库 + 历史已经足够，上模型是杀鸡用牛刀。

什么时候该弹出来：命令超过两行、要写 for / while / heredoc、或者需要一边看上面的输出一边改命令。一行的 df -h 不值得弹窗。
收起 = 回到条状，不是关掉命令栏。Esc 或右上角 × 把内容原样带回底部那条，命令栏一直在；只有发送成功才清空。想让终端更大是另一件事（命令栏左侧的折叠键），不该靠关弹窗实现。

弹窗里多出来的三样东西

  • 左侧快捷 / 最近列表：条状放不下，弹窗有空间。点一条插入到光标处，不覆盖已写的。
  • 行号 + 光标：多行脚本没有行号很难数括号。行号只是显示，不参与复制。
  • 底部「管理快捷命令…」：跳到现有的快捷命令管理界面，不在弹窗里另做一套增删改 —— 两个地方都能改，状态迟早不一致。

范围选择键也在弹窗底部 —— 否则用户在弹窗里写完命令，还得收起来才能改发给谁。

危险命令：告警只在编辑区下方、贴着发送键

rm -rf /var/log/*
⚠检测到删除操作 rm -rf · 将发往 5 台机器
2 个频道5

位置不是随便选的：它夹在代码和发送键之间——视线从最后一行代码落到按钮上，必经这一条。 放到标题下面会像「输入格式错了」，但危险命令不是格式问题。

这一条占的是预留位置（高 28），出现时不改动弹窗高度 —— 否则每敲一个字符弹窗都跳一下。

怎么让它消失
把 rm -rf 删掉就行 —— 检测跟着输入实时跑， 告警条自己消失、按钮变回绿色「发送」。

所以不需要「取消」：不点发送本来就不会发；要退出告警，改命令即可。

要拖到第二个屏幕长时间写脚本，把同一个弹窗升级成独立窗口即可（复用 EditorWindow 的框架，内容还是这一份）。

向上浮，不向下长。命令栏下面就是 SFTP，往下长会把它推走；往上浮只临时压住终端最后一两行，而且正好在「刚敲完命令」的视线位置。
横向与命令栏同宽、同圆角。不挂在输入框上，因为告警说的是「这条命令 + 这个范围」，两个都要看，所以覆盖整条。

怎么交互

  • 输入命中危险模式 → 告警浮出，发送键同时变红「仍然发送」（同一帧，不分两步）
  • 改掉命令 → 告警与红色一起消失，按钮变回绿色「发送」
  • 点「仍然发送」→ 直接发出，不弹第二个确认
  • 没有「取消」按钮：右侧小字「改掉命令即可取消」就是退出方式

和弹窗里有什么不同

  • 弹窗里空间大，告警占预留槽位，出现不改变高度
  • 停靠条里高度固定，告警浮在上层，不占布局 —— 两者都不让周围跳动
  • 文案一致：都是「检测到什么 · 影响几台」，切换形态不用重新理解

你问「还缺什么」——我补了六条

前两条是必须做，后四条是边界，不做会在真实使用里出问题。

MUST 01

勾选是草稿，点「完成」才写回

多选很容易点错：选了三个又全取消，发送范围不该跟着变。所以菜单维护一份草稿， 底部实时显示结果，「完成」才写回按钮；点外部或 Esc 全部回滚。

MUST 02

多选时菜单不能关

单选可以「点完即关」，多选不行：关掉再打开、再找回位置，选第三个频道就崩溃了。 勾选只更新勾与计数，关闭靠点外部或 Esc。

EDGE 03

发送前要重新校验

菜单开着时，某个频道的成员可能刚好退出/关标签。按打开菜单那一刻的成员表发送会打空。 发送时按 id 重新取一次并集，空的就跳过。

EDGE 04

发送后要回执「发给了几台」

选了 2 个频道、实际只送到 3 台（有一台刚断线），界面上必须写「已发送 3 / 4」。 否则用户永远不知道自己漏了哪台。

EDGE 05

频道多了要有上限与搜索

4 个频道一屏放得下，20 个就放不下。菜单限高 ≈320px 内部滚动； 超过 8 个时顶部出搜索框（与分组选择器同一个模式，不另造一种）。

EDGE 06

键盘也要能选

↑↓ 移动、Space 勾选（菜单不关）、Esc 关闭、 Enter 直接发送。开关是命令栏高频区，不能只支持鼠标。
