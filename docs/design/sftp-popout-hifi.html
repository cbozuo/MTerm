v2 优化清单 · 参照主流取什么

参照 WinSCP（右键/权限/队列契约）、Transmit / Cyberduck（简洁浏览器 + 拖拽移动）、Termius（现代过滤与隐藏文件开关）、Windows Explorer（右键菜单惯例与快捷键）。

右键六场景← WinSCP / Explorer

行与空白之外补齐：树节点（新建/刷新/复制路径/在终端打开）、列头（列显示）、路径框（复制/粘贴前往）、队列任务（暂停/取消/重试）、标题栏（置顶/停靠/最小化）。菜单样式 26px 行沿用实机 SftpMenuItem。

文件管理标准操作← Explorer / ForkLift

复制（Ctrl+C）→ 粘贴（Ctrl+V）生成副本；Del 删除、F2 重命名、Ctrl+A 全选、Ctrl+F 过滤；拖文件行到树目录 = 移动（落点高亮）。

可见性三件套← Termius / Cyberduck

隐藏文件开关（工具栏 eye，状态栏计数）；搜索过滤条（Ctrl+F 展开实时过滤 + 命中计数）；批量操作行（勾选 > 0 时工具栏出现下载/复制到标签页/删除）——实机 selected-count 契约。

质感细节← Transmit

导航加载条（列表顶 2px accent 流条）；排序列头 accent-tonal 高亮 + 常显方向箭头；文件类型四档着色（脚本琥珀/配置 accent/文档次级/隐藏弱化）；自绘 tooltip 悬浮钮上方（对齐实机 SftpTooltip 负 y）。

v4 质感与可达性 · 本轮改了什么

四项都只动表现层与前端语义，不改项目代码；每项都给出实机落地位置，且只用项目已有的能力（Slint drop-shadow / accessible-role / PanelAnim.reduced / 现有回调），无需新依赖。

① 层次语言：去 1px 实线= 工具栏 / 列头 / 状态栏 / 队列

原先这四处都是 border-*:1px solid var(--slot-line)，同色同粗的横线把窗口切成等高条带，层次只能靠线。改成底色分层 + 顶部高光 + 底部暗缝三件套（新增 --elev-1 / --elev-2 / --hairline-hi / --hairline-lo）：工具栏与列头抬到 --slot-palt 并用 inset 0 1px 0 高光模拟受光面，分隔线降到 --hairline-lo（暗色是半透明黑、浅色是 10% 黑），状态栏反向用顶部高光。实机 Slint 支持 drop-shadow-blur / drop-shadow-offset-y / drop-shadow-color，inset 高光用一条 1px 的 Rectangle 叠在顶边即可。

② 状态栏「最近一次操作结果」槽= 补实机留下的空位

实机 ui/sftp_panel.slint 里 sftp_status 字符串仍在被后端喂，但注释明写底部状态栏已移除、无处显示；而稿内此前只有零散 toast，导航失败仅路径框闪红。现在状态栏加一个带语义色的结果槽（info / ok / warn / err / busy 五态，圆点 + 单行省略），导航成功、导航失败、粘贴、删除、重命名、改权限、入队全部汇入这一条；role="status" aria-live="polite" 让读屏也能听到。实机落地：在面板底部加一条 26px 状态栏绑 sftp_status，失败态由 Rust 侧回调返回的 Result 决定 tone。分工也一并定了：常规回执（已复制/已刷新/已下载/入队）只进状态槽，浮层 toast 只留给错误，用 warning 图标 + 红描边分级——同一句话不再在浮层和状态栏各播一遍。

③ 行级焦点与读屏语义= 列表 / 菜单

列表容器升为 role="listbox" aria-multiselectable，每行 role="option" aria-selected tabindex="-1"；↑↓ 移动选中后把真实焦点交给该行（不再是「全局 keydown 猜焦点」），鼠标点选同样移交焦点，键盘链 F2/Del/Enter/Backspace 从当前行续接；:focus-visible 用 accent 描边内嵌 2px，不挤占行高。菜单补 role="menu"/"menuitem"，关闭时焦点回到开启者。实机 accessible-role / accessible-label 在 ui/app.slint:9953 与 ui/find_bar.slint 已有用法，FocusScope 在 ui/ 下十余处可用。

④ 减少动效：跟随系统= 对齐 ui/panel_anim.slint

稿内此前全文无 prefers-reduced-motion，骨架 shimmer、面板滑入、队列高度过渡照常播放。现在两路同时生效：@media (prefers-reduced-motion: reduce) 自动关断，页头另给一枚「减少动效 开/关」手动开关（html[data-motion="reduced"]），状态用 aria-pressed 暴露。这与实机契约完全一致——ui/panel_anim.slint 的 PanelAnim.reduced 已让 dur() 返回 0ms，active() 在 reduced 时为 false；落地时把这枚开关绑到同一个全局即可。

v5 图标与选择语义 · 本轮改了什么

四项都是「把语义和实机对齐」：图标回到项目 assets/icons、列头与行项用同一套盒模型对齐、右击改成选中、选择补上 Shift 范围与键盘导航。不改项目代码，落地只需在 ui/icons.slint 注册对应 glyph。

① 图标语义归位= 右键菜单 / 列头 / 复选框

原先「权限…」用的是齿轮（项目里 settings.svg 是设置语义），「粘贴」误用了新建文件夹，行尾是空的齿轮列。现在全部改回项目原件：权限→shield.svg（shield-alert.svg 备用给只读/异常态）、粘贴→paste.svg、删除→delete.svg、列显示→tune.svg、行尾更多→more-vert.svg（与实机 ui/sftp_panel.slint:611 的 compact-more-btn 一致，悬停才显形）。全选框改成项目三态：checkbox-blank / checkbox / checkbox-indeterminate，未选不再是空白方框。实机落地：这些 glyph 已在 ui/icons.slint 注册（shield:208 / more-vert:193 / tune:305 / paste:204 / delete:124 / checkbox 系列:73-75），不需要新增 svg。

② 列头与行项对齐= 名称列

行首是「复选框 + 图标 + 文件名」三段，列头只有「复选框 + 名称」两段，列头「名称」比行内文件名左移一整个图标列（16px）。按实机的做法（ui/sftp_panel.slint:970-1000 列头首项是一个 16px 的 Spacer，注释明写「与行的复选框对齐，让表头与下方取值对齐」）给列头补一个 16px 空占位，两侧用同一盒模型，列头与行内文件名左右边界一致。实机落地：列头 HorizontalLayout 里补一个 Rectangle { width: 16px; } 即可。

③ 右击 = 选中= 列表 / 状态语义

原先右击只在「该行未勾选」时才设当前行，已勾选的行右击看着没反应，还会顺手清掉别处的勾选。改成 Windows 语义：右击总是把该行设为当前行（左侧 2px accent 指示条 + 背景高亮），若它不在多选集合里则集合替换为它，若已在集合里则保留整组多选——右键菜单的作用对象与所见一致。「当前行」与「已勾选」也拆成两套视觉：勾选用复选框图标表达，当前行用背景 + 左指示条表达，不再混用同一个高亮。

④ 选择与菜单的键盘链= 列表 / 菜单

补三条常用链：Shift+点击 = 从锚点行到目标行范围勾选（锚点随普通点击移动）、Home / End = 跳首尾行、菜单 ↑↓ / Enter / Esc = 打开菜单后焦点落到第一项，方向键在条目间移动并高亮当前项，Enter 触发、Esc 关闭并把焦点还给开启者。菜单项同时补 role="menuitem" 与 .active 左侧指示条。实机落地：Slint 侧用 FocusScope + key-pressed（项目里 ui/ 已大量使用 FocusScope），ui/sftp_panel.slint 的行已是 toggle-select 回调，范围选择与 Shift 键位可在 Rust 侧按当前列表快照计算。

v6 上传同名冲突 · 本轮改了什么

上传撞名现在不再静默覆盖：先预检、列出冲突、让用户批量或逐项决定「跳过 / 覆盖」，确认后才真正开始传。本轮仍只改高保真稿，不动项目代码；下面每张卡片都给出实机落地要改的两处（Rust 预检接口 + Slint 回调契约）。

① 为什么必须先弹框= 后端现状

现在 src/sftp/impls/sftp.rs:2748 的 upload_pipelined 直接用 OpenFlags::CREATE | WRITE | TRUNCATE，同名文件被静默截断覆盖，用户既没有提示也拿不回原内容；而同一文件 :1573 的 touch 遇到同名却是报「文件已存在」直接失败——两处语义互相矛盾。稿内据此把上传拆成两段：先预检、再执行，中间必须过一次用户确认。实机落地：新增一个「只查不写」的预检接口（列同名项），把结果交给 UI 决策后才真正调用上传。

② 弹框形态= 列表 / 弹框

按「冲突清单」而非「文件列表」呈现：顶部一行给出冲突数量与默认对同名文件下拉（覆盖 / 跳过），下拉一改即批量套用到所有冲突项；表格三列固定为文件（文件名 + 本地绝对路径）、远端路径（远端路径 + 类型）、处理（每行「跳过 / 覆盖」二选一），逐行改过之后下拉自动显示「自定义（逐项不同）」。底部只有取消与开始上传两个动作；与远端不同名的文件不占表格，只在下方一句说明「其余 N 个文件将直接上传」，避免清单被无关项淹没。

③ 两段式后端契约= Rust / Slint

契约拆成两段：① upload-preflight(dir, local_items) → 冲突清单（每项含远端路径与远端类型）；② upload-exec(dir, items, policy) → 真正上传，policy 逐项带 skip / overwrite，不再由后端自己决定覆盖。实机 ui/sftp_panel.slint:585-590 现有的 upload-clicked(current-path, bool) 需要扩展为能带策略回传（如同 chmod-request 那样由 Rust 回调驱动 UI）。

④ 可达性与回执= 键盘 / 状态

Esc 关闭弹框（复用既有全局处理），弹框打开期间文件的 ↑↓ 导航不再抢焦点（<select> 也从全局键盘链里排除，方向键留给下拉）；「取消」与右上 X 都只回一句已取消上传，不弹错误 toast。确认后走状态栏结果槽回报「上传已提交：N 项 · 跳过 M 项同名文件 · 覆盖 K 项」，与稿内「常规回执进状态槽、错误才上浮层」的分工一致。

v8 弹框同款化 · 本轮改了什么
