右键六场景← WinSCP / Explorer

行与空白之外补齐：树节点（新建/刷新/复制路径/在终端打开）、列头（列显示）、路径框（复制/粘贴前往）、队列任务（暂停/取消/重试）、标题栏（置顶/停靠/最小化）。菜单样式 26px 行沿用实机 SftpMenuItem。

v4 质感与可达性 · 本轮改了什么

四项都只动表现层与前端语义，不改项目代码；每项都给出实机落地位置，且只用项目已有的能力（Slint drop-shadow / accessible-role / PanelAnim.reduced / 现有回调），无需新依赖。

① 层次语言：去 1px 实线= 工具栏 / 列头 / 状态栏 / 队列

原先这四处都是 border-*:1px solid var(--slot-line)，同色同粗的横线把窗口切成等高条带，层次只能靠线。改成底色分层 + 顶部高光 + 底部暗缝三件套（新增 --elev-1 / --elev-2 / --hairline-hi / --hairline-lo）：工具栏与列头抬到 --slot-palt 并用 inset 0 1px 0 高光模拟受光面，分隔线降到 --hairline-lo（暗色是半透明黑、浅色是 10% 黑），状态栏反向用顶部高光。实机 Slint 支持 drop-shadow-blur / drop-shadow-offset-y / drop-shadow-color，inset 高光用一条 1px 的 Rectangle 叠在顶边即可。

② 状态栏「最近一次操作结果」槽= 补实机留下的空位

实机 ui/sftp_panel.slint 里 sftp_status 字符串仍在被后端喂，但注释明写底部状态栏已移除、无处显示；而稿内此前只有零散 toast，导航失败仅路径框闪红。现在状态栏加一个带语义色的结果槽（info / ok / warn / err / busy 五态，圆点 + 单行省略），导航成功、导航失败、粘贴、删除、重命名、改权限、入队全部汇入这一条；role="status" aria-live="polite" 让读屏也能听到。实机落地：在面板底部加一条 26px 状态栏绑 sftp_status，失败态由 Rust 侧回调返回的 Result 决定 tone。分工也一并定了：常规回执（已复制/已刷新/已下载/入队）只进状态槽，浮层 toast 只留给错误，用 warning 图标 + 红描边分级——同一句话不再在浮层和状态栏各播一遍。

③ 行级焦点与读屏语义= 列表 / 菜单

列表容器升为 role="listbox" aria-multiselectable，每行 role="option" aria-selected tabindex="-1"；↑↓ 移动选中后把真实焦点交给该行（不再是「全局 keydown 猜焦点」），鼠标点选同样移交焦点，键盘链 F2/Del/Enter/Backspace 从当前行续接；:focus-visible 用 accent 描边内嵌 2px，不挤占行高。菜单补 role="menu"/"menuitem"，关闭时焦点回到开启者。实机 accessible-role / accessible-label 在 ui/app.slint:9953 与 ui/find_bar.slint 已有用法，FocusScope 在 ui/ 下十余处可用。

④ 减少动效：跟随系统= 对齐 ui/panel_anim.slint

稿内此前全文无 prefers-reduced-motion，骨架 shimmer、面板滑入、队列高度过渡照常播放。现在两路同时生效：@media (prefers-reduced-motion: reduce) 自动关断，页头另给一枚「减少动效 开/关」手动开关（html[data-motion="reduced"]），状态用 aria-pressed 暴露。这与实机契约完全一致——ui/panel_anim.slint 的 PanelAnim.reduced 已让 dur() 返回 0ms，active() 在 reduced 时为 false；落地时把这枚开关绑到同一个全局即可。

v5 图标与选择语义 · 本轮改了什么

四项都是「把语义和实机对齐」：图标回到项目 assets/icons、列头与行项用同一套盒模型对齐、右击改成选中、选择补上 Shift 范围与键盘导航。不改项目代码，落地只需在 ui/icons.slint 注册对应 glyph。

① 图标语义归位= 右键菜单 / 列头 / 复选框

② 列头与行项对齐= 名称列

v6 上传同名冲突 · 本轮改了什么

上传撞名现在不再静默覆盖：先预检、列出冲突、让用户批量或逐项决定「跳过 / 覆盖」，确认后才真正开始传。本轮仍只改高保真稿，不动项目代码；下面每张卡片都给出实机落地要改的两处（Rust 预检接口 + Slint 回调契约）。

① 为什么必须先弹框= 后端现状

现在 src/sftp/impls/sftp.rs:2748 的 upload_pipelined 直接用 OpenFlags::CREATE | WRITE | TRUNCATE，同名文件被静默截断覆盖，用户既没有提示也拿不回原内容；而同一文件 :1573 的 touch 遇到同名却是报「文件已存在」直接失败——两处语义互相矛盾。稿内据此把上传拆成两段：先预检、再执行，中间必须过一次用户确认。实机落地：新增一个「只查不写」的预检接口（列同名项），把结果交给 UI 决策后才真正调用上传。

② 弹框形态= 列表 / 弹框

按「冲突清单」而非「文件列表」呈现：顶部一行给出冲突数量与默认对同名文件下拉（覆盖 / 跳过），下拉一改即批量套用到所有冲突项；表格三列固定为文件（文件名 + 本地绝对路径）、远端路径（远端路径 + 类型）、处理（每行「跳过 / 覆盖」二选一），逐行改过之后下拉自动显示「自定义（逐项不同）」。底部只有取消与开始上传两个动作；与远端不同名的文件不占表格，只在下方一句说明「其余 N 个文件将直接上传」，避免清单被无关项淹没。

③ 两段式后端契约= Rust / Slint

契约拆成两段：① upload-preflight(dir, local_items) → 冲突清单（每项含远端路径与远端类型）；② upload-exec(dir, items, policy) → 真正上传，policy 逐项带 skip / overwrite，不再由后端自己决定覆盖。实机 ui/sftp_panel.slint:585-590 现有的 upload-clicked(current-path, bool) 需要扩展为能带策略回传（如同 chmod-request 那样由 Rust 回调驱动 UI）。

④ 可达性与回执= 键盘 / 状态

Esc 关闭弹框（复用既有全局处理），弹框打开期间文件的 ↑↓ 导航不再抢焦点（<select> 也从全局键盘链里排除，方向键留给下拉）；「取消」与右上 X 都只回一句已取消上传，不弹错误 toast。确认后走状态栏结果槽回报「上传已提交：N 项 · 跳过 M 项同名文件 · 覆盖 K 项」，与稿内「常规回执进状态槽、错误才上浮层」的分工一致。

v10 列宽拖拽手感 · 本轮改了什么

v3 稿的列宽手柄只有一根 6px 热区 + 一小段 accent 线，没有「我在拖哪儿、现在多宽、拖到头了没」的反馈。本轮把拖拽整条链重做：悬停看得见、拖动看得见、边界摸得着、松手可回退。

热区 6px → 9px（仍然精确压在列边界上，好点不误触）。钳制不再只有一刀 40–280：每列有自己的最小宽度（类型 56 / 大小 64 / 修改时间 96 / 权限 88 / 所有者 72 / 组 56），并且上限会再被可用宽收一道 —— 名称列保底 120px，拉宽别的列时不会把名称挤没。宽度取整到整像素。

③ 可回退：Esc 取消 / 双击复位 本文件 mousedown / dblclick

拖动中按 Esc = 放弃本次拖动、宽度回到按下那一刻的值（不算变更）；双击手柄 = 该列宽度复位到默认值（类型 72 / 大小 76 / 修改时间 120 / 权限 104 / 所有者 84 / 组 66），状态槽回一句「权限列宽已复位为 104px」。

v11 书签行尾删除 · 本轮改了什么

书签菜单原来是「书签一条 + 独立的『删除此书签』一条」交替排布，菜单高度翻倍，删除项和它作用的对象在视觉上分离（容易删错行）。本轮改成删除钮停在书签行的行尾：悬停才现形，点一下原位变成「确认」钮，再点一次才真删。

① 删除钮停在行尾，hover 才现形 本文件 .bm-row / .bm-del

每个书签占一行：★ 路径 + 行尾一枚删除钮。删除钮平时 opacity:0（不是 display:none —— 占位恒在，所以悬停时路径不跳位），悬停该行才显形；悬停删除钮本身时染危险色。菜单因此从「2N 行」缩回「N 行」。

② 点一下变「确认」钮，内联二次确认 本文件 bmStartConfirm()

第一次点击删除钮不删，只是原地把它换成一枚红色实心的 ✓ 确认 胶囊，同时整行染危险色（--slot-dg）—— 明确告诉用户「现在点下去就真删了」。第二次点击才执行删除并关闭菜单。这是弹框与「直接删」之间的中间档：比弹框轻，不打断上下文；比直接删安全。

③ 确认态会自动回退 本文件 bmResetConfirm()

待确认状态不会粘住：3 秒无操作自动回退成删除钮；鼠标移出该行、点别处、Esc 也都回退。行尾删除钮的错误成本（删错书签）低，所以二次确认只做「原位一行」的轻量级，不占用一个模态弹框。

④ 路径掐头留尾 本文件 bmPathHtml()

路径太长时不再从尾部截（尾部正是最能定位的那个目录名）：在中间的分隔符处切成两段，头段按像素省略、末段完整，拼起来仍是一条可读的路径（/home/deploy…/app/releases），完整路径挂在 tooltip 上。

v12 目录树收展钮归位 · 本轮改了什么

目录树的收展钮原先挤在工具栏右端那堆动作里（刷新 / 新建 / 上传 / 搜索 / 隐藏文件 / 队列），一个视图开关混在一堆数据动作中间，既难找又把右端塞满。本轮把它挪到工具栏左缘—— 位置直接对着它控制的目录树那一列，也和实机面板的排法一致。

① 收展钮移到工具栏最左缘 实机 ui/sftp_panel.slint:318-372

实机面板的工具栏是 [drag grip][6px 间隔][文件/隧道 tabs][导航][路径]…，注释明写收展钮「always present so both states share a consistent left-edge affordance」—— 面板收展 affordance 占左缘、两态同位，其余控件在它右边。本轮照此把目录树收展钮放到最左缘：按钮正好压在它控制的左侧目录树上方，右端腾出来后只剩动作与显示开关（隐藏文件 / 列设置 / 队列）。

② 图标与提示随两态换 本文件 #treeBtn / i-collapse / i-expand

目录树展开时按钮显示 sidebar-left-collapse.svg（箭头朝左 = 点它收起），折叠时显示 sidebar-left-expand.svg（箭头朝右 = 点它展开），tooltip 同步为「收起目录树 / 展开目录树」，图标在收起时染强调色表明「左栏当前开着」。稿内原先只有一个图标不变，两个资产项目里都已注册（ui/icons.slint:253-256）。

③ 落地 实机对照

落地 = 目录树可见性一个 bool（tree-visible，随面板尺寸自动隐藏的逻辑照旧）；按钮 glyph 按可见性取 sidebar-left-collapse / sidebar-left-expand；tooltip 文案跟着换。与实机左侧面板收展钮（ui/app.slint:766，左上角 LOGO 位悬浮换成 collapse 图标）是同一套语言。

v13 表头与数据行对齐 · 列宽真的拖得动

本轮修两个连着的毛病：标题行和下面的列没对齐，列宽拖不动。它们其实是同一个根因的两副面孔——表头与数据行用了两套宽度来源，差值又恰好被原生滚动条吃掉一部分。

① 根因：列宽有两个来源 本文件 renderListHead() / renderList()

数据行的列宽来自 S.colW（固定宽，inline style）；表头的列此前根本没有宽度（按内容自适应），而表头的「名称」列又继承 flex:1 → 把富余宽度全吸走 → 后面所有表头被推到右边。后果一：两行错位；后果二：拖拽手柄停在「内容边缘」而不是看得见的列边界上 —— 想拖却抓不到东西。修法：表头与行共用 S.colW 一个真源（表头格子同样写 inline width + flex:none），名称列两处同为 flex:1 1 0 / min-width:120px，大小列表头与数据行同为右对齐。

② 差的那 15px = 原生滚动条 实机 ui/widgets.slint:984 PanelScroll

修完宽度来源后仍差 15px：表头容器 926px、数据行容器 911px —— 差的是原生滚动条占掉的布局宽。实机用 PanelScroll：自绘 4px 细圆角条、浮在内容上、不占布局宽（14px 命中区 / 拇指 24px 下限 / hover 淡入），所以实机表头与行天然同宽。稿内照此改：隐藏原生滚动条（scrollbar-width:none）+ 自绘同款细条，树与列表各一根。

③ 落地 实机对照

列宽：一份真源（表头与行都从它取，拖动即改它，其余列依次让位）；滚动条：直接复用实机 PanelScroll（ui/widgets.slint 已有，稿内这版是照它复刻的视觉与行为），不再出现「表头比行宽一圈」的错位。

v14 树上当前目录不再描圈 · 本轮改了什么

v9 给树的当前目录加了一圈描边（inset 0 0 0 1px accent-line），这轮去掉。框框去掉后树干净得多，「当前在哪」交给路径框 + 图标染色两处承担。

① 当前目录 = 图标染强调色，不要框 本文件 .tree-row.current

当前目录的文件夹图标染强调色、文字提亮一档（slot-t1 vs 普通行 slot-t2），不再画描边。祖先目录照旧不带任何底色/描边。落地：树节点的「当前」= 图标 tint + 文字色，不引入任何边框。

② 为什么不画框 实机对照

实机树里本来就没有「当前目录描边」这种东西 —— 用户提供的实机截图里那圈框是悬停/焦点环，不是状态标识；把它当成状态画进稿里，等于凭空加了一个实机没有的视觉元素。状态该由「路径框 + 图标色」说清，焦点环则只在键盘/悬停时出现。

v15 树与列表不再置灰 · 本轮改了什么

上一轮去掉框框后，目录树和文件列表的文字与图标仍整片发灰，和路径框那种主前景色一比就显得「没精神」。本轮把这两处的色调提到正常档位：名称类文字 = 主前景色，图标 = 次前景色，置灰只留给真正次要的信息。

① 名称提到主前景色，图标提到次前景色 本文件 .tree-row / .f-row / .f-ico

目录树与文件列表的名称文字：slot-t2 → slot-t1（与路径框、工具栏文字同档，主前景色）；图标：slot-t3（muted，几乎看不见）→ slot-t2（次前景色，与工具栏图标同档）。当前目录的图标照旧染强调色 —— 那是唯一的彩色标记，别的都收敛。

② 列值色调对齐实机 实机 ui/sftp_panel.slint:1256-1278

实机的列值不是一片 muted：只有「修改时间」是 muted，类型 / 大小 / 权限 / 属主 / 组都是 secondary。稿内此前全按 muted 画（偏灰），本轮按实机逐列归位：类型·大小·权限·属主·组 = secondary，修改时间 = muted；列头仍保持 muted（实机列头就是 muted）。

③ 一条分界线 落地口径

置灰（muted）只留给「装饰性/可忽略」的信息：修改时间、列头、折叠箭头、行尾「⋯」；secondary 留给「可读但次要」：列值、图标；primary 留给「主角」：路径、目录名、文件名。这样整棵树的层级一眼可分，又不会灰成一片。

v16 停靠态对齐实机 + 展开目录的打开样式 · 本轮改了什么

本轮按实机截图把「正常态」逐处对齐，并补了树的一个语义缺口：目录一旦展开（含各级父目录），图标就该是打开样式。

① 停靠常态 = 主窗底部面板 实机 ui/sftp_panel.slint:820-918

面板常态仍是主窗底部的整条停靠面板（终端在上、面板在下），左树右列；「弹出独立窗口」是它的另一种形态而非替代形态（v9 的口径不变）。本轮补上实机有、稿里没有的一处：树列头「目录树」 —— 22px 高、zone-sidebar 底、次级色 11px 小标题 + 1px 下边线（实机 ui/sftp_panel.slint:842-856）。

② 展开的目录 = 打开样式，父目录同样 本文件 renderTree() / .tree-row.open

目录一旦展开，图标换成 folder-open 图形并染强调色；当前目录的各级父目录因为也是展开的，一并走打开样式 —— 整条链一眼可辨「是开着的」，不再只靠一个小图标。落地 = 树节点渲染时按 expanded 取图形与 tint，展开态与「当前目录」解耦（当前目录也可能没展开）。

③ 列表里的目录走实机强调色 实机 ui/sftp_panel.slint:1236-1245

实机列表里目录的图标与目录名都是强调色（entry.is-dir ? Theme.accent : Theme.text-primary），文件则是次级图标 + 主前景名。稿内此前目录与文件同色，现在按实机分档：目录 = 强调色（图标 + 名称一起），文件 = 次级图标 + 主前景名。顺带说明：稿内独有的文件类型着色（脚本/配置/文档三档）保持不变，它只作用于文件。

v17 文件按类型给不同图标 · 怎么实现的

参照 iShellPro 的做法（不同类型不同图形、不同颜色），本轮给列表里的文件按扩展名派生了图标。实现是表驱动的：一张「正则 → 图标 + 颜色档」的表，逐条命中即用；没命中就落到通用文件图标。（v18 换了图标集：v17 那批是拿现成资产凑的，语义对不上，已按类型重画，见下。）

① 机制：一张扩展名表 本文件 TYPE_RULES / typeMeta()

一张表驱动，一行一个类型：{ re: /\.(log|out|trace)$/i, icon: 'log-file', cls: 't-log' } —— 正则命中扩展名就用这枚图标 + 这档颜色。表自上而下匹配，第一个命中即停；全表不命中 → 通用 file 图标。typeMeta(e) 返回 { icon, cls }，渲染时图标与颜色都从它出，不散落在各处判断。加一种新类型 = 加一行规则（+ 一枚已注册的图标），不碰渲染代码。

② 图标全部来自项目资产 assets/icons/*.svg

没有自画图形，全是项目现成资产（路径原样搬运）：log-file.svg（日志：带横线的文档）· terminal.svg（脚本：终端窗口）· tune.svg（配置：滑杆）· notebook-pen.svg（文档：带笔的笔记本）· table-rows.svg（表格）· layers.svg（压缩包：叠层）· link.svg（链接）· folder.svg / file.svg。落地时把这几枚补注册进 ui/icons.slint 分段即可（项目 icons.slint 已有 log-file/terminal/tune 等）。

③ 颜色纪律：图形说「是什么」，颜色只说语义 v16 + v17 合并口径

类型多了，颜色不能跟着铺满——那样等于把列表变成调色盘。稿内的分档是：目录 / 配置 = 强调色（teal，与实机目录口径一致）· 脚本 = 警告色（黄）· 日志 = 成功色（绿）· 文档 / 表格 / 压缩包 / 其它 = 次级色。形状负责区分，色彩只保留语义，列表才不会花。

④ 实机落地路径 实机 ui/sftp_panel.slint:13-27

实机 SftpEntry 已经带 file-type 字段（就是「类型」列显示的那串：文件夹 / PY / FILE…），所以不需要给模型加字段：图标与类型列共用同一份类型串即可 —— 类型串来自 SFTP 服务端的 file_type；服务端不给时按扩展名兜底推导（与本轮这张表同口径）。UI 侧把 glyph: entry.is-dir ? "folder" : "file" 换成按类型查表即可，一行 Icon 组件的事。

v18 类型图标重画 + 树的亮起只跟当前目录 · 本轮改了什么

两处修正：类型图标按文件类型重画（v17 那套是拿现成资产凑的，语义对不上）；树的亮起只跟当前目录走（展开过的目录不该一直亮着）。

① 六枚类型图标按语义重画 本文件 i-file-* 六枚 symbol

v17 拿现成资产凑，图形和类型对不上：log-file.svg 其实是「文档 + 笔」（编辑）、terminal.svg 是终端窗口（不是代码）、tune.svg 是滑杆（不是配置）、layers.svg 是叠层（不是压缩包）。本轮按类型重画一套（24×24 / stroke 2 / 圆角端点，与项目图标同风格）：file-log 文档 + 三行（日志）· file-code 文档 + <>（程序）· file-config 文档 + {}（配置）· file-markdown 经典 M↓ 标记（文档）· file-table 文档 + 网格（表格）· file-archive 立体包裹盒（压缩包）。目录 / 通用文件 / 链接沿用项目现成资产（folder·file·link）。落地 = 新增 assets/icons/file-*.svg 六枚（已落，与稿内 symbol 逐字一致）+ 注册进 ui/icons.slint 的两处清单（known-glyph 列表 + @image-url 开关，漏一处不显示）—— 注册留待实现轮。

② 判定多一条：看可执行位 本文件 typeMeta()

类型判定不只看扩展名：无扩展名但带 x 权限位的（appctl / migrate 这类二进制程序）也用程序图标。判据 = 扩展名 → 可执行位 → 兜底通用文件。

③ 树的亮起只跟当前目录 本文件 .tree-row.current / .tree-row.open

此前把「展开」也做成了强调色，于是在同一目录里切到别处时，先前展开过的目录会一直亮着，看着像「还选着它」。现在：展开只换图形（folder → folder-open），颜色只给当前目录（强调色）。展开与否看图形 + 箭头，选中与否看颜色，两件事彻底分开。

v19 树的亮起 = 当前路径链 · 展开跟随路径 · 本轮改了什么

v18 把亮起收窄到「当前目录」一个，矫枉过正：父目录不亮就看不出当前在路径链的哪一截。本轮把语义定准：亮起 = 当前目录 + 各级父目录；同时树的展开态跟随当前路径，切目录时上一次留在别处的兄弟目录自动收起。

① 亮起 = 在路径链上 本文件 .tree-row.on-path

判定改成「cwd === path || cwd.startsWith(path + '/')」—— 当前目录和它的各级父目录一起亮（强调色图标），一眼能看出当前在链的哪一截；不在链上的目录一律不亮（哪怕它是展开的）。这与 v18 的差别：v18 把「展开」当成亮的条件，于是切目录后旧目录一直亮；现在亮的条件是「在路径上」，展开与否只由图形（folder ⇄ folder-open）表达 —— 两件事彻底分开。

② 展开态跟随当前路径 本文件 navigate() · S.expanded

切目录时，展开集合重算为「当前目录 + 各级父目录」，上一次留在别处的兄弟目录自动收起、图标换回未打开那枚。落地 = 展开集合不再是一份独立的手动状态，而是由 current-path 推导（Slint 侧同样：树节点展开态 = 是否在当前路径链上）；手动点箭头展开的目录会在下一次导航时被收掉，这正是「树跟随路径」的预期。

v20 类型覆盖与语义校对 · 本轮改了什么

用户指出「类型还缺（如 nginx.conf、.java、.php）」，并要求按主流设计再核一遍图标是否名副其实。本轮把规则表改成按族（一族一枚图形，扩展名清单只是数据），同时逐族对照主流图标订正了三处语义错配。

① 覆盖：按「族」给图标 本文件 TYPE_RULES

不按扩展名单枚画图标，一族一枚图形，扩展名清单是纯数据 —— 加一个扩展名只加一条正则，不用画图。当前族与命中：日志（log/out/trace/err/pid）· 程序（含 sh/py/js/ts/java/php/go/rs/cs/swift/kt/scala/vue/svelte…约 60 个）· 配置（conf/cfg/ini/toml/yml/json/env/xml/properties/.gitignore/.service…）· 文档（md/markdown/mdx）· 表格数据（csv/tsv/xls/xlsx/ods/db/sqlite/sql…）· 压缩安装包（zip/tar/gz/7z/rar/deb/rpm/dmg/exe/jar/whl…）· 图片（png/jpg/gif/webp/svg/ico/psd/avif…）· 媒体（mp3/wav/flac/mp4/mkv/mov/webm…）· 密钥证书（pem/key/crt/p12/gpg/keystore…）· 字体（ttf/otf/woff…）· 链接（lnk/url/desktop）。

② 三处语义错配已订正 对照 VS Code / iShellPro

① .txt 不该是 M↓ —— M↓ 是 Markdown 专属记号，txt/readme/license/rst/adoc 原来都蹭了它，现已移出（落通用文档）；② 编译产物不该是 <> —— <> 是源码记号，无扩展名 + x 权限的二进制改用齿轮（VS Code 用 cog 表示二进制）；③ .gz 等单扩展名压缩漏了，已补齐（backup.tar.gz 之前落通用图标）。

③ 逐族对照主流 主流图标记号

日志 = 文档+三行（iShellPro 同款，绿）· 源码 = 文档+<>（iShellPro 同款）· 配置 = 齿轮（v26 定稿：闭合轮廓、纯几何，与家族同量级；项目现成 settings.svg）· Markdown = M↓（VS Code 一模一样）· 表格 = 网格（VS Code 的 csv/xlsx）· 压缩包 = 立体盒 · 图片 = 相框（VS Code 的 image）· 字体 = A 字形（VS Code 同款）· 密钥 = 钥匙（permission.svg）· 二进制 = 齿轮（VS Code 的 cog）。仍缺的族（现在落通用文档，想要专属图标就补一枚资产 + 一条正则）：PDF / Office（主流是带字样的文档）、音频 / 视频（主流拆成音符与胶片，我们合用播放标）、Git（主流用 git logo）、锁文件（挂锁）、备份 / 临时（.bak/.tmp/.swp，主流用扳手）。

v21 两个图标归位 + 多传输怎么显示 · 本轮改了什么

用户圈出传输队列（工具栏右端）与弹出独立窗口（状态栏右下角）两枚，问位置与交互是否更贴切，并追问「存在多个文件传输时，右下角的上传下载怎么显示」。本轮把这两枚对调，并把右下角从「两条裸速度」升级为一块传输状态。

① 两枚对调 本文件 .sftp-toolbar / .st-xfer

传输队列 → 状态栏右下角：它本来就是传输状态的入口，跟速率/计数放一起才对；工具栏右端此前混着「刷新·新建·上传·搜索·隐藏文件·队列」六件不同性质的事，队列下沉后只剩动作。弹出为独立窗口 → 工具栏右端：这是面板级动作，跟隐藏文件 / 列设置 / 树收展同列；独立窗口形态下这枚自动隐藏（窗口标题栏已有「停靠回主窗面板」）。

② 多传输：右下角显示「一块聚合」 本文件 updateQueueUI() / .st-xfer

原来的「↑ 0 B/s ↓ 0 B/s」在多传输时既说不清在传谁、几个，空闲时又只剩两条噪音。改成 ⇅ 3 项 · ↑ 2.4 MB/s · ↓ 4.8 MB/s：项数 = 进行中任务数（含暂停的，另在悬浮注明）；速率按方向各自聚合（多个同向任务合并成一条总吞吐，不是每任务一条）；空闲整块淡出，只留一枚淡的 ⇅（仍可点开队列），不摆 0 B/s。

③ 明细怎么给 队列抽屉 + 悬浮气泡

逐条明细在队列抽屉（已有：方向图标 · 名称 · 大小 · 进度条 · % · 速度 · 暂停/取消/重试）；悬浮状态块先给一份清单（进行中最多 4 条 + 「还有 N 项…」）—— 多个传输时不用开抽屉就知道在传什么；点状态块即开/关队列抽屉（取代原工具栏那枚队列钮）。参照 WinSCP（队列逐条 + 状态栏计数）、VS Code（状态栏一条可展开）；列表行内进度条（Explorer 做法）属可选增强，落地时另议。

① 试过什么，为什么不行 本文件 TYPE_RULES 的配置族

③ 尺寸按「同族基准」校，不按平均值校 浏览器 getBBox 实测

把每个资产的实际几何包围盒量出来对比（库内基准：文档类 file.svg = 16×20、log-file.svg = 16×18；独立形 settings.svg = 18×20、language.svg = 20×20、layers.svg = 20×20），新图标族**各自贴自己的参照**：文档族（log / code / table）16×20 = 与 file.svg 完全一致；独立形（markdown 20×16 / archive 18×20 / image 18×18 / font）落在 18–20 那一档。库内平均 21×20.5 是被齿轮/滑杆这类「撑满盒」的图标拉高的，文档类天然就窄 —— 所以按平均值校会把文档类画胖。按同族基准校才协调（唯一被实测点名偏小的是字体「A」：原 14×16 → 已放大到 17.6×18）。

v23 树收展钮不再上色 · 本轮改了什么

用户指出工具栏最左的目录树收展钮被染成强调色没必要 —— 树在不在场上一目了然，按钮再上色是冗余，还跟旁边 accent 色的「文件」页签抢注意力。

① 收展钮只管切换，不做状态色 本文件 #treeBtn

去掉 active 类：常态与切换后都是普通图标色（次级色，hover 提亮）。状态由图形表达 —— 展开时 sidebar-left-collapse（箭头朝左 = 点它收起）、收起时 sidebar-left-expand（箭头朝右 = 点它展开），tooltip 同步「收起目录树 / 展开目录树」。与「显示隐藏文件」那枚的区别：后者是模式开关（开着=正在显示隐藏文件），染强调色有意义；前者是布局开关，状态就摆在眼前。

② 顺带修掉一处逻辑反转 本文件 treeBtn onclick / setPanelMode

原代码 classList.toggle('active', hidden) 是反着的：树藏起来才上强调色（与直觉相反），而初始标记又是「树展开着 + active」—— 同一状态两种颜色。移除该类后，切换「文件/隧道」页签时树的显隐也不再依赖这个类（改成直白的 m === 'files' ? '' : 'none'），逻辑反转随之消失。

v28 配置族拆分：设置 vs 数据 · 本轮改了什么

用户指出「.yml 用设置齿轮不贴切」。根因是配置族把两类语义混在一起：设置类（conf / ini / properties / service…）读作「设置」，用齿轮对；结构化数据类（yml / json / toml / xml / env…）是「键值清单」，用齿轮就是张冠李戴。

① 拆成两族 本文件 TYPE_RULES

设置 / 配置类 → 齿轮（项目现成 assets/settings.svg）：conf cfg config ini properties plist editorconfig desktop service socket timer target mount —— 这类文件读作「设置」，齿轮贴切 ✓。结构化数据类 → 清单记号（新画 file-data.svg，3 点 + 3 行，VS Code 的 YAML 记号）：yml yaml json toml xml env .gitignore .dockerignore —— 这些是「键值清单」，清单记号才贴切。

② 花括号为什么还是没选 对比记录

「花括号」是 VS Code 的 JSON 记号，语义上也贴切，但试了三档宽度后在 16px 下全读成 ( ) —— 腰口太浅、两条内缘平行，就是圆括号。与其画一个会被误读成圆括号的记号，不如用清单（真正的「键值列表」语义）。
