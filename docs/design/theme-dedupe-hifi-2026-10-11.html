明暗

3.3 灰色用量体检：446 处 vs 209 处

查完色值再看一层，发现问题不只在"某个套不合格"，而在整个 UI 的灰度预算。上游 Islands Dark 的用色比例是 #BCBEC4 出现 43 次、#7A7E85 只有 16 次（约 27%）；而我们 ui/ 里的实际情况是 ——

209text-primary（正文一级）t1 · 前景色
236text-secondary（次级）t2 · 灰
210text-muted（弱化）t3 · 灰
68%灰色占总文字的比例上游是 27%

为什么这会让 MTerm 显得"灰"

其它主题的 t2 和 t3 是两个不同的灰，用在界面上还能看出层次。而 MTerm 暗档 t2 == t3 == #7A7E85（上游只给了一个 descriptionForeground）—— 于是 446 处文字全部落在同一个色值上，既显得灰，又彻底失去了层级：弱化文字和次级文字渲染完全一致，用户读不出主次。
典型例子：app.slint:353、welcome.slint:648、widgets.slint:675 三处的 icon-color 都绑在 Theme.text-secondary 上 —— 图标用了描述灰，这在上游的语义里是不存在的（上游的 icon.foreground 就是前景色 #bcbec4）。

灰度应该用在哪 —— 按上游语义

前景色 #BCBEC4：图标、列表项、分组名、按钮、tab（激活）、面板标题（激活）、菜单、数值
灰 #7A7E85：未激活的 tab / 面板标题、输入框占位符、搜索提示、描述与辅助说明、inlayHint 之类注释

对应上游的 tab.inactiveForeground / panelTitle.inactiveForeground / input.placeholderForeground / descriptionForeground 四处 —— 而 icon.foreground 在上游明确是前景色。

建议的修法：色值层与 UI 层各动一处

① 色值层（MTerm 两套都要）：把 t2 / t3 从同一个值分成两级 —— t2 保持 #7A7E85（对应"未激活"），t3 再压深一档（约 12%）对应"占位符与注释"。这一条同时解决了 t2≡t3 的塌缩（§4.7 P0-1 的连带项）。
② UI 层（跨全部主题生效）：把 icon-color、分组名、列表项、激活态 tab 从 text-secondary 改到 text-primary。这类改动与色值无关，换成任何主题都会更清晰 —— 因为把"图标"和"分组名"降级成描述灰，本身就是超出上游设计的额外弱化。

3.4 UI 灰度收敛：把图标从"描述灰"放回"前景色"

§3.3 给的是"灰色占 68%"这个总量结论。这一节是它的落地清单 —— 先纠正一个我上一轮给错的数字，再说清楚为什么这件事不能靠改一个色槽了事。

先纠正：icon-color 不是 236 处，是 7 处

上一轮说的「236 处 icon-color」是把整个 text-secondary 的引用数当成了 icon-color 的数。icon-color 只是两个组件的自定义属性（widgets.slint:675 的 ProtocolIcon、app.slint:353 的 IconBtn），全项目只有 7 处。
更关键的是：icons.slint:254 那个 Icon.tint = Theme.text-secondary 的默认值，是死代码 —— 157 个 Icon 实例无一例外全部显式传了 tint，默认值从未生效。所以「改一行默认值覆盖全部图标」这条路不存在。

最省事的做法是把 theme.slint:164 的 text-secondary 映射到 slot-t1，一行搞定全部 229 处。但这条路会连带四件不该发生的事：

④ 两处非文字用法被误伤 —— tabs.slint:752 的「更多」三圆点背景、terminal_view.slint:1199 的滚动条滑块，都借用了这个槽。

3.5 改法分解：只动 A 类，其余三类原样

A 类 · 改 75 处图标染色 tint / icon-color

4.5 抽样对照：亮档可读性修复

亮档主题最集中的问题是"把暗档的 ANSI 表原样搬到浅底上"：彩槽对比度大面积低于 3.0:1。下面 6 个：前 4 套是把 ANSI 表搬到浅底后彩槽低于 3.0:1 的（墨纸 / 卡布奇诺 / Ayu / 松玫瑰），后 2 套（石墨·亮 / 北欧·亮）彩槽本来就达标，作为对照组 —— 说明「亮档有对比度问题」不是普遍现象，只有上游自己没做浅底校准的那几套才有。

但色表里仍保留 28 套（§2 的 A/B/C/D 四级清单保留下来的），理由是：亮档（石墨·亮 / 北欧·亮 / MTerm·亮 等 14 套）不装进"常用"是合理的 —— 它们本就该由"跟随系统"或"反向"按钮派生，让用户手动挑亮档是多余的；而剩下几套（墨纸 / 岩焙 / 神奈川 / Ayu / 原子 / Solarized / Darcula / 常青）各有鲜明风格，砍掉等于替用户做审美决定，删了以后想要只能换主题系统。
搜索框保留但改了职责：它不再是"在 38 套里找一套"的救急工具（有了「常用」后高频主题不用找了），而是"偶尔切到冷门主题"的入口 —— 所以匹配维度从「中文名」扩到中文名 / id / 色相名，而删掉了「家族」这个维度。
所以落地形态是：色表 28 套 · 内置常用 8 套 · 用户可自选增删到 8 套上限。如果确实要只留 8 套（连亮档都砍），那是另一个决策 —— 会让"跟随系统在浅色系统下"这件事失去选择面，需要单独评估。

6.4 新增红线：五条，每条对应一处具体问题

旧红线只管"别做错"，不管"做对了没有"。门面现在是默认主题，需要补一批正向断言。左边三条是刚完成的门面临设计所要求的，右边两条是跨主题的。

新增断言说明
t3 对 panel ≥ 3.0辅助级文字的独立门槛。暗档 #6F737A（3.66）· 亮档 #968F85（3.02） —— 与正文级的 4.5 门槛分开计
t2 与 t3 不得再同值原纪律把 t2 == t3 当成"缺陷"，但暗底上 t2 已 4.28、往弱走必然跌破 4.5 —— 改成两级分工：t2 管未激活（保持上游原样），t3 管占位符与注释
灰族唯一：a8 与 t3 Δ色相 ≤10°原纪律是 a8 == t3，它把亮档一个 2.51:1 的值固化成了标准色。放宽为同色相后意图（灰族同源）保留，不合格值不再被保护；亮档 a8 保持 #A49E95 不动（终端里的 brightBlack 本就作注释色）
group24 不与其余 27 套逐位相同门面的取色面板必须独此一家。已定稿：8 色相 × 3 档，明度跨 51%~70%（暗）/ 31%~48%（亮）
语义色与同名 ANSI 槽 Δ色相 ≤30°守住「界面 ↔ 终端同源」这项全表独有的优点。它守的不是好看，是"一整套配色还认不认得出是同一套" —— 一旦有人单改一边，这条立刻炸

顺带暴露的一件事：「灰族唯一」这条纪律本身有副作用

它的本意是让终端注释色与界面弱化文字同源 —— 方向对。但它只校验"两者相等"，不校验 t3 自身是否可读，于是把亮档一个 2.51:1 的颜色固化成了标准色。这不是疏漏，是纪律设计时的盲区：任何"两个东西必须相等"的断言，都要同时约束那个共同值本身。

同类风险在别处也有：islands_accent_survives_guard 钉死 ac == #2AACB8，只保证"守卫不改强调色"，不保证"强调色在面板上够不够"。补一条 ac 对 panel ≥3.0 才完整（实测暗档 6.39、亮档 5.13，都已达标，属于把已有事实钉住）。

这次没有一条新断言要求改色值 —— 全部都是"把已经定好的东西钉住"，所以可以与门面临设计一起落地，不需要额外的视觉评审。
