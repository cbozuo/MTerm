MTerm 内置编辑器 · 界面与交互高保真

面向 远程文件编辑 场景（SFTP 打开 → 编辑 → 回写）的编辑器重做稿。目标不是做一个通用 IDE，而是把 「打开远程文件 → 看清 → 改准 → 安全存回」这一条主路径做到位，同时把上一轮定位到的三个性能瓶颈 （ui/editor_window.slint:252 行号槽全量遍历、:254 每行一个隐藏测量器、:319-324 每次按键全量重建行模型） 在结构上消掉。

交互可直接点：点代码区移动光标 · 拖拽选区 · 打字产生脏标记 · Ctrl+F 开查找 · 「:」开命令面板 · Ctrl+S 存盘。

场景约束

远程文件，SFTP 读写；单文件、浅层使用；Ctrl+S 直存，无本地副本。

规模约束

目标 1 MB / 5 万行内流畅；超 2 MB 自动降级（关高亮、关软换行）。

平台约束

Windows / macOS / Linux / Android 四端；等宽字体族与 CJK 回退已就绪。

实现约束

Slint 1.18 TextInput 不支持按 span 着色 → 编辑态彩色必须自绘。

03

命令面板 · Helix 风格 :

新增
可交互

为什么做：接上一轮的结论——不整体移植 Helix，但借它的交互语言。: 唤起是 Helix 的招牌动作， 零学习成本，且天然容纳后续扩展（:w 保存、:q 关闭、:set wrap）。 Ctrl+Shift+P 是 VSCode 习惯，作为别名保留。面板同时承载「保存 / 只读切换 / 换行切换 / 编码 / 跳行 / 复制路径」等 低频动作，不占用顶栏空间——顶栏只留高频的「保存」。

04

只读态

editor-readonly

要点：只读时保留高亮与查找（看文件是主需求），仅去掉光标与保存入口；标题栏出现琥珀色 只读 徽标；状态栏右侧显示「只读」并禁用保存。不做「只读也允许编辑后另存」的复杂分支—— 远程场景下另存为的路径选择器成本高于收益，先不做。

05

大文件降级态

新增 · > 2 MB 或 > 8 万行

要点：超过阈值时顶部出现一条 30px 横幅，明确告知关掉了什么、为什么（关语法高亮 + 关自动换行）， 并提供「仍然启用」的一次性豁免。降级不是为了偷懒，而是把成本花在刀刃上： 关掉软换行能省掉每行一次 TextInput 测高（即 editor_window.slint:254 那个热点）， 关掉高亮能省掉全量 tokenize。
注意现状：现在超限的文件是直接拒绝打开，不是降级—— src/sftp/impls/sftp.rs:1710-1712 的 MAX_BUILTIN_EDITOR_BYTES = 512 * 1024、 MAX_BUILTIN_EDITOR_LINES = 20_000、MAX_BUILTIN_EDITOR_LINE_BYTES = 64 * 1024 三道闸门任一触发就返回 EditorTextRejection。建议改成软上限 + 降级： 超限仍可打开（只读、可搜索、不可编辑），而不是一律拒绝。 编码 / 外观 / 格式化的完整设计见 editor-settings-hifi-2026-10-23.html（第二稿）。

06

窄窗 / 小屏态

min-width 420px

要点：420px 是 editor_window.slint:48 定的最小宽度。窄窗下：查找面板改为整行覆盖 （不再浮在右上角，否则只剩 200px 宽没法用）；状态栏只保留 Ln/Col 与两个图标按钮，其余折叠进命令面板； 行号槽缩到 38px（最多 4 位行号）。

设计 → Slint 实现对照

每个视觉元素对应到 Slint 的实现手段与代价。这一栏是可行性，不是美学。

视觉元素实现手段代价 / 风险可行性
语法高亮（彩色）slint::StyledText 公开 API 不可构造任意 span → 必须自绘：自绘 Rectangle+Text 逐 token 渲染每行 N 个元素；需配合行号槽虚拟化只渲染视口内 ±20 行，否则元素数爆炸可行
编辑态彩色同上自绘 + 隐藏 TextInput 负责输入，光标位置由自绘层跟随IME / 选区 / 光标同步是最大复杂度来源；建议一期只做只读彩色一期不做
行号槽ScrollView + for = 全量实例化（已核实）→ 换 std ListView（Slint 官方虚拟滚动）ListView 要求统一行高 → 与「关软换行」是同一个决定；行号必须并入每行才能同步滚动。注意编辑器有两份实现：ui/editor_window.slint:291 与 ui/app.slint:5263，应抽成共享组件可行
行高测量每行一个隐藏 TextInput 测高 → 改为整段一次测量 + 行高缓存软换行下行高不一致；可退化为「单行高度 × 行数」，关掉软换行即完全一致可行
查找面板普通 Rectangle+TextInput，visible 切换无简单
命中高亮自绘层按命中区间加底色依赖自绘层（见上）可行
命令面板浮层 + TextInput + for 过滤后的命令列表命令列表用 ModelRc 驱动，随输入重建（量很小，无压力）简单
状态栏一行 Text，属性绑定行列号更新必须增量，不能再走全量重算简单
修改行标记gutter 内一条 2-3px Rectangle，由「脏行号集合」驱动集合用 [int] 传给 Slint可行
滚动条Slint ScrollView 自带无已有
minimap自绘缩略条额外一遍布局 + 持续重绘不做
字素簇光标unicode-segmentation（已在依赖里）需按 grapheme 而非 char 计算列宽，CJK 全角算 2可行

⚠ 一条待验证 + 一条已核实（2026-10-23 更新）

  • ❗ 待验证：Slint 1.18 的 Text 是否接受 styled-text 属性、markdown 是否支持内联颜色语法 —— 官网文档路径当前 404（releases.slint.dev/1.18.1/docs/...），需查 docs.rs/slint/1.18.1 源码确认。 若支持，只读彩色的工程量会从「自绘几百个元素」降到「一次 StyledText 构建」，成本差一个量级。
  • ✅ 已核实：ScrollView + for = 全量实例化（每帧 O(n)）。 Slint 官方内置的 ListView（internal/compiler/widgets/common/listview.slint）走 「Repeater 内嵌 Flickable」的虚拟滚动，任意时刻只实例化可见行 + 少量缓冲（源自 Slint 官方 issue #11021）。 MTerm 全仓库零处使用 ListView，编辑器两处（ui/editor_window.slint:291、ui/app.slint:5263） 用的都是最慢的 ScrollView + for 写法 → 行号槽虚拟化应直接用 std ListView， 不必自研窗口化。
