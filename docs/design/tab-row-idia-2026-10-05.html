更根本的问题：× 和「关闭频道」语义重叠
左边已经有「关闭频道」（解散频道、踢掉其他成员、需二次确认）， 右端 × 又是「关闭」，两个按钮在同一行、只隔 10px，用户会点错—— 而且点错的那个后果不可逆（解散了频道）。

已做的区分：
① tooltip 写明 「隐藏状态条（不离开频道）」——点它只是收起这条 bar， 频道成员关系不变，再点顶栏「同步」按钮就回来；
② 形态不同：一个是文字按钮（关闭频道），一个是纯图标（×）；
③ 视觉权重不同：「关闭频道」是主色实心，× 是灰图标。
演示稿点状态条最右 × 可看到整条 bar 消失、 终端直接贴上来，但顶栏「同步」按钮仍是亮态——这就是「只隐藏、不离开」。
一个仍然存在的风险，建议你定：
状态条消失后，「我还在频道里」这个信息就没有任何常驻显示了 ——只有 tab 上的频道字母和底缘线。如果那条线不够显眼，用户会以为同步已关闭。
建议：× 隐藏后，在顶栏「同步」按钮上加一个 2px 强调色下划线 表示「已加入频道但状态条被隐藏」，点它重新展开。这样 「有没有在频道里」永远有一个常驻锚点，不会因为收起条就丢失。

为什么不用「确定 / 取消」
截图那两个按钮意味着「成员表立刻生效」。但本项目当前 app.rs:7971 是无差别全量广播—— for (target_id, handle) in h.iter() 遍历所有在线会话， 连发送方自己都发，既没有成员表也没有频道概念。

所以这个对话框是「模型改造的入口」不是「已有功能的配置界面」： 点「应用」要同时做三件事——
① 写成员表 tab_id → channel；
② 把 send_raw 的全推改成按当前 tab 所在频道筛选；
③ 排除发送方自己（现状会发给自己，靠 interactive_echo_until 压回显，属于将错就错）。
工作量全在 Rust 侧slint 侧只是多一个对话框。
四槽是固定的，不能增删 顶部四页签永远显示全部 4 个，即使某频道 0 成员也保留（显示 0）。
不能像 DBeaver 那样「新建频道」—— 频道要参与输入定向，槽位必须稳定可预期；而且色板是固定四色， 新增槽就要扩色板，会与分组色 24 色混淆。
一个 tab 只能属于一个频道 已在其它频道的会话在左栏置灰并标注，不能直接加入—— 要先从原频道移出。防止出现「同时收 A 和 B 两路输入」的歧义。
实现置灰行不可点，但仍显示原因 （悬停出 tooltip「已连接其它频道，先移出」）。
本窗口固定在成员里且不可移出 当前窗口的 tab 恒在当前频道（否则自己发给自己没意义）， 标记「本窗口」并禁用其移出。否则用户会困惑 「为什么这个移不掉」。
「重置」是必要的，不是多余 四个频道的成员表会持久化，一旦存错用户很难自己看出来。 「重置」= 回到「每频道仅本窗口」的默认态， 而不是清空——清空会让所有输入无处可去。
离线会话要不要列出来：截图只列在线的。本项目建议列出全部会话， 离线的那几个置灰并标「离线」——因为成员表是持久化的， 临时下线的机器回来后应该自动恢复同步；若不列出，用户得先把机器连上才能配， 绕路。落地时 Rust 侧过滤 handles 之外还要读 ConfigStore.sessions()。

顶栏按钮改三态后可这样验收 ① 未加入 → 按钮灰，点开对话框停在空槽频道；
② 已加入 X → 按钮亮，点开时页签预选 X；

演示稿本轮只做了 ①②， ③「暂停」在主界面的频道状态条上。
快捷键：先只做两个 Ctrl+Shift+S 打开对话框、Enter 应用、 Esc 取消。
别学截图标 (D)/(E)「添加全部/全部删除」—— 那是 DBeaver 的，本项目左栏可能几十个会话， 「全部加入」几乎永远不是用户想要的，误点代价还很高。 要批量就配合分组筛选（先筛分组、再全选该组）。
三个状态在左栏里同屏可见 可加入（正常）／已在其它频道（置灰 + 原因）／离线（置灰 + 标注）。
不要用 tooltip 独占原因——用户是在扫列表， 置灰行要能一眼看出为什么不能点，否则会反复点。
切页签不丢选择 四个频道的成员表在对话框内是暂存态，切来切去不会丢。 只有「应用」才写回、「取消」才丢弃——不能改一下就立刻生效， 否则误点无法撤销。
入口与状态条要联动，不能各管一套
顶栏「同步」按钮（app.slint:1718-1721）现在是 二态 toggle（开 = 广播中）。改成频道模型后它应该是三级： 未加入任何频道（点击 = 打开本对话框）／ 已加入频道 X（点击 = 打开本对话框，当前页签预选 X）／ 已暂停（点击 = 恢复发送）。
不能保留二态——「开」这个状态在新模型里已经不存在了： 输入是否广播，取决于「当前 tab 在不在某个频道里」，而不是一个全局开关。
