频道暂停标识无 字母加删除线
不改颜色		 改 暂停是跨 tab 的状态，原先只在状态条里表达， 而状态条只服务当前选中的 tab —— 切到别的频道就"失忆"了。
不用颜色，三条理由： ① 颜色通道已被"频道身份"占满，再塞状态就是一条通道两个信息； ② 暖色 #e2a84a 在亮色底只有 1.64:1， 压到 3:1 的 #8a5a12 在暗色底又只有 2.50:1，单值无解； ③ 与 C 槽 #ba7517 只差 1.76:1 —— C 槽暂停后字母跟自己没暂停时一模一样，功能在最需要的频道上恰好失效。
用形状：::after 画 1.5px 删除线 + background: currentColor（自动跟随频道色，不新增 token）， top:50% + translateY(-50%) 居中（不写死 top）， left/right:-1px 略微出头。
三态落在三个通道：正常 = 纯色字母 / 暂停 = 带删除线 / 不在频道 = 字母消失。 形状标记必须配文字：tab 的 title 在暂停时追加 「本会话已暂停与频道内其它会话的通信」
暂停的数据粒度— 按会话
PAUSED[sid]		 改 语义：只让当前这个 tab 退出与频道内其它 tab 的通信（既不发送也不接收）， 同频道其它 tab 照常互传。
判据：状态挂在"能被独立关掉的最小单元"上—— 频道是容器、会话才是通信的一端；挂在容器上就表达不了"只退出一个"。
key 用稳定 sid，不是数组下标 （下标会随拖拽 / 关闭移位，关掉一个 tab 会错删别人的标记）。

状态条操作无 3 个平铺按钮
窄屏 → ⋮		 改 「离开频道 / 关闭频道 / 隐藏状态条」默认全部平铺在状态条右端， 宽度够时 ⋮ display:none，完全不出现。 ⋮ 用竖排三点，横排 ⋯ 在中文界面里会被读成"省略号文本"。
正确解法是"降低权重"而不是"增加层级"： 破坏项用红字，位置仍在右手边，一眼扫到、一眼分辨。 原先收进 ⋯ 的理由只是"破坏性操作不该显眼"，代价是每次多点一次， 而且菜单项没有 tooltip、没有二次确认。
已删 × 键：「隐藏状态条」既是平铺按钮， × 就是同一件事的第二个入口，且最容易被误读成"关掉这一切"。
两条硬规则：① 破坏项在任何状态下都不能最醒目 （不给主色）；② 不做"挤掉一个留一个"—— 要么全平铺要么全收，部分可见等于没有规则
暂停入口位置— ⋮ 菜单 + tab 右键
不在状态条上		 改 状态条上不要放彩色按钮：它是整条状态条唯一的彩色块， 视觉重量压过左右全部信息——一条状态条里最醒目的应该是状态本身，不是操作； 且暂停是低频操作。
必须留两路入口：⋮ 只在窄屏出现，若暂停只挂 ⋮ 里， 宽度够时就没有任何暂停入口 → 功能等于废掉。 判据：折叠/隐藏型入口不能是功能的唯一入口， 必须有一条永远可达的路径。
菜单里用强调色文字（.mi.pri），不用实心底—— 深色菜单里的实心块与平面调性不符；强调色文字表达"这是当前可执行的主操作"， 且不与破坏项的红字撞（红 = 要慎重，蓝 = 可以点，语义不重叠）。
两处共用 togglePause()
状态条文案无 一句完整的话 改 旧文案「发送到 3」缺三要素： 没有主体（谁在发）、数字没单位、方向有歧义（"发送"可读成发出去或发进来）。
新文案四要素齐全：主体（我）+ 动作（发）+ 方向（发往） + 对象（另外 N 个会话）。「另外」是关键的——它解释了"为什么是 3 而不是 4"。
删掉「N 个会话」：它与流向说明是同一个事实的两种说法 （3 = 4−1），两个数字并排会让用户怀疑有一个算错了。那是冗余不是信息量。
暂停态文案必须两端都写：只说"不发送"，用户看到别人的输入 照常出现会困惑；只说"不接收"，用户以为自己的输入还能发出去。 且必须点明「本会话」并补「它们之间仍互通」——不写用户会以为频道全停了。
「发送到 0」改成文字描述："没有别人可发" ≠ "同步坏了"， 但裸 0 会被读成故障
投递数算法无 在线数 − 1 改 不能用「成员表长度 − 1」： 成员表是持久化的、离线成员仍留在表里（只是跳过投递） → 那个数不是"能发到几个"。
拆成两个数据源：CH_MEMBERS（表内总数）与 CH_ONLINE（在线数），投递数 = 在线 − 1（排除自己）。 这正是 send_key 改造第 ③ 步要用的算法—— UI 不该显示一个后端不会执行的数。
修一处不够，要问"还有谁在算这个数"： 对话框里的页签数字、右列「N 个」、底部「发往 N 个会话」原来都还在用成员表长度， 离线被算成在线 → 统一改成只数在线，右列另标「· N 离线」。

与「离开频道」的区别只有作用域：离开 = 当前这一个 tab； 关闭 = 本频道内全部活动会话。两者都不删频道。 破坏性操作的后果必须写在 tooltip 里，不能只靠名字让人猜

这个症状修了三轮才找全，每轮只找到一条。全部列出供后续核对：
成因 触发条件
1 transition 残留 拖拽过一次之后，之后任何宽度变化都被播成过渡 → tab 滑一下
2 插入线定位按 +1px 拖拽时插入线偏 1px（间隙归零后没同步）
3 关闭键在流内做 display 切换 鼠标悬停在任意 tab 上 → 关闭键突然占 20px， 把后面的 tab 顶开一条缝。最隐蔽： 不拖拽也会出现，但截图里鼠标不在 tab 上就看不到

验证方式：鼠标悬停在某个 tab 上按住不放， 看它右侧的 tab 是否被顶开。
判据凡是用 display 切换显隐的元素， 一律不进 flex 流（改 position: absolute）。 在流内切换 = 悬停时突然改变占位 = 把邻居顶开， 而"顶开"这个症状会被误判成"间距没设对"，极难定位。

三 · 频道语义与状态条
频道是一个固定 4 槽（A/B/C/D）的输入定向机制： 一个会话最多属于一个频道；加入新频道会自动退出原来的。 状态条是当前选中 tab 的频道状态，随它一起出现/消失。
三态落在三个不同通道上（这是本方案最要紧的一条）
状态 tab 行字母 含义
正常 纯色 双向都在跑
暂停 带删除线 通道停摆（既不发也不收），成员关系还在
不在频道 字母消失 根本不在场

语义梯度：删除线正好卡在中间—— 它表达的正是"成员关系还在、通道停摆"，而"字母消失"是更强的信号 （连通道都不存在）。
形状标记必须配文字：删除线比色块抽象， 用户不一定知道它表示"暂停"。tab 的 title 触发判据要改成 「有东西要解释」（标题被省略 或 频道暂停）， 而不是"标题截断了吗"。
暂停是「这个会话退出通信」，不是「整个频道停摆」
判据：状态要挂在"能被独立关掉的最小单元"上—— 频道是容器，会话才是通信的一端。 挂在容器上就没法表达"只退出一个"：用户想的是"这个终端先别掺和"， 得到的却是"整个频道静默"。
自问：这个状态描述的是「谁在做什么」， 还是「哪一组整体怎么了」？后者才挂容器，前者挂个体。
已数值验证：A/B/C 同在频道 X、只暂停 B → 带删除线的 tab = [B]（不是 [A,B,C]）； 投递矩阵 B → 发不出；A → 不含 B；C → 不含 B； A ↔ C 之间仍有通道。
粒度一改，所有"清 / 不清"的判断都要重新称一遍
位置 该怎么做
离开频道 清本会话。留着会在重新加入时莫名多一道删除线， 而用户已经忘了自己暂停过
关闭频道 清该频道下每个会话。⚠️ 只清这个频道的成员， 别整表清——其它频道的暂停互不相干
关闭 tab 清本会话（delete PAUSED[t.sid]）。key 是稳定 sid 才删得干净； 用下标会错删别人的标记
换频道 保留（跟着会话走）。要恢复由用户显式点「继续参与频道」
对话框应用成员表 不动。成员归属变化与暂停是正交的

判据：把粒度从「频道」改成「会话」后， 每一条旧结论的前提都变了——照抄别的粒度下的判断一定错。
状态条的三条硬约束
① 底色 = term-bg，与 tab 行条带、终端区三者同色。
用 bg-panel-alt 会比终端亮一档，状态条读成"另一个面板插在中间"。 暂停态也不能转暖底色——一转暖就又变成"另一个面板"， 改用左侧 3px 暖色竖条（#e2a84a，padding-left 同步 12→9px） + 文字标签。竖条比转色更克制——只占 3px，不破坏整条连续的面。

② 上下双线，顶线贯通整宽。
同色之后 tab 行下沿与状态条上沿没有任何色差（都是 #0e0f13，对比 1.00）， 这条线是唯一的分界手段。实测 #3a3d46 vs #0e0f13 = 1.77:1，亮色 #bfbfc8 = 1.75:1（与底缘线同值，上下等重）。
不要在选中 tab 处断开：有同步条时状态条本身是独立信息层， 边界必须完整——断开读成"选中 tab 漏下去了"。 连通关系由底色同色保持，不靠断开顶线。
顶线画成 absolute 1px、left:0; right:0： 由父盒宽度自动铺满，不依赖 tab 位置 → 切 tab / 拖拽 / 侧栏收放 / 窗口缩放 都不必刷新。若改成"按选中 tab 量位置分两段"，就需要 5 个刷新时机， 而且多出一类"忘了刷新导致错位"的 bug——这类 bug 触发时机很偏，最难查。
这条线与被撤掉的「tab 间分隔线」不是同一件事： 它隔的是两个信息层（标签行 / 频道状态条），职责必需； 被撤的那条隔的是同一层内的相邻同级，职责本就不成立。 别把"竖线都删了"顺手延伸到这条。

③ 宽度不够时整块换成 ⋮，判据量「离屏副本」。
不能用 barOps.offsetWidth 当判据的输入： 折叠态下它是 display:none → 量得 0 → 判据必然为假 → 切回平铺 → 再变紧，两个状态来回抖动（只有拖窗口时才可见， 静态截图完全正常，会被验收判成"通过"）。
根因是循环依赖：用"当前状态的元素"去量"需要多少宽"， 状态决定测量结果、测量结果又决定状态。 解法：克隆一份 barOps 放视口外测固有宽度， 结果缓存进 OPS_W，让测量与当前显隐彻底解耦。
判据通则：凡"根据当前状态计算目标状态所需资源"， 都要问一句「这个测量会不会被当前状态污染？」—— 折叠态量展开宽、隐藏态量可见宽、禁用态测可用宽，同一类坑。
不用媒体查询：状态条只占 main 列，侧栏展开/收起会改它宽度， 媒体查询测不到（监听 resize + ResizeObserver）。
对话框里暂停的成员也要列出来
它还在频道里（成员表没变），只是不参与通信——与"离线"同理， 不能藏起来。
标注「已暂停 · 互不收发」，与「离线 · 不接收」 措辞要能区分（两个是完全不同的原因）。

实现层：send_key 的暂停过滤要判的是 当前这个会话，不能写 if paused(ch) { return; } ——那会让一个会话暂停拖垮整个频道，正好是这轮要修的问题。 发送侧遍历前返回、接收侧收到就丢，两端都要判。
计数口径全项目统一
页签上的数字、右列「N 个」、状态条流向、底部「发往 N 个会话」—— 全部只数「在线且未暂停」，其余分项列出 （「另有 1 个离线、1 个已暂停，互不收发」）。
判据：修一处不够，要问"还有谁在算这个数"。 这个问题在状态条修好过一次，随后在对话框里以三个副本的形式重现。
两个数字并排会互相伤害：「4 个会话」与「发送到 3」 描述同一件事（3 = 4−1），用户第一反应是"是不是有一个算错了"， 于是整条信息都不可信——那是冗余，不是信息量。

错误 后果
元素带 opacity / 半透明色，直接拿色值算 必须先与底色混再算。实例：频道字母 #993556 + opacity:.75 在 #25282f 上混色后是 #7c324c， 对比度 1.70:1 而非 2.11:1 —— 系统性偏乐观。所以字母规格里禁止 opacity

工作量的分布
Slint 侧只是"多一个状态条 + 多一个对话框 + 改 tab 行的定位"， 工作量全在 Rust 侧：现在 app.rs:7971 是 无差别全量广播（for (target_id, handle) in h.iter()， 连发送方自己都发，靠 interactive_echo_until 压回显）， 既没有成员表也没有频道概念。
所以这个对话框是「模型改造的入口」，不是「已有功能的配置界面」： 点「应用」要同时做三件事——① 写成员表 会话 id → 频道；② 把全推改成按当前 tab 所在频道筛选； ③ 排除发送方自己。
