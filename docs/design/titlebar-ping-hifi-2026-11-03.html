01 / ANY TARGET一个清单，多个目标

任意 IPv4、IPv6 或域名都可以测：输入后回车即入清单。本软件已新建的主机从一个可搜索下拉里挑，选中即入清单。

02 / INPUT FIRST自由粘贴，加入即测

输入框是自由草稿：原样保留你的粘贴（空格 / 逗号 / 换行都行，不打断行），点框内「加入 N」才解析入清单——单个地址回车即可；多行编辑时回车换行、Ctrl+Enter 加入。执行统一交给页脚「探测」主按钮。格式错误就地提示，不把用户丢进一个只会转圈的弹框。

03 / QUIET连续 Ping，只在需要时

手动一次测完即止；勾选「连续 Ping」才以 2 秒间隔刷新，关闭弹框即停。在途的单次探测不被关闭打断，后台完成后结果保留。

04 / ONE LIST一张清单，两种视角

左边勾选目标，右边默认看汇总（全部曲线叠加 + 最慢 / 最快 / 抖动）；点某一行才看那一个。再点一次或点「← 全部」回到汇总。

工具头 / 32px 标题区

脉冲图标 + 「Ping 测试」标题，右侧关闭。这里只负责身份，不放目标或结果，避免和输入区抢层级。

2
目标草稿区 / 第一屏

输入框是自由草稿：原样显示你的粘贴（空格 / 逗号 / 换行都不改写），纯自动扩大（下限单行，超过 120px 出滚动条），无拖拽抓手。框内右侧按钮组（项目查找栏同款语言）：✕ 清空（22px 圆形热区，hover 强调色圆底+图标反色）+ 「加入 N」——点它才解析入清单，条数实时统计。无换行的单行回车即加入（不管几个地址）；多行编辑回车换行、Ctrl+Enter 加入。往清单加主机的 ＋ 入口在清单头。执行统一在页脚「探测」主按钮。

3
结果身份 + 主数值

先显示范围（全部目标 / 单个 target）与探测方式（ICMP / 端口），再给主数值：汇总态是最慢，单目标态是当前 RTT；端口模式是端口号 / 监听总数。数字用 tabular numerals，不做滚动动画。

4
趋势窗口 / 不画双 Y 轴

折线只画 RTT，上方标注 100ms 阈值。丢包用底部红色短刻度表示；窗口为最近 30 个采样点（连续 Ping 2s 间隔 ≈ 60 秒；手动单次只有 3 点，空窗是正常的），只滚动不重排。

5
三项硬指标 / 平均 · 抖动 · 丢包

放在同一行、同一基线上。异常时只把对应值转琥珀/红，不整块变色。测试中统一显示 —。

6
页脚 / 三段式

左＝连续 Ping 开关（默认关，2s）；中＝汇总（目标数 / 最慢 / 异常数）；右＝探测（主按钮）与清空结果：主钮为项目 PrimaryButton 原样——30px 高 / 6px 圆角 / accent 实心 / 纯文字无图标 / 12px 加粗 / 字色 ink-on / hover 白叠 12% · press 22%；次钮 1px 描边 ghost、hover 变面（CmSmBtn 规格）。探测按钮放页脚是因为它属于「执行」而不属于「输入」——输入区只管攒目标。没有原始输出：要原始报文就切回终端。

7
目标清单（常驻，不折叠）

清单就是结果表：勾选框 + 状态点 + 地址 + RTT + 丢包 + 迷你曲线，一行一个目标。加入目标有两条路——输入框回车，或清单头右侧的 ＋ 主机下拉（本项目已新建的主机 + 最近地址，可搜索）——加目标的入口跟着清单走，输入框只管输入。点已选行切换右栏详情。

9
汇总 ⇄ 单个

范围标签只在单个态出现（「← 全部」，点击返回汇总）——汇总态没有返回动作，视角由标题直接说明，不留一个看起来可点的高亮标签。汇总态把所有目标的曲线叠在一起（最差的一条高亮），统计给「最快 / 平均抖动 / 丢包目标」；单个态只画那一条，统计给「平均 / 抖动 / 丢包」。点清单里的行切换，点同一行返回汇总。

8
探测定义 / 源 + 方式

第一行只放「从哪探、用什么方式」：源（本机 / 托管主机）与 方式（Ping / 端口）。换源会改写结果口径，所以提示语与结果头的 source chip 必须同步改写。端口模式下源与提示退场（端口＝本机占用，无源概念），方式分段成为两个视图的切换开关。

05

场景与取舍：谁发起、探什么

「ping 谁」其实有两个方向：本机去探，和被 MTerm 管理的主机去探。前者答「我这边通不通」，后者答「A 能不能访问 B」。两者的问题、数据口径与失败模式都不同，所以交互上必须把探测源显式暴露出来，而不是藏在某个高级开关里。

SOURCE A / 默认 本机探测
回答
「我这台机器到目标通不通？」——含本地 Wi-Fi / 运营商 / VPN / 代理链路
用法
连不上服务器、怀疑 DNS 或本地出口、给同事一个「能不能 ping 通」的结论
约束
无任何前置依赖，按下即跑；结果天然是「用户视角」
占比
~70估计
SOURCE B / 进阶 从托管主机探测
回答
「A 能不能访问 B？」——服务器之间的东西向连通性
用法
应用连不上数据库、灰度节点互访、查安全组 / iptables / 服务网格策略
约束
需该会话在线（复用已有 SSH 通道，不新增凭据）；远端需有 ping 或可用的 /dev/tcp；RTT 是源主机视角，与本机值不可直接比
占比
~30估计

占比是假设，不是数据 —— 怎么在发版后把它变成数据

口径做法判据
源分布埋 probe_source ∈ {local, remote}（只记来源，不记目标内容）remote > 40% → 把「源」从二级选项提到首屏常驻
方式分布埋 view ∈ {ping, port}「端口」视图使用率持续走高 → 考虑独立成窗（系统信息窗口那套），而非塞进 Ping 弹框
分层看按会话数分层：单机会话 vs 多主机 / 团队会话两类人群比例不同，UI 默认值也应不同
时机对比「日常」与「故障高峰」的 remote 占比高峰占比显著上升 → 说明它更像一个「排障模式」而非「常驻功能」

端口模式＝本机端口占用视图，不是远程端口探测

「端口检测」回答的问题其实是「本机哪个口被谁占了」——起服务撞端口、查占用、看服务有没有在跑。它等价于把 ss -tlnp / Get-NetTCPConnection 图形化：一次列出全部监听端口（端口 / 进程 / pid），选中看详情（监听地址 / 路径）。在这条路上，目标、源、端口挑选都用不上。

WHY / 退场三样源提示、端口挑选、＋ 全部不需要

没有目标就没有「你 → 目标」的链路（源提示不适用）；监听端口本来就全在本机一张表里，不需要挑选（端口 chips 退役）；没有清单就无需 ＋ 添加主机。草稿输入框同样退场——切回 Ping 全部恢复。

WHY / 结果语义不同Ping 给数值，端口给占用

ICMP 给的是数值（RTT / 抖动 / 丢包 + 曲线）；端口给的是占用（端口 / 进程 / pid / 监听地址 / 路径）。两个视图共用弹框骨架但内容互斥，切方式 = 换版式。

WHY / 一键全量刷新一次给全部

监听端口是快照不是探测：点「刷新」重新拉取一次（复用「监听端口」预设命令通道），搜索框按端口 / 进程名就地过滤。要测远程端口可达性，用 Ping 模式的草稿输入远程地址即可。

「这个端口上跑的是什么」——监听进程能不能显示

能，但只在能下命令的主机上。MTerm 里已经有一条现成的「监听端口」预设命令（ss -tlnp；Windows 侧 Get-NetTCPConnection + Get-Process），端口模式可以复用同一条通道执行，不必新造能力。规则很简单：目标主机是本机、或 MTerm 有在线会话的托管主机 → 查得到进程名；否则查不到。

目标能否显示监听进程界面上的说法
本机 / 127.0.0.1能mysqld · pid 2210 · /usr/sbin/mysqld——这就是「我本机 3306 被谁占着」
托管主机（会话在线）能经该会话的 SSH 通道执行 ss -tlnp，返回进程名 + pid + 路径
托管主机（未连接）不能「目标主机未连接，无法查询监听进程」——给原因，不给空白
任意 IP（不在会话列表）不能「目标不在会话列表，无法查询监听进程」；只能给出「端口开放」这个结论
远端非 root部分看得到 socket 状态，看不到进程名（要 root 才看得到 PID）→ 明说降级原因

两条语义要写清楚：① 进程属于目标端（谁在监听那个端口），不是发起端；② 它是「通的是什么」的补充信息，不是把 Ping 工具变成进程管理器——不提供 kill / 改端口这类动作，那属于运维操作且有风险。

端口模式的视图结构

弹框骨架不变（左定义 + 清单 / 右结果），端口模式下左栏整体换成监听端口表，右栏换成选中端口详情。

项取值说明
左栏监听端口表全部监听端口一行一条：端口 / 进程 / pid；顶部计数 + 搜索框（按端口 / 进程 / 监听地址过滤），无 ＋、无草稿
右栏选中端口详情未选中＝端口总数 + 「点左侧查看详情」；选中＝端口号大字 + 「监听中」+ 监听地址 + 进程 / pid / 路径
数据通道复用「监听端口」预设命令ss -tlnp；Windows 侧 Get-NetTCPConnection + Get-Process，「刷新」= 重新拉取快照
页脚连续 Ping / 清空结果退场「探测」按钮在端口模式下变「刷新」；汇总条给「N 个监听端口 · M 个进程」
远端挂账托管主机占用视图后续版本可扩展：源选在线托管主机时同一视图展示其监听端口（同一命令经 SSH 通道）；当前版本聚焦本机

交互落点：两组控件，两层含义

层控件作用
定义「怎么探」源（本机 / 托管主机） + 方式（Ping / 端口）换源 = 换视角，结果口径随之改变，界面必须说清是谁的视角；换方式 = 换结果版式
定义「探谁」输入框（回车加入）+ 清单勾选只有一种多目标交互：清单勾选。清单常驻，不另开选择器
端口占用视图左栏监听端口表（搜索 + 刷新）端口模式专用：无目标概念——源提示 / 草稿 / 清单 / ＋ 全部退场；选中行右栏给进程详情，页脚「探测」变「刷新」
执行Ping / 探测 按钮源不可用（会话未连）时按钮旁就地报错，不发请求
呈现结果头固定带 method 与 source 两个 chip任何时候都能回答「这条结果是谁、从哪、用什么方法测的」

尺寸：一个就够，760×460，可拖可缩

高亮设置是 716 × 706，它敢那么大是因为要编辑一整套规则（列表 + 取色器 + 预览）——编辑规则时本来就不看终端。Ping 不需要那个高度，但需要那个宽度：左边是一张表（目标 / 状态 / 延迟 / 丢包 / 趋势），右边是一条曲线，两样都要横向空间。所以宽度对齐高亮设置（760），高度对齐设置弹框（460）：760 × 460，标题栏可拖动、右下角可缩放，最小 560×420、最大到窗口边界。

WHY / 760×460宽＝高亮设置，高＝设置

表格和曲线都要横向空间，所以取宽；纵向只需要「定义 + 清单 + 结果」三段，所以取高。项目里已有可拖拽 + 可缩放的实现（settings_dialog.slint：ifd-w/ifd-h + 抓手），Ping 复用那套手感。

WHY / 双栏左「目标」右「结果」

左栏＝源 / 方式 / 端口 + 输入 + 目标表（清单即结果表）；右栏＝选中目标的大数字 + 曲线 + 统计 + 监听进程。清单是唯一的入口，不另开选择器。

WHY / 不做两种形态一种尺寸 + 可缩放

小浮层 + 宽面板的双轨会带来两套布局、两套记忆点。要更大的空间，拖一下就行；要长时间盯盘，则另开独立窗口（进程窗口 / 系统信息窗口那套），而不是把弹框做大。

用户当下的念头在弹框里怎么做为什么
「能不能 ping 通」右栏一个大数字 + 一个状态词一眼看完，不必滚动
「哪个慢 / 有没有丢包」左栏清单逐行列 RTT / 丢包 / 迷你曲线多目标一眼对比；曲线细节看右栏选中项
「这个端口上跑的是什么」右栏「监听进程」块查不到时给原因，不给空白
「我要大一点看」拖右下角抓手放大一个尺寸已经够用，放大是用户的选择而不是另一套设计
06

动效与键盘

动效只解释状态变化，不表演。所有过渡都短于 160ms，避免在终端工作流里拖慢下一次输入。

打开与探测时间线

1点击图标0 ms
2弹框入场130–140 ms
3输入目标 + Enter输入框已聚焦
4结果落位≤ 1600 ms

入场：opacity 0→1，translateY −5px→0，scale .985→1，cubic-bezier(.16,1,.3,1)，结束后焦点进入输入框。关闭：90ms 淡出。连续 Ping：2s 呼吸，不使用弹跳。

键盘与焦点

  • Enter无换行＝加入（单行草稿不管几个地址都解析入清单）；有换行＝换行继续编辑；空值不动作；非法目标就地提示
  • Ctrl+Enter加入草稿 任意行数下都生效，与「加入 N」按钮同效；加入后草稿清空
  • Esc关闭弹框，焦点回到标题栏图标
  • Tab关闭 → 探测源 → 方式 → 端口 → 输入框 → 清单行 → 连续 Ping → 探测 → 清空（落地时建议跳过头部「关闭」，从探测源开始）
  • ↑↓多目标清单内上下切换选中目标（曲线与统计随之切换）
  • Ctrl+A输入框内全选目标地址，便于整体替换
  • 1–4本页沙盘状态预览；产品内不注册数字快捷键

时序参数

弹框入场140ms · ease-out-quart · opacity + translateY(4px) + scale(.985)
弹框退场90ms · ease · 仅 opacity
数值/状态切换120ms 颜色过渡；数值直接替换，无滚动
趋势折线180ms 路径过渡；窗口滚动时不做逐点入场
首次探测延迟提交后 0ms 发起；打开弹框只聚焦输入，不自动发包
07

落地备注

输入是主路径：任意 IP / IPv6 / 域名都能测；项目主机与最近目标只是清单里的候选项，勾选即加入，不改变工具的全局属性。

DATA / 目标解析用户输入优先生效

输入框是草稿区：粘贴内容自动按行排开（空格 / 逗号 / 分号都认），「加入」并入清单，单条回车即可；主机下拉取的是本软件已新建的会话（与左侧会话列表同源），选中即用该会话的地址。域名先解析，结果区标注实际地址与探测方式（ICMP）。

SAMPLING / 采样手动单次，按需连续

「探测」按钮触发一次 3-probe burst；只有开启「连续 Ping」才以 2s 间隔运行（多目标时对每个存活目标各采一点，超时目标持续重探等恢复）。连续 Ping 随弹框关闭立即停止；在途单次探测不被关闭打断，后台完成后结果保留、重新打开即呈现。清空结果只清数值、保留目标清单。

MULTI / 多目标一次最多 12 个，逐个探测

输入框以空格/逗号分隔多个地址（回车一次性加入），或从主机下拉里挑。每个目标独立探测与独立状态，互不影响；汇总条给出「最慢 / 异常数」。

PICKER / 主机选择可搜索 + 悬浮信息卡

「源」与「清单头 ＋」（目标主机）两个下拉共用同一套：顶部搜索框（按名称 / 地址 / 用户过滤）、条目只显示主机名称（同左侧会话列表的单行化），悬浮 150ms 弹信息卡，逐行给「主机 / 用户 / 认证 / 备注」——与项目里会话行的悬浮卡同款。

GUARDRAILS / 约束不抢焦点，不制造噪声

打开后焦点进入输入框，但不在终端输入过程中抢焦点；颜色之外必须有「优秀 / 一般 / 超时」文字。沿用项目 1px accent + 3px accent-soft 焦点语言。

REMOTE / 托管主机发起复用已有 SSH 通道

源为托管主机时，探测命令经该会话的 SSH 通道下发（ping -c 3 -W 2），不引入新的凭据与协议栈。会话未连接就就地报错；远端缺 ping 工具时结果区明确说明，不静默失败。端口占用视图当前聚焦本机，托管主机的占用快照列为后续挂账。

SIZING / 一个尺寸760×460，可拖可缩

单一弹框形态：双栏（左目标表 / 右结果），标题栏拖动、右下角抓手缩放（最小 560×420），行为与项目已有的 设置 弹框一致。不做「小浮层 / 宽面板」两套形态。

边界情况

场景处理
空值 / 非法输入输入框红边 + 错误文案「请输入有效的 IPv4 / IPv6 / 域名」；不发起请求，保留上一次结果可对照。
多目标里混有非法地址草稿逐行校验：点「加入」时只提示出错的那一行（第一个非法项），整批不入、草稿保留可改；单条草稿回车同样就地提示。
目标过多一次最多 12 个目标：超出直接提示并说明跳过数量（已跳过 N 个），不静默截断；清单头行数到 12 时转琥珀警示。
端口模式刷新中「刷新」读取监听端口快照期间按钮转圈禁用（约 1–2s），清单保持上次内容可继续查看；完成后 toast 报告数量。
探测中修改定义在途探测按提交时的快照完成：源 / 方式 / 端口 / 清单的改动只影响下一次探测，结果不会串到新定义上。
部分目标失败某个目标超时不影响其它目标：清单里该行转红，其余行照常出数；汇总条给出「N 个异常」。
域名解析失败该行状态列显示「解析失败」，告警条说明原因；Ping 按钮保持可重试。

窗口贴近右缘弹框以按钮中心为优先锚点，左右各留 12px 安全边距；transform-origin 随实际位置调整。
