MTERM 按钮重设计 v5 · 按主流规范
2026-10-22 · 不再自己发明规则

对话里只有一个主按钮，
取消是描边——这条不是我定的，是主流的做法。

上一版我把「取消」做成了灰色填充块，觉得“终于有形状了”。查完规范才发现这恰好是明确的禁忌： 对话框里不要并排两个凸起按钮。你觉得怪，是因为它和「创建」在抢同一层注意力。 这一版把按钮尺寸、层级、文案都对齐 GitHub / Vercel / IBM Carbon 的实际规范。

RULE 01

一组只允许一个主按钮

「Never put more than one in a group of buttons.」其余降为次要。

GitHub Primer
RULE 02

取消用描边，不用填充

「对话框里不要并排放两个凸起按钮。」次要动作要降对比。

Dialog guidelines / Carbon
RULE 03

主按钮文字用白字

Primer、Geist、Composio 的 primary 都用 on-primary。

Primer / Geist
RULE 04

32 高 / 圆角 6 / 13px

GitHub 32-6、Composio 40-8。描边键内衬减 1px 补边框。

Primer / Composio
RULE 05

文案写「动词 + 宾语」

不要 OK / 确定这种空词 —— 它不说明会发生什么。

Vercel Geist

取消是描边。它和「创建」的关系是「一个能看见的退路」而不是「另一个按钮」—— 底透明、1px 边、没有色块。
测试连接保持你要的浅填充。它在页脚左侧、带图标，属于功能键，和右侧的「取消 / 创建」不在一个组里，所以不违反「一组只有一个主按钮」。
02

确认删除

红只出现在落点。「取消」保持中性描边，不跟着变红 —— 两个红色按钮并排时，红就不表示危险了。
「确认删除」→「删除文件」。Geist 的规则是 Verb + Noun：说清删的是什么，比「确认」有用。
03

新建分组

app.slint:6218（13 处 std 控件之一） 「确定」→ 动词
新建分组×
分组名称
生产环境
「确定」是最差的按钮文案。它不说明会发生什么，用户得回头看标题才知道自己在确认什么。换成「创建分组」后，标题都可以省掉一半。
按钮不等宽。主流的按钮宽度跟内容走（min-width: 64 只防过窄）—— 强行等宽会让四个字的按钮被压、两个字的被撑。

上传 / 下载是描边小键，其余是图标。只有一整排都是图标时，「无底 + 悬停出面」才成立；带文字的动作给个边框，否则读不出可点。
删除只悬停转红。列表里一排红叉是最常见的过度设计。
