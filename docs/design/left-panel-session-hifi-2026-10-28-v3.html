00设计上下文DESIGN CONTEXT

设计方向不是从“好看”倒推的。它由使用者、工作场景和一次真实的失误风险决定。

USERS
开发者 / 运维同时管理 10–100 台服务器，长期开着多个终端标签；频繁在生产、预发布、开发环境之间切换。
JOB
快速找到并进入正确的主机扫读名称、环境、主机地址与连接状态；整理分组；把会话从一套环境移到另一套环境。
TONE
精确、安静、可靠像一块仪器面板，而不是消费级仪表盘。信息密度高，但每个元素都有职责。
ANTI
不要这些玻璃拟态、霓虹渐变、彩色图标汤、卡片套卡片、把所有按钮都做成主按钮。

Design Principles / 五条设计原则

  1. 结构先于装饰。分组层级、组色、缩进和分组带先建立归属；图标与动效只做辅助。
  2. 状态必须能被解释。当前标签、已打开、在线、连接中、选中、拖拽中，每个状态都有唯一视觉来源，不叠加“第三态”。
  3. 危险环境先于美感。生产环境使用暖色分组带与更明确的计数；删除、移动等批量操作必须可撤销或二次确认。
  4. 键盘不是附加项。搜索、遍历、展开、打开都必须有键盘路径；焦点环优先于悬停效果。
  5. 为下一块面板留白。会话只是左面板的第一个标签；结构要为 SFTP 留出可扩展的壳层，而不是把会话做成唯一入口。

02结构解剖ANATOMY

左侧面板被拆成三个稳定的纵向层：面板标题 → 搜索行（按需） → 树画布。 只有树画布随会话数量伸缩；搜索行默认收起，点击标题栏搜索图标或 Ctrl+Shift+K 才展开。文件页签本版收起，标题右侧保留搜索 / 新建 / 定位 / 更多；底部统计 / 收起条已移除。

为什么 V3 先把文件页签收起

文件页涉及 SFTP 独立数据源、目录状态与传输队列，和会话树不是同一种信息密度；在信息架构没有定稿前，强行给左面板塞第二个页签只会让「+」的语义继续漂移。V3 先只做会话面板，把文件页留给下一阶段。

面板壳层仍然保持可扩展：标题右侧保留 ⌕ 搜索、new-session、⌖ 定位当前终端、⋯ 面板菜单 四个入口；未来接入文件页时，无需再挪动会话树。

为什么把新建收到标题栏

搜索默认收起后，面板顶部只保留标题和四个裸图标，树直接上移。需要搜索时再展开搜索行，搜索框独占整宽；不会让常显输入框一直占着一整行高度。

「＋」不再常亮：默认与搜索 / 定位 / 更多同色，悬停才转为强调色；仍然只靠图标表达，不用大面积色块。

为什么去掉树脊线

在 328px、2 级、深色侧栏里，竖向树线会同时和组色、悬浮底、选中态、状态点争抢注意力；用户真正依赖的层级线索其实是缩进、分组带和文件夹图标。去掉树线和成员左侧竖线后，30px 父组 / 27px 子组 + 20px 缩进 + 34px 单行成员已经足以表达归属，滚动和拖拽时也少了一层需要重绘的装饰。

为什么图标不再加底座

26px 圆角底座 + 边框 + 阴影只是在给图标“加第二层轮廓”，但协议类型本来就靠字形区分。V3 改为裸图标，图标更轻，行距和组带更清楚；只有真正需要区分的“当前会话”才用背景渐变，不再给每个图标配一个阴影方块或在线灯点。行悬停时右侧操作也不再出现胶囊底座或阴影，只保留裸图标，悬停用颜色变化反馈。

颜色设置复用 / 预设弹框 + ColorPickerDialog

分组颜色不再使用右键菜单内联色板，而是完整复用「设置 → 强调色」的两级选择：① 预设颜色弹框（最近色 + 48 个预设色，点选仅暂存）→ ② 点「调色盘 ›」进入 ColorPickerDialog（色轮 / 明度条 / HEX / RGB / HSV / HSL）→ 返回预设弹框点「应用」写回分组。两个弹框的尺寸、控件和确认/取消语义都与强调色设置同一套。

步骤界面行为
1 · 入口右键分组 →「分组颜色…」不再展开内联色板；打开与强调色同款预设弹框。
2 · 预设最近色 + 48 色 8 列网格点选只暂存「选定」；取消/关闭还原；底部可随机、应用。
3 · 自定义「调色盘 ›」→ ColorPickerDialog确认只把新色带回预设弹框，不直接改分组；取消回到原预设。
4 · 应用预设弹框「应用」写回分组颜色；只更新分组带与文件夹图标，不给成员区铺底色。

Color Inheritance / 子分组颜色

有效色 = 本组自定义色 → 最近祖先自定义色 → tone 默认色

子组没有自定义色时，跟随父组：父组从琥珀改成蓝色，所有子组头也一起变。子组一旦设置自定义色，只影响自己的组头和其下子组头；父组色不会覆盖它，也不会给成员区铺任何底色。

树里的分组带和文件夹图标读取同一个有效色；成员行始终是中性底色。这样“生产环境”整体保持琥珀，内部“数据库集群”可以单独用紫色组头表示风险域，但成员区不会出现双层渐变。

交互：继承是默认态，自定义是显式动作

预设弹框标题旁显示当前状态：「继承自 生产环境」或「自定义」。在子组上点「应用」但没有改颜色时，保持继承关系，不会把父色固化成子组自己的颜色。

子组右键菜单提供「恢复继承父分组」；清除自定义色后，子树立即回到父组有效色。这样用户可以放心试色，也可以一键回到统一环境色。

03定位与树形交互LOCATE & TREE

这棵树有两个入口：从树里打开终端，也从终端反查树。下面的定位流程参考 IDEA 的 Select in Project View， 把“当前终端在哪里”变成一个可重复、可键盘化、可感知的动作。

Locate / 从终端到树

一次定位，四步完成

1 · 触发：终端头部 ⌖ 在树中定位，或 Alt+F1。未来若文件页已接入，会先切回会话页。

2 · 展开：自动展开当前会话的所有祖先分组；搜索 / 过滤状态会先被清空，确保目标行一定可见。

3 · 滚动：将当前会话行滚动到树视口中央，而不是顶边，保留上下文。

4 · 确认：行出现 1.8s 静态高亮（描边 + 浅底，不做呼吸/脉冲）；顶部临时展开「已定位 · 生产环境 / 华东区 / web-prod-02」路径条。

为什么这是 IDEA 式的

IDEA 的 Project View 用目标图标和 Select in Project View 解决“编辑器里的文件在哪里”。MTerm 把它移植到终端：终端是 Source，会话树是 Project View；动作方向是从右往左，不要求用户先回到树再找。

反向路径仍然保留：树内双击 / 回车打开终端，右键菜单也可「在终端中激活」。定位不是取代树，而是补上从终端反查这一半。

点击顶部标签时，树自动跟随：展开目标会话的祖先组、滚动到视口中央、做 1.6s 静态高亮，不弹出路径条；手动「⌖ 在树中定位」仍保留完整四步定位。

触发定位前状态定位后反馈
⌖ 在树中定位 / Alt+F1折叠组 / 搜索过滤 / 长列表滚出视口切回会话页 → 展开祖先 → 居中还焦 → 1.8s 静态高亮 → 路径条
点击顶部标签目标会话在折叠组 / 树视口外自动展开祖先 → 滚动居中 → 1.6s 静态高亮；不显示路径条
定位时没有活动终端没有打开的终端标签Toast「当前没有活动终端」，不改变树状态
定位到未打开会话会话存在但无标签（例如手动从树选中）仍然定位并聚焦；打开动作需要用户确认，不隐式开连接
T1

展开 / 折叠

点击整行 · 点击箭头 · ← → · Enter

组头整行都是命中区，箭头只是视觉提示。展开时箭头旋转 90°，子层高度在 170ms 内展开；折叠后计数徽章仍留在组头，用户不必展开就知道里面有多少项。

  • 状态持久化到 collapsed_groups；重开应用保持。
  • 搜索或过滤时强制展开匹配路径，但不写回用户的折叠状态。
  • 空分组展开显示「空」占位，避免点击后无反馈。
T2

搜索与过滤

搜索图标 / Ctrl+Shift+K · 输入即筛 · Esc 收起 · ↑↓ 遍历

搜索默认收起，避免常显输入框占高度；点击标题栏搜索图标或按 Ctrl+Shift+K 才展开。搜索覆盖名称、主机地址、用户名、备注和分组名，命中组名会带出全部子项——用户搜“生产”时，要看到整个生产环境，而不是一个空组头。

  • 搜索命中直接过滤树；结果计数显示在标题的会话总数旁，清零时保留搜索词。
  • 无结果时显示搜索空态与「清除搜索」，不显示新建空态。
  • 不再保留「全部 / 在线 / 最近」筛选行，树默认展示全部会话。
T3

单选与键盘打开

单击 · Enter · Space · ↑↓ 遍历

单击会话行直接打开；树默认不做 Ctrl/Shift 多选，不出现复选框和批量条。组级操作留在右键菜单，批量动作等真正出现高频需求时再用显式模式提供。

  • 成员行只有一个主操作：打开会话；悬停只补充「更多」。组头也只保留「⋯」，新建会话通过顶部按钮或组菜单完成。
  • 焦点、当前会话、在线状态三者分开表达，不把选择态混进树。
  • 删除仍走单行右键 + 二次确认；移动走单行「移动到分组…」。
T4

拖拽与落点

按住行拖动 > 6px · Esc 取消

拖动中出现半透明 ghost 卡，显示会话名与主机；目标行上方或下方出现 2px 落点线。拖到组头整行时高亮为“放入该组”，停留 650ms 自动展开折叠组。

  • 会话可在同组内排序，也可跨组移动；保留组（本地终端）默认不可移入。
  • 组本身可拖动排序；组拖拽只改变同级顺序，不改变父子关系。
  • 落点若无效（拖到搜索框、面板外），ghost 回弹并取消，不写入模型。
T5

右键菜单

右键组头 / 会话行 / 树空白

菜单在指针处打开，靠近底部时自动上翻；点击外部或 Esc 关闭。父组菜单包含新建会话、新建子分组、重命名、组色；子组只到一级，不再提供「新建子分组」。会话菜单包含打开、在新标签打开、编辑、复制、移动、复制主机、删除。

  • 高频动作放在前 3 项；危险动作沉底并标红。
  • 组色打开与「设置 → 强调色」同款的两级流程：预设弹框（最近色 + 48 色）→「调色盘」ColorPickerDialog（色轮 / 明度条 / HEX / RGB·HSV·HSL）→「应用」写回分组带和文件夹图标。
  • 菜单打开时，对应行保持菜单锚点高亮，指针移开也不闪灭。
T6

键盘导航

方向键 · Home/End · * · Enter · Space

树采用 roving tabindex：Tab 进入树后，只有当前行可聚焦；方向键在可见行间移动，→ 展开组或进入第一个子项，← 折叠或回到父组。焦点环为 2px accent + 2px 外扩，不依赖悬停才可见。

  • * 展开全部，Shift+* 折叠全部（可在实现时调整）。
  • 搜索框内 ↓ 进入结果树，Enter 打开第一个结果。
  • 焦点移动时同步 aria-activedescendant，读屏可播报层级与状态。

快捷键避让说明

终端内 Ctrl+K 必须继续是“删除到行尾”，因此左侧搜索在全局使用 Ctrl+Shift+K；焦点已在左侧面板时，额外接受 / 直接进入搜索。新建会话建议 Ctrl+N 仅在左侧面板聚焦时生效，避免与终端行编辑键抢占。

Move to Group / 移动到分组

不再把菜单铺到终端区

旧交互在右键菜单右侧展开一个平铺分组列表，菜单会越过面板边界盖到终端上；层级、当前所属组和批量目标都不清楚。新版改为应用窗口内的可拖动浮动弹层：标题栏可拖动，标题说明“移动 1 / N 个会话”，搜索框即时过滤，列表按树形缩进显示分组路径与成员数。

当前所属组用「当前」标记并禁用；目标行点击后高亮，底部「移动」才可用。单行右键即调用同一弹层，不再出现“菜单在终端上找分组”的问题。

取消 / 确认语义

取消、关闭、Esc、点遮罩 = 不改数据；双击目标行或选中后 Enter = 确认移动。移动后刷新分组计数，目标组自动展开。

拖动标题栏可移动弹层，位置限制在应用窗口内；目标组里的计数包含子孙会话，保留组（本地终端）不出现在目标列表里，避免把远端会话误移到本机保留组。

旧交互问题V3 处理
右键菜单右侧展开平铺组列表越过面板、盖住终端；嵌套组看不出层级；目标与当前组混淆窗口内可拖动弹层 + 搜索 + 树形缩进列表；当前组置灰；底部确认
单行右键入口不再需要为批量选择维护第二套菜单统一调用 openMoveDialog(ids)，标题显示目标数量

数据模型 / From Flat to Tree

// 当前：SessionInfo.group 是字符串，组不是实体
SessionInfo {
    group: string,        // "" / "default" / "system" / 自定义名
    group-header: string, // 显示层把首行伪装成组头

}

// 目标：组是一等实体，会话只引用 group-id

    id: string,
    name: string,
    parent-id: string,    // "" = 根级

}

SessionInfo {
    group-id: string,     // 替代 group: string
    // 其余字段保持不变
}

迁移顺序

1. Rust 侧新增 Vec<SessionGroup>，把现有 group 字符串去重生成实体；保留组 system / default 固定 ID。

2. 生成扁平渲染模型 Vec<TreeRow>（group 或 session + depth），Slint 只消费扁平数组，避免递归布局造成性能与状态问题。同组内直属会话与子组的先后顺序必须定死（建议子组在前），否则成员块不连续，现有组内拖拽几何无法复用。

3. 保存时写回 groups 与 sessions.group-id，提供一次性迁移与回滚脚本。

4. 新回调统一为 move-node(node-id, parent-id, index)，替代当前“组内仅排序”的 move-session-to。

四条落地约束 / P0

① 先统一 group id，再做实体

现状里侧栏用 "default"，分组管理台用显示名「默认组」作键；不先统一，嵌套后改名、拖拽、组色都会写错对象。迁移第一步必须是 id 唯一化 + 别名映射，而不是直接加 parent 字段。

② Slint 仍吃扁平行，不递归布局

Rust 侧用 build_session_rows 递归拍平成带 depth / group-path 的 SessionInfo 行模型，Slint 继续渲染单列表。这样可保留现有列表/滚动/拖拽基础设施，避免递归组件带来的状态与性能问题。

③ 双实例状态必须回到 Rust

欢迎页与停靠侧栏默认同屏复用同一 LeftSidebar；搜索、右键、hover、折叠如果继续放在 Slint 本地，两个实例会漂移。新增的组状态、选中态、折叠态统一进 Rust 模型，UI 只做投影。

④ 拖拽分两期落

本稿把跨组拖拽作为目标态完整演示；但现有成员组内排序与组头扁平排序是两套状态机，嵌套后命中区、组高、单条插入线都会失配。建议一期先做「显示 + 折叠 + 右键移动」，跨组拖拽在二期重构状态机后上线。
