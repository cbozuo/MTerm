「发送命令」不是一个输入框，
是一台发射台：写什么 · 发给谁 · 安不安全 · 落没落

这个窗口被调了 8 轮（#cmdbar-expand-left → #cmd-expand-window → #cmd-expand-fixes → #send-cmd-window → #send-cmd-polish → #send-cmd-round2 → #send-cmd-round3 → #send-cmd-caret-live），每一轮都在修看得见的像素： 中缝线断了一截、下拉框边线太粗、深色面板里立着白色滚动柱、光标类型没跟着变。 这些都对，但它们回答的都是「这块画得对不对」。

从没人问过另一个问题：用户在这个窗口里到底要完成什么？ 用户自己其实说过 —— #cmd-expand-window 那一轮的原话是 「发给频道 A，再发给全部标签页是常见用法」。也就是说，这是一个连续对多台机器下命令的地方。 可它现在的结构是一条「命令栏 + 一个多行输入框」，四个最关键的问题里只答了一个半。

诊断 点第一条第命令，左栏就空了 过滤态拿整段草稿当搜索词（:161）。点一条 → 草稿多一行 → 其余条目全不命中 → 高度归零。 用户最核心的「挑几条、拼起来、连发」第一步就走不下去。
结构 一条命令的四个问题，只答了一个半 写什么答得不错；发给谁只有字母 + 台数，永远看不到主机名； 安不安全只有一句标签，Ctrl+Enter 直接绕过；落没落只有一个 1.4 秒的「已发送」。
提案 把答案收进左下角那一个键 不再新增常驻行：目标、告警、回执全部长在「发送范围」键的悬浮提示卡里。 页脚只留两个控件（范围键 + 发送键），正文区不多被占一行。

01活沙盘：改过的窗口长这样

下面是 1:1 逻辑像素的可操作原型。直接试：在左栏搜索框里打字（注意：搜索框和草稿是两件事， 这是本次第一处改动）；点命令行 → 插入到光标处并独占一行；点右下「当前标签页 ▾」展开目标菜单， 能看到真实主机名；敲 rm -rf 看发送键先转红（仍是「发送」）， 点一次才变成「再点一次确认」；按 Ctrl+Enter 也一样要走那两步。

本轮新增的几处，可以直接在这块沙盘里点：粘一段多行命令（例如 if true; then 换行   echo hi） → 底部出现「2 行 · 整段粘贴」胶囊，点它可以切回逐行；点一次发送 → 回执里出现「重试这 N 台」与「清空」； 拖两栏之间那条竖线 → 改左栏宽度，双击复位；悬停左下角范围键 → 目标卡，鼠标可以移进去复制。

03重构：一条命令其实是四个问题

现在这个窗口只完整回答了第一个。把四个问题摊开，每个都要有一个看得见的答案， 而且答案要能在同一处、不跳变地出现 —— 最终落点是左下角那个「发送范围」键的悬浮提示卡。

01写什么

答案在编辑器。现状不缺，但缺辅助方式：点候选应该插到光标处、独占一行、能撤销； 候选列表应该由搜索框过滤，不该由草稿过滤。

对应改动：搜索与草稿解耦 · 光标插入 · Ctrl+Z · 行号按需

02发给谁

答案必须在发送之前就看得见，而且是主机名不是字母。字母是内部编号， 用户脑子里记的是 web-01 / db-02。

对应改动：悬浮卡列出真实主机名 · 菜单里可逐个勾主机 · 断开的机器标出来

03安不安全

两个独立的危险源：命令危险（rm -rf）和语义危险（多行会被当续行吃掉）。 现在只识别前者，而且识别了也拦不住。

对应改动：两步确认（Ctrl+Enter 同路径）· 多行语义检测 + 粘贴模式切换

04落没落

发送是一对多的，回执也必须是一对多的。一个「已发送」把 20 台压成一句话， 等于告诉用户「别问了」。

对应改动：悬浮卡里逐台回执（失败优先）· 常驻到下次编辑 · 失败可单独重试

为什么四件事都挂在「发送范围」这一个键上：因为它们是同一条时间线上的四个瞬间 —— 写的时候在这里看目标，发之前在这里核对，发之后在这里看结果。 用户要核对时鼠标本来就要移到这个键上，不需要额外去别处找信息。 现在版本里那条 28px 的「危险告警预留槽」是反面教材：它只在危险时才有内容， 却永远占着高度，平时就是一条空白 —— 而且它位于代码和发送键之间，用户看不到它时也想不到它存在。
（修订）常驻信息行后来也被删掉了。最初设想是在页脚加一条常显的「发射条」， 但实际跑起来它是自我重复的：左边写「等 84 台」、右边又写「84 台 · 4 台已断开」， 同一份明细悬浮卡里还有一遍。于是整条删除，正文区多出 46px 高度。 结论：信息只在「用户正在看的地方」出现一次就够，常驻行往往是在替自己解决不存在的问题。

04八处改动，逐条说清「为什么」

① 搜索与草稿解耦 —— 一处改动救活整条主流程

这是本次性价比最高的一处。现在 filtering = (text != "")，草稿即是搜索词。 改成一个独立的搜索框（左栏顶部，28 高，field 底 + line-2 边，聚焦转 accent： 与命令管理弹框的搜索框同一套），草稿再怎么长都不影响候选。

顺带解决三件事：
① 「连发第二条」这条路通了 —— 点完第一条，其余条目还在原地；
② 历史不再只搜最后 8 条（搜索框走全量，列表懒滚）；
③ 草稿里已有大段脚本时，左栏依旧可用（现在的实现里这种状态下列表是空的）。

② 点候选 = 插入到光标处 + 独占一行 + 可撤销

现在的 root.text = text + "\n" + cmd 是无条件追加到末尾。改成： 读编辑器选区 → 在光标处插入 → 若光标两侧不在行首/行尾则自动补换行（新命令独占一行，不把上一行截断）→ 光标落到插入内容之后 → 焦点留在编辑器。再配 Ctrl+Z。

③ 目标可见：悬浮卡里的真实主机名

这需要动数据，不只是画法：SendScope 结构要从 { letter, color, count } 扩成带主机列表（或另开一个 [SendTarget] 模型，由 Rust 按「已打开且 kind == terminal」的标签页现算）。 悬浮卡里逐台列出：频道色点 + 用户@主机名 + 频道/在线状态，超过 8 台收成「…还有 N 台」。 断开的机器用虚线边 + 降透明度 —— 明确告诉你「这台也会算进目标，但大概率发不到」。

④ 危险：真正的两步确认，且 Ctrl+Enter 无法绕过

现在 send-now() 无条件调用 root.send()，危险态只改了文案和底色。 改成共享一个 armed 状态：

  • 危险命中（阶段 1） → 按钮变实心红，但文案仍是「发送」。 红色本身就是「这条命令危险」的信号，不改变点击语义；
  • 第一次触发（点击或 Ctrl+Enter）→ armed = true，不发送， 文案才变成「⚠ 再点一次确认」，3 秒后自动解除；
  • 第二次触发 → 真正发送。改任何一个字符 → armed 立即归零，回到阶段 1；
  • 键盘与鼠标走同一个函数，物理上不存在「绕过」这条路。
为什么「阶段 1」必须还是「发送」：早先的写法是危险一命中就把按钮改成「再点一次确认」—— 等于把第一次点击这个动作从界面上抹掉了，用户第一眼看到的是个「已经要确认」的按钮， 只会困惑「怎么一上来就要确认」。两段式的关键是：红色负责警告，文案负责语义， 两者不抢同一件事。

同时把危险词表从写死的 8 个 token 换成单一出处（现在 send_cmd_window.slint:106-120 和 terminal_view.slint:1112-1130 是两份，注释自己都承认「被抄了第三遍」），并先剥掉引号内容再匹配， 这样 grep shutdown app.log 不再误报。

⑤ 多行语义：把「会出事的那个」显式化

这是最容易被忽略、后果最重的一条。现在多行文本被 trim_end() 后原样写进 PTY 再加一个 \n。 普通多行命令能跑，但下面三种情况会静默出错：

会被远端吃成续行

  • 引号未闭合：echo "deploy
  • 块结构：for / while / if / case
  • here-doc：cat <<EOF

表现：远端停在 > 提示符，后续行全部被吞，界面无感。

提案：两个显式模式

  • 逐行执行（默认）：每行各自回车，等于人工逐行敲；
  • 整段粘贴：用 bracketed paste 包裹（\e[200~ … \e[201~）， for / heredoc / 未闭合引号才安全。

检测到续行风险时自动切到「整段粘贴」，并在悬浮卡首行说明原因。

还需要一起修的三处：trim_end() 会削掉末尾反斜杠（破坏 \ 续行）； 第二行起在 sudo 场景会被当密码喂进去，应在多行 + sudo 时提示； 超宽命令行现在既不可见也不可横向平移（wrap: no-wrap + content-width: self.visible-width + 两条滚动条 always-off），编辑器要开横向滚动。

⑥ 回执：悬浮卡里的逐台结果

发送后悬浮卡的标题从 将发往 变成 结果，内容换成逐台结果； 每台主机 chip 从灰色变成绿（成功）/ 红（失败 + 原因）/ 黄（超时）； 右侧汇总 4 台 · 3 成功 · 1 失败；失败的可单独「重试」。 回执常驻到下一次编辑（不是 1.4 秒就消失）。

这需要 on_send 从「无返回值」变成「返回每目标的投递结果」。 send_raw 现在 let _ = commands.send(...) 把错误吞掉了， 至少要拿到「该 tab 的 handle 是否存在 / 通道是否还活着」这两个事实。 这是本方案里唯一必须改 Rust 侧语义的一条，也是最能提升信任感的一条。

⑦ 布局：760 宽、左栏收窄到 196、可折叠、行号按需

现为 620×420（最小 520×340），左栏固定 224 —— 最小宽度下占 43%。提案：

  • 默认 760×500，最小 620×420；
  • 左栏 224 → 最终 196：左栏放的是「名称 + 命令串」两行，命令串本来就靠省略号收尾， 收窄只牺牲几个字符，却把宽度让给了真正要写字的编辑区。代价用悬浮卡补（见 §08 ②）；
  • ⚠️ 收窄必须配 min-width:0：只写 flex:0 0 196px 是无效的 —— flex 子项的 min-width 默认是 auto（= 内容最小宽）， 左栏里那条 mysqldump ... > /backup/app-$(date +%F).sql 会把 min-content 撑到 416px，实测 side:416 / main:342，右栏被挤掉一半。 现在 .side 上 width/min-width/max-width 三值都钉死 196， 并在 .list / .row / .row .n,.c 上补 min-width:0 让省略号真正生效。 实测结果：side:196 / main:562 / 编辑器 302→522px；
  • 左栏宽度可拖（本轮新增）：默认 196，拖动两栏之间的分隔条可在 150 ~ min(420, 窗口宽×0.55) 之间调整。双击复位 196； 键盘 ←/→ 步进 16px、Shift 加速到 64px、Home 复位。 命中区 7px（1px 的线根本点不中），视觉仍是 1px 发丝线，悬停才出胶囊手柄；
  • 左栏可折叠：标题栏按钮，图标复用主界面左上角 BrandLogoBtn 的同款 SVG （assets/icons/sidebar-left-collapse.svg / sidebar-left-expand.svg，24 网格、stroke-width 2、16px 渲染）， 悬停出「收起/展开侧边栏」提示；窗口宽 < 700 时自动折叠；
  • 行号列：按实际行数动态生成（不再写死 30 行），且单行时整列隐藏；
  • 编辑器开横向滚动，超宽命令行可平移核对。

⑧ 草稿、焦点与 Esc 的分层

现在的 is_visible() 分支会把命令栏 ↗ 带进来的草稿静默丢掉；关闭窗口 = hide()， 草稿随之消失；Esc 只在编辑器持焦时有效。提案：

  • 窗口开着时再从命令栏 ↗ 打开：替换草稿但给 3 秒「撤销」（不弹确认框，弹框更烦）；
  • 关闭（hide）保留草稿，下次打开恢复；只有发送成功或手动清空才丢；
  • Esc 分层：菜单开着 → 只收菜单；否则关窗口（草稿已保留，不再需要「确认丢弃」）；
  • 键盘处理提到窗口根节点（不再只挂在编辑器上），范围键 / 发送键进焦点链并补 accessible-role / accessible-label（现在全窗口 0 处）。

05键盘契约：只保留真正需要的三个

按反馈收敛：这个窗口不以键盘操作为主，搜索框里那枚 Ctrl K 提示和对应的快捷键一并删除 （不再教用户按快捷键，一切靠鼠标点得到）。只留三个「没有就真的会出事」的键 —— 少而确定，比列满一张表更像一个桌面工具。

按键作用域行为
Ctrl+Enter全窗口发送。危险态下第一次只 arm，第二次才真发 —— 与点击完全同一路径。
Esc全窗口（分层）菜单开着 → 收菜单；否则关窗口并保留草稿。
Ctrl+Z编辑器撤销。点左栏插入的那一次必须能退回去（这是唯一必须有的编辑键）。
Ctrl+A / C / V编辑器系统级文本编辑，由原生输入框自带，不需要自己实现。
删掉的那些为什么不遗憾：Ctrl+K（聚焦搜索）、Ctrl+B（折叠左栏）这两个键的价值 在于「省一次鼠标移动」；而本窗口的搜索框和折叠键本来就在最显眼的位置，鼠标一步就到。 为它们维护快捷键、还必须在界面上教育用户，成本高于收益 —— 用户的原话是「不需要快捷键操作」。

07第二轮五条反馈：逐条落地

这五条都来自实际看稿后的直觉判断，每一条背后其实都有一个具体的失效场景。 下面不但给出改法，也交代「为什么原来那样不行」。

①折叠图标：用主界面同款

原来手绘了一个 16 网格的方框图标，几何随意、描边权重和标题栏其它图标不一致。

改法：直接引用 assets/icons/sidebar-left-collapse.svg 与 sidebar-left-expand.svg —— 就是主界面左上角 BrandLogoBtn 悬停时 淡入的那两个图标（24 网格、stroke-width 2、stroke-linecap/linejoin: round）。 收起时用 collapse，展开时用 expand，连同「收起/展开侧边栏」的提示文案一起搬。

②左栏收窄 + 命令悬浮卡

224px 的左栏要放「名称 + 命令串」两行，长命令全靠省略号；而右边真正写字的区域被挤。

改法：收窄到 196px（让出的 28px 全部给编辑区）， 同时补一张悬浮卡：鼠标停在被截断的行上 → 弹完整命令（等宽、pre-wrap、可读多行）， 并注明「点击插入到光标处 · 独占一行」。

只有真的被截断才弹 —— 没截断就弹卡是噪音。

③删掉搜索框里的快捷键提示

搜索框右侧原本挂了一枚 Ctrl K 键帽，还配了 Ctrl+K / Ctrl+B 两个全局快捷键与一张键盘契约表。

改法：键帽、快捷键、教学文案、契约表里的对应行全部删除。 搜索框和折叠键都在最显眼的位置，鼠标一步就到 —— 为省这一次移动去维护快捷键并教育用户， 成本高于收益。空态引导也一并改成「讲鼠标能做什么」。

④「将发往」机器很多怎么办

原稿把每台机器画成一枚 chip。84 台就是一整屏 chip，既放不下也读不完 —— 这是「把明细当摘要用」的典型错位。

改法：这一行改成一句话摘要： web-01、db-02、cache-03 等 84 台 + 右侧汇总 84 台 · 3 台已断开。 首三台给「身份」，数量给「规模」。要明细就悬浮：信息区展开逐台气泡（最多 60 行 + 「还有 N 台」）。

⑤ 范围键移到左下角，与发送键同行；信息行删除

范围键从「独占一整条发射条的右侧」移到页脚左下角、与发送键同一行， 视线不用再上下跳两次才能完成「看发给谁 → 点发送」。

并且按反馈把中间那条「信息行」整条删掉：状态、告警、回执摘要全部收进范围键的悬浮提示卡。 页脚因此从「三区」简化成「两个控件 + 一句极简助记」，不再有一条常年显示「就绪」之类废话的常驻行。

页脚布局 · 简化后（1:1）
2 个频道3 危险 · 需二次确认 再点一次确认
← 范围（悬停出提示卡） 极简助记（可空） 发送 →
为什么状态搬进「范围键」的悬浮卡而不是别处：要回答的三个问题——发给谁、安不安全、落没落—— 全部围绕这一个键展开：它是选目标的键，所以「目标是哪几台」最该长在它身上。 用户要核对时，鼠标本来就要移到这个键上；不需要额外去别处找信息。 这也顺带解决了原来那条 28px 危险告警槽的失败原因：它在，但用户想不起来看。
提示卡三种形态，同一张卡：常态（逐台主机名 + 频道 + 在线状态）、 危险态（红描边 + 警告行 + 「再点一次才真正发送」）、回执态（失败优先排序 + 成功/失败汇总）。 机器多时只列前 8 台 + 「…还有 N 台」，卡片自身限高 320px 可滚动。
实现要点（给落地的人）：提示卡用 position:fixed 挂到 body， 不要放进 .foot 里向上弹 —— .body/.side/.main 层层是 flex + relative， 多个层叠上下文叠加，卡放在里面无论怎么调 z-index 都会被左栏列表文字盖住（两轮截图 + 涂绿诊断实证）。 这是本稿唯一一处「看起来能靠 z-index 解决、实际不行」的坑。

08第三轮两条：点开菜单时收起提示卡 · 左栏宽度真 bug

①点击时不要再弹提示卡

提示卡本来是给「没点开菜单时」用的：鼠标划过范围键，先看一眼将发往哪几台。 但点开菜单后，菜单本身已经把目标、频道、台数全列出来了， 再压一张卡上去就是纯遮挡（截图里卡正好盖住「web-01 / db-02」那几行）。

改法：showTipCard() 开头加一道 if (S.menuOpen) return； 点击范围键 / 点菜单项 / 点「完成」/ 点外部关菜单，四处都调 hideTipCard()。 鼠标仍停在按钮上时，由 mousemove 在菜单关掉后把卡唤回 —— 不会「划走再划回来」才有。

②左栏太宽 —— 是 flex 的 min-width 陷阱

上一轮把左栏从 232 改到 196，但实际渲染出来是 416px，右栏只剩 342。 用户看到的是「左侧命令栏有些宽，右侧输入框有些小」。

根因：flex 子项的 min-width 默认 auto， 等于内容的最小宽度。左栏里那条 mysqldump --single-transaction app > /backup/app-$(date +%F).sql 把 min-content 顶到 416px —— flex:0 0 196px 的 basis 形同虚设。

改法：.side 三值钉死（width/min-width/max-width 全 196）， 并给 .list / .row / .row .n,.c 补 min-width:0， 让省略号真正生效。实测 side 416→196、编辑器 302→522px（+73%）。

这条 bug 值得记住，因为它「看起来已经改过了」：上一轮的 changelog 里明明白白写着 「左栏 232 → 196」，代码里也确实是 flex:0 0 196px —— 但渲染结果完全没变。 这类问题只读代码看不出来，必须实测 getBoundingClientRect()。 本轮是先用无头浏览器量出 side:416 / main:342 才定位的， 改完再量一次 side:196 / main:562 作为验收 —— 不靠「改完看一眼觉得对了」。

09把那条常驻信息行整条删掉

截图里那一行是 将发往 ●●● web-01、web-02、web-03 等 84 台  |  84 台 · 4 台已断开。 看着挺有用，实际上它在自己重复自己，而且三处都在说同一件事。

问题三重冗余

  • 行内自重复：左边已经写了「等 84 台」，右边又写「84 台 · 4 台已断开」—— 同一个数字在一行里出现两次。
  • 与悬浮卡重复：逐台主机名、频道、在线状态，左下角那张卡里全都有，而且更完整。
  • 占着高度不说话：常态下它就是 46px 高的一行字，为了偶尔看一眼让正文区永久矮一截。

改法整条删除

删掉这一行后，页脚直接贴到正文下方：正文区多出 46px（实测 body: 352 → 398）。

目标信息全部由左下角「发送范围」键承担： 键本身显示当前范围（全部标签页 84），悬停出提示卡看逐台明细。 页脚右侧只保留一句极简助记（多数时候是空的），比如「1 台失败 · 悬停左下角看明细」。

结论：信息只在用户正在看的地方出现一次就够。

删除时踩了一个坑，值得记下来：发射条那段 CSS 和 .tip（标题栏悬浮提示）、 .tipcard（范围键提示卡）、.foot-note 在文件里是相邻的， 整块切掉时把它们一起带走了。表现是： ①「收起侧边栏」六个字竖排、常显糊在标题栏里（.tip 丢了 position:absolute， span 退回行内流被挤成一列字）；② 提示卡完全不显示（.tipcard 无样式）。 教训：删除功能块前，先确认 CSS 块的边界——共享基础样式（.tip）不能跟着功能一起删。 两处现已恢复，并在各自规则上方留了注释。

10本轮：补上三个「文档说过、原型却没做」的交互

这一轮不是加新点子，而是把前面几轮自己写下的承诺补齐。 文档里早就写了「续行风险自动切整段粘贴」「失败可单独重试」「发送成功或手动清空才丢草稿」—— 但可交互原型里一个都没有。说到做不到，比不说更糟。

①多行命令：逐行 vs 整段粘贴

同样一段多行文本，两种写进 PTY 的方式后果完全不同：

  • 逐行回车：每行各自 Enter，等于人工逐行敲；
  • 整段粘贴：bracketed paste 包裹后补一次回车。

一个没写完的块（例如只有 if … then 没有 fi）， 逐行敲会一直卡在续行提示符上。所以检测到风险时自动切整段粘贴， 并在信息区说明原因；用户仍可点胶囊切回去 —— 此时胶囊变红、标「有风险」。

⚠️ 注意：完整的 for…do…done 不算风险 —— 它是闭合的，逐行敲本来就能用。 只有「没写完」才需要兜。

②失败项一键重试

回执里有失败时，信息区出现「重试这 N 台」。点击后：

  • 目标范围收窄到刚才没收到的那几台（范围键同步变成「N 台主机」）；
  • 回执清掉，草稿保留；
  • 不自动发送 —— 发送是对多台机器的动作，多给一次确认比省一次点击重要。

早先只在卡片里写「可重连后单独重发」，但没有入口 —— 用户得自己去菜单里一台台勾。

③发送后「清空」

发完之后草稿留着（方便「再发一次」），但要写下一条命令时， 原本只能全选 + 删除。

现在回执态信息区直接给「清空」：草稿、回执、armed、送达方式覆盖 一起复位，焦点回到编辑器。

它和「再发一次」是一对：要么重复，要么重写，两条路都只要一次点击。

第四条小改动：提示卡标出「当前标签页」。 目标列表有 84 台时所有行长得一样，不标当前位置等于让人自己找。 现在当前那一台的行尾显示 频道 A · 当前（强调色），一眼能定位「我在哪」。 只加一个词，不新增任何控件。
写这轮时抓到的真问题：同一句风险提示，在两种模式下含义相反。 原来的逻辑只要检测到风险就写「远端会当成续行」—— 可一旦自动切到整段粘贴， 这句话就是错的：整段粘贴恰恰不会当成续行。 结果界面在「已经帮你兜住了」的同时还在吓你。改成分支： block → 「已自动改整段粘贴」（琥珀色提示）， line → 「逐行回车会卡在续行提示符」（红色警告）。
两条没有做的想法，以及为什么。
① 左栏键盘上下选、回车插入 —— 用户明确说过「不需要快捷键操作」， 列表本身用鼠标点已经足够，加键盘导航属于自作主张。
② 在提示卡里直接勾选/取消单台主机 —— 范围菜单里已经有「逐个挑选主机」， 再做一套等于同一件事两个入口，状态还要互相同步，只会更容易出错。 卡片现在的职责很清楚：看清单 + 复制，不抢菜单的活。

11危险命令的发送键改成两段式

用户指出的问题很具体：危险命令一出现，按钮就已经是「再点一次确认」了 —— 等于把第一次点击这个动作从界面上抹掉了。正确的时间线应该是 「发送」→ 点一次（只警告）→「再点一次确认」→ 点第二次（真发）。

阶段 1刚命中危险

按钮变实心红，但文案仍是「发送」。

红色是「这条命令危险」的信号，但不改变点击语义 —— 用户以为自己点的是普通发送，实际只触发警告。

信息区同时说明「检测到 rm -rf · 将发往 3 台」。

阶段 2点过一次之后

文案才变成 「⚠ 再点一次确认」，图标出现。

这一下真的发出去。3 秒内没有第二次动作 → 自动退回阶段 1； 改任何一个字符 → 也退回阶段 1。

Ctrl+Enter 与鼠标点击走同一个函数，无法绕过。

设计原则：红色负责警告，文案负责语义。两者不该抢同一件事 —— 早先那版让红色和文案同时表达「危险」，结果文案把「还没点过」这个事实吞掉了。 现在的分工是：颜色说「注意」，文字说「现在点会发生什么」。
验证时踩到一个陷阱：截图看不到红色。 按钮有 transition:.11s，而 headless 截图会把过渡的计算值 冻在起点 —— 实测危险态按钮本该是 #DC4B44， 截出来却永远是 #1FC8B4（暗色主题的强调色）。 一度误判成「红色没生效」，逐一排查了类名、CSS 变量、规则优先级都不对， 最后注入 transition:none 后重测得到 rgb(220,75,68) 才确认样式本身是好的。 结论：截图验证前先关动效，否则量到的是中间态。

12上一轮：两栏之间那条竖线可以拖了

用户要求「这个竖线支持拖动」。左栏宽度从写死的 196 改成可调 —— 命令名长短因人而异，固定宽度对谁都只合适一半。

①三个入口，同一套钳制

  • 鼠标拖动：拿住分隔条左右拖，实时跟手；
  • 双击：复位到 196（拖歪了不用猜原值）；
  • 键盘：←/→ 步进 16px，Shift 加速 64px，Home 复位。

范围：150 ~ min(420, 窗口宽×0.55)。 下限保证搜索框和命令名不折行；上限保证编辑区永远拿到一半以上。

②线看不见，手柄才看得见

1px 的发丝线没人点得中，所以命中区放到 7px（透明，不影响观感）。

悬停时露出胶囊手柄（4×40，强调色，带一圈 panel 色描边把它从列表文字上「抠」出来）+ 竖线转强调色 —— 手柄才是「这里能拖」的信号，光标也同步变成 col-resize。

首版手柄做的 3×26 且无描边，截图里几乎看不见，已加粗加深。

踩到的坑：窗口宽度取 0 时，拖动会「拖不动」。 上限算法是 min(420, 窗口宽×0.55)。如果 #win 还没布局 （首帧 / 离屏渲染 / 测试环境），宽度读到 0 → 上限算成 0 → 再被 max(150, …) 兜成 150 → 它和下限相等，调用方传什么都被钳到 150，表现为「拖了没反应」。 修法：宽度无效时上限直接退回 420，不要拿 0 去算。 这个 bug 在真实浏览器里很难撞到（窗口总是有宽度），但测试环境一撞一个准 —— 也正因为它，最初的拖动断言全红，反而把问题提前暴露了。
两个实现细节： ① 拖动时在 document 上监听 mousemove，不是挂在分隔条上 —— 指针拖快了会离开那 7px 宽的条，挂在条上会中途丢事件； ② 写宽度时要同时写 flex-basis / width / min-width / max-width 四个值， 只写其中一个会被其余几个夹住（这正是「改了 196 却渲染 416」的同一个坑）。

13信息区做成状态区，提示卡做成能操作的

两条反馈指向同一件事：信息现在只能「看」，不能「用」。 一是页脚中间那块只能显示一行灰字，二是悬浮提示卡是 pointer-events:none 的 —— 鼠标一碰就消失，想复制个主机名都做不到。

①信息区 = 状态区，不是灰字行

用户要求「两个按钮之间都是展示信息的地方」。所以这块升级成 图标 + 状态 + 可点动作三件套，四种状态各有自己的图标与颜色。

关键取舍：信息区说「将要发生什么」，发送键说「你要做什么」。 危险态下按钮已经写着「再点一次确认」，信息区就不该再写一遍 「危险 · 需二次确认」—— 同一句话说两遍就是白占位置。 改后信息区给的是：命中了什么 · 将发往几台 · 有几台断了。

「台数」和「断开台数」是两个事实， 早先写成 if(offN) 只报断线数，把「将发往几台」挤没了；现在两者同行并存。

②提示卡可交互：移进去不消失、能操作

移进去不消失：原来离开按钮就立刻收。改成延迟 260ms 收起， 卡片 mouseenter 取消这次延迟 —— 指针从按钮划到卡片的那 8px 空隙来得及走完。

进了卡片就粘住：指针一旦进过卡片（或在里面点过任何东西）， 卡片不再自动消失，只有关闭 / Esc / 点空白才收。 早先这里做的是一个「钉住」按钮，后来删了 —— 原因见下方。

能操作：pointer-events:auto 之后，卡片里可以： 复制名单（每行一台，带频道与在线状态）、复制结果、 点单台主机名复制它。

删掉的两种「帮倒忙」文案（都是我自己加的，后来判断是纯噪音）：
① 「点击选择发送范围（当前页 / 全部 / 频道 / 逐个挑）。」 —— 范围键就在卡片正下方、还带个下拉箭头，这句话在教用户已经看得懂的东西。 现在改成：只有真有断开主机时才出一句「N 台已断开，发送时会跳过」，其余情况那行留白。
② 「点主机名可复制 · 单击主机名不会改变目标」 —— 前半句是操作提示，但主机行本身悬停就有反馈；后半句在解释一个不存在的问题 （本来就没有「点主机名会选中它」这个功能）。
③ 另有一个 「钉住 / 已钉住」按钮：它要求用户先理解一个概念、再点一下， 而「延迟收起 + 移入保持」已经解决了同一件事。删掉后改成自动粘住 —— 用户伸手进来操作本身就是「我要看」的信号，不必再确认一次。
做这一轮时挖出一个隐蔽 bug：淡入动画让卡片背景变半透明。 transition:opacity 是整层一起变透明 —— 过渡期间卡片自己的背景也是半透明的， 底下的列表文字整片透上来。深色主题下几乎看不出来（卡片底色和面板底色都接近）， 浅色主题下一眼就露馅（截图实证）。 改法：只过渡 transform，不过渡 opacity，显隐用 visibility 离散切换 —— 卡片一出现就是完全不透明的。改完实测 getComputedStyle().opacity = 1。
还有一个真 bug：复制结果用错了转义。 文件里写的是 join("\\n") —— 在 JS 里这是「反斜杠 + n」两个字符， 不是换行，复制出来会挤成一行。改成 join("\n")。 这类错肉眼极难发现（要真的复制出来粘到别处才看得出）， 所以补了一条断言：targetListText 不得含字面量 \\n。

14上一轮：一个漏调用导致按钮名称不跟随

同期还有一处布局取舍（删掉那条常驻信息行，已并入 §09）， 以及一个真 bug —— 而且是被这一版原型自己暴露出来的。

A按钮名称没跟着选择变

选择「全部标签页 / 频道 A / 自选主机」后，左下角按钮仍显示「当前标签页」。

根因：render() 里调了 renderList / renderMenu / renderFoot， 唯独漏了 renderScope()。它只在菜单开关那两处被调到， 所以标签只在「点开菜单」的瞬间才刷新，选完反而停在旧值。

改法：① 把 renderScope() 补进 render()； ② 把 5 种状态的文案统一收进一个 scopeLabel() 纯函数，杜绝「各处自己拼文案」； ③ 加回归断言：6 种选择逐一切换，必须渲染出对应文案。

B同一轮的连带修正

把范围键移到页脚左下角、删掉常驻信息行之后，状态的唯一去处就成了左下角那张提示卡 —— 于是「点开菜单时不要弹卡」「卡片要能移进去操作」这两条都必须满足（见 §10）。

教训：删掉一个常驻区域之前， 先确认它的信息已经搬到了别处，否则就是直接丢信息。

这个 bug 值得单独说，因为它有典型性：五个渲染函数排成一排，漏掉第六个 —— 这种错不会报错、不会崩，只是某个区域「偶尔不更新」。人工点几下很容易刚好错过 （只在「不打开菜单直接改状态」的路径上复现）。所以本轮补了 6 条标签断言， 而不是改完看一眼就算数。
