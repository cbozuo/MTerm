新建会话 · 高级区四个控件的交互方案

位置：新建会话弹框「显示高级选项」展开后的第二段（session_dialog.slint:2421-2549）， 截图标注的四项 = 终端字符集 ▾、启用 VT100 线框绘制 ☐、跳板机 ▾、禁用 shell 集成 ☐。本页只出方案，未改任何代码。

现状诊断（4 条）

①hint 被裁 / 被下块压住
两段 wrap: word-wrap 的 hint 只拿到 1 行高度
 现象：凡是需要两行的 wrap: word-wrap 文本都只拿到 1 行高度，第二行溢出后被 clip 裁掉（本弹框共 8 处 wrap 文本，只是前两处不在截图范围内）。
成因待定（两条都可能）：① content-height: body.preferred-height 查询时子项宽度尚未确定，wrap 文本按 1 行计入；② 布局给该 Text 的高度就是 1 行。
修法对两条都成立：给这几段 hint 显式两行高度（height: 32px），不依赖测量 —— 本方案按此处理。
②「禁用 shell 集成」归属错位
信息所有权问题，不是视觉问题
 它描述的是目标服务器的 shell 行为，却紧跟在「跳板机 ▾」下面，读起来像"关于跳板机的选项"。这是四个控件里唯一真正的语义错误。
③例外关系没有表达 字符集 = UTF-8 时 VT100 本就自动生效，复选框是例外开关；但它与下拉平级同缩进，读者要靠文案自己推断这层关系。
④排版不一致 启用 VT100 线框绘制（即使 UTF-8 模式）用全角括号，禁用 shell 集成(Windows / pwsh 服务端)用半角括号且无空格。两处 checkbox 代码是复制粘贴的重复块（18×18 / 圆角 5px / Icon check / TouchArea），改一处漏一处的风险已存在。
控件本身（38px 高、9px 圆角、chevron 14px、复选框 18×18）与弹框内其它字段完全一致，这部分不需要动。

方案 A · 顺序 + 缩进修正归属（推荐）

不动控件、不加分组标题，只做两件事：① 把「禁用 shell 集成」从跳板机下面挪到字符集这一段的末尾、与 VT100 左对齐同缩进 —— 不缩进本身就是"它不属于任何下拉"的信号； ② VT100 缩进 18px 并加 1px 竖线，明确它是字符集的例外分支。 跳板机因此成为干净的独立字段（只有 ▾ + hint），不再挂着别人的开关。

交互规格（本轮按反馈补充）

下面两组行为已落地（#drop-focus-decoupled / #checkfield-row）。 原实现把「聚焦态」绑在弹层开闭上（drop-open && 代际时钟），于是"点开→再点收起"后蓝框跟着弹层一起消失； 复选框的 TouchArea 只盖 18px 方框，点文字没反应。两处都已改为与弹层解耦。

方案 B · 把 VT100 并进字符集枚举

「UTF-8 时 VT100 自动生效、手动勾选只是例外」——既然如此，例外本身就可以是枚举里的一项：UTF-8 / UTF-8 + VT100 / GBK / … 少一个控件、少一段 hint，"例外"概念消失。代价：选中 GBK 时这一项语义上无意义，得把它灰掉，而 SelectField 目前没有"单项禁用"能力，要先给组件加 enabled 数组。

方案 C · 分组卡片 + 可见标题

最直白：把四项装进两张带标题的卡（终端行为 / 连接路由），从属关系由卡片承载。代价是给扁平风格引入了新的视觉层级 —— 弹框其它部分（标识 / 连到哪 / 认证 / 代理 / 端口转发）都没有可见分组标题，只有这一段有标题会显得突兀。

推荐 A 的四条理由

① 它是唯一不动控件的方案 —— 四个控件的尺寸/圆角/配色已与弹框其它字段完全一致，无需回归验证；
② 它修的是真语义错误（② 归属错位），不是把问题挪个位置；B 也修对了，但代价是改公共组件；
③ "不缩进"是零成本的从属表达：不需要新组件、不需要新 token，也不需要给弹框引入分组标题；
④ 顺带清掉复制粘贴：两个复选框块抽成一个 CheckField 组件后，④ 的括号不一致与"改一处漏一处"的风险一并消失（纯实现层，界面无变化）。
