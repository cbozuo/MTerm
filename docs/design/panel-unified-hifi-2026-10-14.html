1为什么去掉 Rail、面板贴边框

  • 原方案 4 个面板各自可 dock 四边（welcome / sidebar / quick / sftp），组合爆炸、学习成本高；图标栏再多一跳。
  • 新结构只有两个锚点：左侧台（会话/文件/命令/隧道四合一）+ 右监控，直接贴窗口左右边框（1px 分隔线，无 gutter 圆角），与窗口浑然一体。
  • 收起即 36px 贴边窄条（沿用代码 sidebar-collapsed: 36px），只剩一颗展开钮，主区域自动让宽。
  • 几何延续：侧台宽 300（welcome-size 280~480 区间）、监控宽 320、标题栏 44、TabBar 36。

2会话与 SFTP 同面板 · 监控重设计

  • 左台顶部 tab 条 = 统一入口：会话 / 文件 / 命令 / 隧道，Ctrl+1..4 直达；SFTP 的树、列表、传输队列、多选、列设置整体搬入，主区域 100% 归终端与分屏。
  • 监控从"静态堆叠进度条"改为仪表盘：CPU / 内存环形仪表 + Swap 附条、网络双曲线（网卡切换）、磁盘分段条、Top5 进程内嵌。
  • 数据链路不变：仍读 cpu-percent / net-*-history / disks 等现有属性，ProcWindow / SystemInfoWindow 保留为深挖入口。

3拖拽分组 · 其他整合

  • 试试拖动左台「文件」tab：拖到右侧监控 → 组成「监控 | 文件」标签组；拖到中央 → 成为主区域标签；拖回左台 → 还原。监控 tab 同样可拖出。
  • 整合清单：快捷命令+片段（原 quick panel）、SSH 隧道+端口转发（原 sftp tunnels tab）、传输队列（原顶栏弹层）、导入 SSH config、本地终端入口。
  • 保持不变：主区域 TabBar / 分屏 / 频道 A-D / 同步输入、独立窗口（进程、系统信息、编辑器）、主题三层体系。
