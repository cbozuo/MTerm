分组管理 · 从「逐条右键」到「一屏总控」

现状把分组的六件事全塞进组头右键菜单：新建、改名、改色、删除、排序、成员归属。每件事都成立，但没有一个地方能同时看到「有哪些组、每组几个人、谁在哪个组」。本稿把它们收进一个 760×522 的双栏弹框：左栏管组（拖排序 / 就地改名 / 就地改色 / 删除），右栏管这个组的人（刷选 / 批量移动 / 移出）。两栏之间还有一条手势通道：把成员拖到左栏任一分组即换组，拖到成员之间即组内排序。不引入新的数据语义——全部落在既有 ConfigStore 的 groups / group_colors / session.group 上，组件可以直接长在现有回调上。

1
删除有成员的组，是死路「删除分组」受 ctx-menu-empty 门控，只有空组才显示。想让一个 6 人的组消失，得先把 6 个人一条条移走——而移人一次只能一条。
2
搬人一次一条，且每条都落盘on_move_session 每次 save() + sync_sessions_for_window + broadcast。批量搬 20 人 = 20 次写盘 + 20 次列表重建。
3
改名撞名，静默失败rename_group 返回 ()，重名直接 return。用户在 362px 单组弹框里点「确定」，弹框关了、名字没变、没有任何提示。
4
组序只能拖，且要滚到两处排序靠拖组头；组多到要滚动时，源与目标不在同一屏，没有键盘替代（reorder-group 已支持任意 before 落点，缺的只是入口）。
就地不叠第二层弹框改名、改色、删除确认全部发生在列表行内／右栏顶部，不弹 362px 的小框再挡一次。
后果先看见再确认删除前直接写出「6 个会话移到 [未分组]」；改名撞名当场红框，不等提交。
即时没有确定 / 取消底层每次改动都落盘，底部只写「改动已自动保存」。代价是没有撤销——所以危险动作必须把后果写在动手之前（删除条），而不是事后兜底。

保留原有的轻量路径（新建分组 / 重命名 / 分组颜色仍可单点直达），只新增一个收口入口。空白处右键同样可达，避免「必须先找到一个组头」。

SPEC尺寸与令牌

全部换算自 ui/theme.slint：fs-lg 15px / fs-sm 13px / fs-xs 11px / radius-md 6px / radius-lg 10px。行高取 36/38px（比侧栏 32px 大一档），因为弹框里每行都是可点击目标，需要更大的命中区。

区域尺寸说明
弹框760 × 522 px
radius 10px		宽度 = 左栏 248 + 右栏 512。高度取 522 让右栏一屏放下 7 个成员行（38px）不滚动；超出滚动，不改变弹框高度（避免列表增删时弹框跳动）。
标题区56 px15px/700 标题 + 11.5px 统计副标题；右侧搜索 206×30；关闭按钮 28×28。
底部48 px左「改动已自动保存」11.5px；右「完成」28×70。中段键盘提示在窄窗口可隐藏。
左栏248 px底色 base-bg-root（比面板深一档）形成分区；组行 36px，圆角 6px，选中态 = accent 12% + 左 2px 竖条（呼应侧栏脊线语言）。
组行36 px
拖柄 12 / 色点 10 / 计数 17×15		拖柄只在 hover 显形（0.55 透明），「未分组」不显示拖柄且不可拖。选中行的铅笔 / 垃圾桶常显——否则「改个名」这件事只能靠猜。
成员行38 px两行文本：名称 12.5px（t1）+ host 10.5px mono（t3）。复选框 14px（命中区 22px），常态 62% 透明，hover / 选中升到 100%。整行不加手型光标——手型会让人以为行是按钮，而它实际是拖拽对象。
删除条自适应，约 62 px右栏顶部内嵌，danger 9% 底 + 42% 边；不叠第二个弹框。
批量条36 pxaccent 15% 底 + 30% 边，浮在成员列表底部（不占流）。若改成占位，刷选时列表会被整体推下 44px，指针下的行直接错位——连续手势里这个位移是致命的。列表恒定留 48px 底部内边距。
悬浮卡206–280 px 宽150 ms 首锚 + 跟手（+16）；标题 12.5px、字段行 11.5px（标签定宽 38px）、备注在分隔线后 11px。指针靠近右/下缘时翻转到左侧/上方。
拖拽浮层高 30 px
跟手 +14 / +14		鬼影（ghost）显示会话名 / 组名，多选时追加「N 项」药丸；尾注实时显示落点语义（「放到 生产环境」/「第 3 位」）。pointer-events:none，不遮挡命中。
插入线2 px + 两端 6 px 圆点组排序与成员排序共用同一视觉，绝对定位在滚动容器内（不插入占位元素，落点跳变时不会引起列表抖动）。

RULES交互规则

每条都对应一个具体实现落点。表中「代码」列是现有能力，标 NEW 的是本稿要求新增的。

动作触发行为与反馈代码
切组单击组行 / ↑↓ 右栏立即换成该组成员；清空当前多选；右栏滚动回顶部。切换不写盘，纯视图态。 gm-selected-group NEW
右栏标题点色点 / 双击组名 右栏顶部的色点就是改色入口（与左栏共用同一套色板），双击组名就地改名。两处编辑的是同一个字段，只是输入框长在不同位置。「未分组」的标题不可双击。 set-group-color / submit-group
成员悬浮卡悬停 150 ms 显示：名称（带在线点）、主机、用户、认证、分组、备注。跟手移动，超出弹框右/下缘自动翻转。拖拽与刷选期间不出现——手势中途弹卡会挡落点。 复用列表侧 hover-card
就地改名双击组名（左栏行 / 右栏标题）/ 铅笔 / F2 组名就地变输入框，原文全选（直接输入即覆盖）。在右栏标题上双击，输入框就长在标题位置，不会跳回左栏。Enter 或点任意空白都算确认（含点另一个组——确认后接着切过去），Esc 才是放弃，失焦也提交。四种离开方式里只有 Esc 反悔。撞名当场红框 + 红字（左栏在行下、右栏在标题右侧），不关闭、不清空。 submit-group(orig,name,hex)
改名预校验输入时实时 三条规则按序：① 空 → 不提交；② 与 default/system 忽略大小写相同 → 「系统保留名称」；③ 与其他组忽略大小写相同 → 「已存在同名分组」。必须先校验再做，因为 rename_group 撞名是静默 return，UI 无从得知失败。 Slint 侧 NEW
改色点色点（左栏行 / 右栏标题） 色板 5×2 + 「无颜色」，锚在色点右下，越界向上翻。选中即生效（不等待确认），两处色点同步换色。未分组同样可改色——代码里 set_group_color 只拒绝空名。 set-group-color(name,hex) NEW（现只有菜单注入路径）
拖成员换组按住成员行拖到左栏组行 行主体按下、位移 >5px 起拖；ghost 显示会话名（多选时带「N 项」药丸）。悬停目标组时该行 1.5px accent 内描边 + 底色高亮，ghost 尾注「放到 生产环境」。松手追加到目标组末尾。目标是自己所在组时不响应——那是下一条。 move-sessions(ids, group) NEW
拖成员排序按住成员行拖到成员之间 落点画 2px accent 插入线（两端圆点），ghost 尾注「第 3 位」。松手按原相对顺序插入，其余行相对次序不变。这是唯一能改「组内顺序」的手势——存储顺序就是显示顺序（无字母排序）。 move-session-relative(id,target,after) 已有单条
拖拽多选勾选多行后拖其中任意一行 拖动的是整个选中集：ghost 带「N 项」，所有被拖行同时 35% 透明。落点语义与单行一致——组行 = 整批搬过去；成员之间 = 整块插入。未勾选任何行时只拖当前行。 同上两条（批量）
刷选在复选框列按下并上下拖动 指针经过的成员行逐行勾选，不起 ghost、不动数据。从已勾选行起拖 = 逐行取消（反向刷选）。单击复选框仍是切单行。复选框命中区 22px（方块仍 14px），否则这列太窄按不住。 Slint 局部状态 + 行 y 区间命中
组排序拖组行 / Alt+↑↓ 被拖行 40% 透明，落点画同款插入线。未分组不可拖、也不接受投放（它只能收，不能被排序）。 reorder-group(group, before)
删除组垃圾桶 / Del 右栏顶部展开删除条：标题带组名 + 成员数，成员去向默认「未分组」，可改选任一组。点「删除分组」才执行。不再要求组为空；未分组无此入口。 delete-group + move-sessions NEW
删除后果执行删除 一次原子操作：成员迁移 + 组移除 + 颜色条目清理 + 折叠态清理 + 一次落盘。toast 只报结果「已删除「X」· 6 个会话移到 未分组」，不提供撤销——所以成员去向必须在删除条上先选好，这是唯一一道防线。 remove_group 已含颜色 / 折叠清理
多选点复选框 / 刷选 / 表头全选 只有复选框改变勾选。单击行不做任何事——行上的按下只用于起拖，所以拖一行绝不会顺手把它勾上（这是上一版最烦人的误触）。选中行底色 accent 8%、复选框实心；批量条浮出，右栏标题的「全选」变「已选 N / M · 取消」。 Slint 局部状态
批量移动批量条「移动到」 下拉列出全部可投组（含「未分组」），当前组不列。执行后一次落盘、一次重建，选中自动清空。 move-sessions(ids, group) NEW
移出分组行尾「移出」/ 批量条 等价于移动到 default（存储写空串）。单行移出后该行从列表移除并淡出 120ms，不重新排序整表。 move-session(id,"default")
新建组左栏底部按钮 在列表末尾插入一个编辑态行（无组色、计数 0），直接可输入。空名失焦 = 放弃，不产生空组。 submit-group("",name,"")
搜索标题区输入 组名命中 → 只留该组；成员命中 → 保留其组，右栏高亮命中行。无结果给「没有匹配的分组或会话」+ 清空。搜索期间禁用全部拖拽——过滤后的落点与存储位置不对应（与列表侧 #in-group-only 同一约定）。 复用 session_matches_normalized_query
空组— 右栏居中空态：图标 + 「内网 还没有会话」+ 一句可执行路径「到其他分组勾选会话，用「移动到」搬进来」。不提供无效的「添加」按钮。 —
拖动弹框按住标题区或任意空白拖动 位移 >3px 才起拖，3px 以内仍是点击（不会因为手抖把窗口挪走）。只改 translate、不重排布局；拖动中阴影抬升、临时去掉过渡以免拖影，并夹在应用窗口内。行、按钮、输入框、色板、删除条、批量条上的按下不触发窗口拖动——它们各自有手势。 Scrim 下的空白 TouchArea（与其它弹框同一套）
关闭完成 / Esc / 点遮罩 直接关。没有「有未保存修改」的拦截——所有改动早已落盘。正在编辑的输入框：Esc 先取消这次编辑，再按才关窗；点遮罩则先提交再关（改名不会因为点了一下外面就丢）。 —

CODE落地映射

新增一个 ui/group_manager.slint，不改任何既有组件结构；Rust 侧三个新回调 + 一条批量排序，拖拽骨架直接沿用列表侧已有的那套。

层改动
组件ui/group_manager.slint：GroupManagerDialog（内置 Scrim）。输入两个 model：gm-groups（组行）与 gm-members（成员行，字段可复用 SessionInfo）。纯视图，不持有配置。
组行 modelstruct GroupRow { name, color, color-hex, count, kind, collapsed, reserved }。由 Rust 在 sync_sessions_for_window 同一处刷新，保证弹框与左栏列表同源同序。
回调（复用）submit-group（新建/改名，已有校验路径）、delete-group、move-session、reorder-group。
回调（新增） set-group-color(name, hex) —— 现有设色只能从右键菜单经 ctx-menu-group 注入，弹框需要直连版本。
move-sessions(ids: [string], group) —— 拖到组行 / 批量条，一次迁移 + 一次 save + 一次广播。
move-sessions-relative(ids: [string], target: string, after: bool) —— 组内排序。单条版 move_session_relative 已存在，批量版必须自建，否则拖 5 行就是 5 次重建（列表会跳 5 下）。
group-manager-open: bool + gm-selected: string 两个属性。
为什么必须批量on_move_session 每调一次都 save() + sync_sessions_for_window + broadcast_config_changed。在 UI 里循环调用 20 次 = 20 次写盘、20 次 set_vec 重建：左栏列表会肉眼可见地连闪 20 下，跨窗口还会触发 20 次广播。这是本稿唯一的硬性 Rust 改动。
删除原子性不要「先 move 再 remove」。中间态会让成员短暂出现在目标组而源组仍在（两次重建），且两次写盘之间崩溃会丢归属。remove_group_with_target(name, target) 在同一个 borrow_mut 里完成迁移 + 移除 + 清理 + 一次 save。
拖拽骨架不要新写一套 DnD。left_sidebar.slint 里已经有完整的指针模型可照搬：位移阈值起拖、ghost 跟手、drag-fly-home 松手飞回原槽、clamp-at-group-ends 越界钳制、drop-report 上报落点。唯一新增的是「跨容器」这一段——落点判定要从成员列表跨到左栏组行。
刷选命中Slint 没有 elementFromPoint，命中靠算：成员行固定 38px，index = floor((y - list-y + scroll-y) / 38) 即可，比 DOM 版更简单。刷选期间只改 picked 集合与行背景，不重建 model ——每经过一行重建一次列表会吞掉拖拽中的指针状态。
不做撤销已确认。删除组是唯一「一次影响多条会话」的动作，因此删除条上的去向选择是最后一道防线，文案必须写出具体数量与目标组名，不能用「确定删除吗？」这种无信息量的确认。

与既有 #41 单组弹框的关系

入口保留理由
右键 →「新建分组」新建一个组只需要一个名字，362px 弹框（含实时预览 + 色板）比打开 760px 管理台更快。管理台负责「建完之后」。
右键 →「重命名」同上。但管理台的内联改名更省一步，两处都可写，共用 submit-group 与同一套校验文案。
右键 →「分组颜色」色板已在菜单里，改单个组的颜色不需要开窗。
主入口「管理分组…」只在需要横向比较 / 批量搬运 / 删有成员的组 / 重排多个组时使用。入口不做成常驻按钮，避免和「新建会话」抢视觉。

OPEN待确认

  • 跨组拖拽落在目标组的位置？本稿选「追加到末尾」——跨组时成员在目标组里没有可参照的邻居。若希望「插到指针所在的行」，需要在拖动经过左栏时同时显示目标组的成员预览，复杂度明显上升。
  • 单击行 = 切换勾选，还是「设为当前行」？本稿选前者（没有独立的当前行概念，右栏就是当前组）。副作用是：想拖动一行但手抖没到 5px，就会把它勾上。
  • 组内排序要不要键盘替代？成员多时拖拽仍要滚屏。Alt+↑↓ 对选中成员上下移一位，成本很低（move_session_relative 已经够用）。
  • 刷选的追加语义：本稿「从空白处起拖 = 覆盖选择；按住 Shift = 追加」。如果用户更习惯文件管理器的纯覆盖语义，可以去掉 Shift。
  • 弹框尺寸是否固定？本稿固定 760×522。若希望随窗口自适应，建议只放大右栏、左栏恒 248；小窗口（<900）下弹框改为 92% 宽高。
