MeatShell · 主题与壁纸解耦方案

高保真设计稿 · 2026-10-05 · 主题（Theme）／强调色（Accent）／壁纸（Wallpaper）三层独立
0 · 一句话结论
你的判断成立：主题和壁纸目前是混在一起的，而且是双向混用——壁纸不只是铺在底下，它还反写主题的明暗与强调色。 拆成三层后，界面上真正需要动的不是配色，而是设置面板的信息架构（壁纸页要拆成两页）、顶栏主题控件（单toggle 不够用了）、 以及三个透明度滑杆要各自独立。下面逐项给方案。

1 · 目标模型：三层各自独立
核心原则：壁纸只负责"背后那张图"，不参与任何颜色决策。强调色从主题里独立出来，成为用户可直接选的一等公民。
L1
主题 Theme
一整套中性色阶 + 语义色 + 终端 ANSI 调色板。
决定所有文字与面的可读性，是唯一的"对比度责任人"。
标识：theme = meat-dark
L2
强调色 Accent
8 个预设 + 取色器。用于选中态、主按钮、链接、焦点环。
不再由壁纸决定，也不由主题锁死。
标识：accent = ocean
L3
壁纸 Wallpaper
一张图 + 三个独立透明度（可见度 / 面板 / 终端）。
不读主题，不写主题。可选"跟随图片取色"，默认关。
标识：wallpaper = ""
▼
绘制顺序（改完之后的栈）
z0窗口底色 = 主题 base-bg-root（永远不透明）
z1壁纸图（image-fit: cover，受"壁纸可见度"控制）
z2面板雾面 = 主题面色 + 主题色微染 + "面板不透明度"
z3终端底 = 主题 base-term-bg + "终端不透明度"
z4弹窗 / 菜单 = 主题面色，始终不透明（现状 popup-bg 保持）
与现状的差别
  • 现状 z2 的雾面里混进了 wp-tint（图片平均色）—— 拆掉，这是"界面被壁纸染色"的根源
  • 现状 panel-alpha 一个值同时驱动面板与终端，拖一下全局齐变 —— 拆成两个独立值
  • 现状 z3 终端会"霜化"（半透），导致浅色终端在亮壁纸上文字发飘 —— 拆分后终端有独立下限保护

终端是唯一承载不可控 ANSI 输出的区域，因此拆出硬约束：
term-alpha = max(0.75, 终端不透明度)
修掉现状里"浅色终端 + 亮壁纸 = 文字发飘"这个只有用户自己能发现的坑。
2 · 主题预设设计（4 套色系 × 明/暗 = 8 个变体）
设计约束：4 套色系都按同一套语义槽位填色（root / panel / panel-alt / elevated / hover / active / line / line-strong / text ×3 / term）， 所以切换主题不产生任何布局位移 —— 只有颜色变。点卡片可实时看终端小样换肤。

调整 ⑤　随主题变化的数据：终端 ANSI + 分组色（无布局影响，但必须改）
终端 ANSI 调色板：2 套 → 8 套
位置现状改后
presentation.rs:654ANSI16_DARK / ANSI16_LIGHT 二选一 按 theme_id 取 8 套之一
terminal_ui.rs:233buffer 上只挂 is_dark: bool 改挂 palette_id: u8，切主题时全量重渲染

为什么必须做：Nord / Solarized / Tokyo Night 这类主题的 ANSI 16 色是主题身份的一部分。 若终端还用现成两套，主题切换后终端配色会与界面脱节 —— 这是最容易被用户一眼看出的破绽。
分组色 24 色：2 套 → 8 套
位置改法
theme.slint:244-255 group-color-dark / group-color-light 两组 24 色 → 改为按主题查表；每套主题的 24 色按其明度重新取档，保证 1px 树线在各自背景上清晰
这套取色面板（右键菜单 → 分组颜色）必须跟着主题走，否则会出现"在浅色主题里选了深红、在深色主题里选了亮红"的不一致。
单窗口主题的传播
现状 broadcast_config_changed 只在主题翻转时广播，壁纸不广播。 拆开后壁纸也要广播（因为遮罩影响所有独立窗口的观感）， 独立窗口需同步的属性从 4 个（wallpaper_active / wp_accent / wp_tint / dark） 改为 theme_id / accent / wallpaper / panel_alpha / term_alpha 共 5 个。
4 · 是否支持自定义主题：支持，分三级

6 · 需要你定的三件事
① 4 套色系选哪 4 套
方案给了「原味 Meat / 深海 Abyss / 松石 Verdigris / 炭焙 Charcoal」。也可以换成 Nord / Solarized / Tokyo Night / Gruvbox 这类社区成熟色系 —— 后者辨识度高但撞脸其它终端软件。 倾向哪一边？
② 是否保留"跟随图片取色"
这是唯一让壁纸反向影响界面的开关。默认关能保证解耦干净；开则保留一点"惊艳感"。 我的建议：保留但默认关，并在取色时明确提示"强调色将跟随图片"。
③ L3 自定义主题文件做不做
L1/L2 已能覆盖绝大多数人。L3 是 2–3 天的工程 + 长期格式兼容负担。 建议第一版只做 L1/L2，等有人真需要再上。
本页只是方案，未改动任何代码。定稿后按"先出这一页的确认 → 再改 theme.slint → 再改设置页 → 再迁移 → 最后打包"的顺序推进。
