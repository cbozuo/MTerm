默认不覆盖。所有远端写操作都应走同一套 mtime 比对。

🔴 这是本稿唯一一个「数据安全」级别的项，不是体验优化。 现状 src/app/sftp_callbacks.rs:850-866 保存时直接 h.write_text(path, content)， 不做任何远端状态检查——你在编辑期间远端文件被别人改了 / 被日志轮转替换了 / 被部署脚本覆盖了， MTerm 会静默覆盖。而 mtime 明明拿得到（sftp.rs:2161 已在文件面板显示修改时间）。
做法：打开时记住 mtime + size → 保存前 sftp.metadata() 比对 → 不一致则弹本框。 四个选项里默认不覆盖。「三方合并」只在双方改的是不同行时自动做，改的是同一行才需要人工选。

1 2 3 4
1编辑器里 Ctrl+Enter = 把当前行送进同会话终端并回车；状态栏有绿色「执行当前行」按钮
2编辑器里的选区可以直接喂给终端（Ctrl+Shift+Enter = 校验语法，如 bash -n）
3终端输出里的 file.conf:42:12 被识别成位置，点击直接跳到编辑器第 42 行
4命令面板的「重载服务」预设 → systemctl reload myapp 送进终端

为什么这是 MTerm 最值得做的一条：MTerm 的编辑器开在同一个 SSH 会话里，终端就在旁边—— iShellPro / Termius 这类以移动端为主的工具做不到这件事，而 MTerm 做得到，而且不需要自研编辑内核。 它把「改配置」和「重启服务」这两个动作接成一条链路，正好覆盖运维 60% 的日常动作。
实现上需要三样东西：① 找到同会话的终端输入口（MTerm 已有终端输入通道）； ② 终端输出流里做 path:line:col 正则匹配，把位置变成可点击片段； ③ 命令模板表（预设 systemctl reload/restart、nginx -t、bash -n 等）。

移动端为什么必须单独设计：MTerm 的四平台里包含 Android，而 v1/v2 的桌面交互（键盘命令集、 多光标、状态栏信息密度）在触屏上都不成立。移动端的核心动作只有四个：看、改、存、执行—— 所以手势只需覆盖这四个，其余（命令面板、编码设置、格式化）全部收进命令面板， 不要在移动端暴露桌面级设置项。

现状是硬拒绝（sftp.rs:1710-1712：512 KB / 20000 行 / 单行 64 KB），改造后改为逐档降级。

档位能力桌面Android取舍
F3可编辑 + 语法高亮≤ 4 MB≤ 1 MB行高统一 + 全量 tokenize 的成本上限
F2可编辑，无高亮≤ 10 MB≤ 2 MB关掉高亮省一次全量扫描，其余不变
F1只读浏览（滚动 / 查找 / 复制）≤ 50 MB≤ 10 MB不建行模型、不高亮，按需切行；峰值内存 ≈ 3× 文件大小
