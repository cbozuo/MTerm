Quick Command Manager / HIFI

管理快捷命令，先给「找」一个地方

现有管理弹框是「上半张表单 + 下半张列表」：表单常驻占掉 40% 高度，命令只有一行 elide， 分组操作全靠右键菜单。参考 iShellPro 的指令管理页，把结构换成左栏分组导航 + 右栏卡片墙—— 卡片上名称与两行命令预览同屏，找得到、认得出；表单收进二级编辑卡，浏览空间还给列表； 勾选浮出批量条，移动/删除不再进菜单里翻。MTerm 特有的「点击执行 / 只填入」语义做成卡片徽标，点一下即切换。 整体与《分组管理》高保真稿同族：同尺寸、同行语言、同一套底部完成条。

01左导航 · 右卡片墙左栏只做分组导航（全部 / 默认 / 自定义 + 计数），右栏 2 列卡片网格。管理弹框从「一张表」变成「一个工作台」。
02两行命令预览卡片直接展示名称 + 两行 mono 预览，不用点开就能确认是哪条——列表行 38px 时代一行 elide 看不出命令差异。
03表单退役，编辑卡登场常驻表单收进二级卡（名称 / 分组下拉 / 命令 / 发送方式分段），点开才出现；新建与编辑共用一张卡。
04「执行 / 填入」徽标即开关send_enter 语义常驻卡片右上角：accent 底「执行」/ 灰底「填入」，点徽标直接切换并落盘，不用进编辑卡。
05勾选即批量点卡片任意位置即勾选（与分组管理同手势），浮出批量条：已选 N / 全选 / 移动至 ▾ / 删除；删除进入内联确认态。
06「全部分组」总览默认落在「全部分组」，一次看所有命令；每卡显示所属分组 chip。搜索跨组命中时同一语言。
07拖拽移动与排序卡片拖到左栏组行 = 整批移动（+N 徽标预告范围）；组视图内卡片间拖动 = 组内排序，2px 插入线给落点。
08分组动作收敛双击左栏组名 = 行内改名；自定义组头部垃圾桶 = 唯一删除入口（内联删除条，组员去向可选）；默认分组兜底不可删。
09与《分组管理》同族760×560、52px 头、48px 完成条、DialogClose 关闭键、accent-soft 计数胶囊——同一套肌肉记忆，零学习成本。

状态与边界

STATE必须存在且好看的态
  • 一条都没有：右栏换虚线投递区「还没有快捷命令」+ ＋ 新建第一条 主按钮，不放空文案了事。
  • 空分组：虚线投递区「把命令拖到这里，或用批量条从其他分组移入」。
  • 搜索无结果：全局无命中 =「没有匹配的快捷命令」+「清除搜索」；仅本组没有 =「本分组没有匹配 · 其他分组还有 N 条」+ 跳转按钮。
  • 批量态：勾满当前列表时「全选」变「清除全选」；确认态下其他按钮隐藏，只剩取消/删除。
  • 编辑卡校验：名称 / 命令为空时保存置灰 + 红字即时提示；保存 恒在（disabled 表达），不做二次弹窗。
  • 组很多：左栏滚动，＋ 新建分组 吸底不随内容滚走。
  • 命令很长：卡片预览固定两行截断（-webkit-line-clamp 语义），完整内容靠编辑卡与悬浮看全。
GUARD刻意不做的事
  • 不造新数据字段：iShellPro 卡片有创建日期，但 MTerm 的 QuickCommand{name,command,group,send_enter} 没有时间概念——不为装饰加字段，元信息行放「所属分组 + 发送方式」这两个真实存在的语义。
  • 不给分组上色：会话分组有 group_colors，快捷命令分组刻意不引入——「默认就是没有色彩的」，左栏用 folder 图标承担分组视觉锚点。
  • 不做组嵌套：与分组管理同一口径，单层结构，靠搜索与「全部分组」兜住规模。
  • 单条删除不做确认：命令是低成本可重建物，悬停删除 + 底栏反馈足够；批量删除才进内联确认态（代价不对称，闸门只设在不可逆的大口）。
  • 「全部分组」不提供排序：跨组拖动排序没有相邻语义（数据模型本就是组内有序），排序只在单组视图出现。
  • 不做「点击卡片打开执行」：管理弹框里点击已经用于勾选；执行发生在终端那边（命令栏 chip / 面板），两处职责不混。

待确认

  • 默认视图落在「全部分组」还是延续现状「默认分组」？我倾向全部分组——管理弹框的多数场景是「找一条来改」，总览先给全貌；命令栏 chip / 面板才是执行场景。
  • 卡片徽标点击即切换 send_enter 很快，但 18px 高的目标也容易误触。保守方案是收进编辑卡、徽标只读——你更看重哪个？
  • 命令预览用 mono 画（专业感 + 与终端同语言），但实机 mono 链无 CJK（#54），中文命令会回落 UI 字体。可接受「拉丁 mono / 中文 sans 混排」，还是干脆统一 UI 字体？
  • 「全部分组」视图下卡片是否需要按分组分段（小节头）而不是平铺 + chip？命令超过 20 条后小节头更好扫，但会牺牲一屏卡片数。
  • 删除单条现状就是立即删，本稿沿用（底栏反馈兜底）。如果希望更稳，单删也可以走批量条那条内联确认，代价是每次多一击。
