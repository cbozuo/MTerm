REDESIGN / SEND COMMAND / 2026-11-06

「发送命令」不是一个输入框，
是一台发射台。

写什么 · 发给谁 · 安不安全 · 落没落

方案 E 已经把「编辑 + 命令库」做对了，但“发给谁”仍挤在页脚一个文字键里，“落没落”只有一行汇总。 这次不新增能力，只把页面结构重新排一次：右侧常驻投递栏、逐台回执、发送条左侧的危险状态位。 数据全部来自现有的 targets 与 receipt，不改一行代码，只交可交互高保真。

01 / TARGETS

目标，从页脚搬到右栏

主机名、频道、在线状态、当前标签页常驻可见；发送前就知道会打到哪几台。

02 / RECEIPT

回执，从汇总变成逐台

每台一行结果，失败可一键收窄目标重试，成功/失败可复制回终端。

03 / DANGER

警告，贴着发送动作

行号槽三角 + 发送条左侧的红色状态提示；首次点击只 arm，不发射。

01

先把四个问题分开

发送命令的复杂度不在“输入”，而在输入之后的三个判断。结构要围绕这四个问题排，而不是围绕一个输入框排。

Q1 · 写什么

多行编辑器 保留

等宽字体、动态行号、横向平移、块/下划线光标、宏粘贴。方案 E 已经稳定，这次只让编辑器变宽。

Q2 · 发给谁

目标可见性 重构

当前只有页脚左侧一个范围键，打开前不知道具体主机；多选频道和主机藏在二级菜单里。

Q3 · 安不安全

危险识别 保留

Rust 单一来源检测危险词与续行风险，首次点击只 arm。逻辑不动，只把警告从底部横幅搬到动作旁。

Q4 · 落没落

逐台回执 重构

SendReceiptItem 已经有 id/ok，但 UI 只显示“2 failed · 1 ok”，看不到是哪两台、也没法按失败重试。

三条结构原则

PRINCIPLES
01

常驻，不打断

目标列表留在窗口右侧，而不是发送前弹一个模态框。用户一边写命令，一边能看见会打到哪几台。

02

警告贴近动作，回执贴近目标

危险状态提示并入发送条左侧；每台机器的结果回到它所在的那一行。空间位置就是因果位置。

03

一个画面只有一个主动作

整窗只有「发送」是 filled button；重试、复制、收起全部是 ghost。危险态只改这一个按钮的文案与颜色。

为什么不加功能也要重排？
因为页脚 56px 同时承担了范围、送达方式、状态、提示卡、发送五个职责。加到第 8 台主机时，它不是“信息密度高”，而是层级塌了。

940 × 600 默认（方案 E 为 760×500），最小 800 × 540。1366×768 笔记本上左右各留 213px，仍能完整显示。
右栏

发送条
56px：左侧只在多行时出现「逐行回车 / 整段粘贴」胶囊；中间一句状态；右侧 Ctrl+Enter 与发送。
纵向顺序
编辑器 → 发送条。危险与风险提示并入发送条左侧状态位，不再设独立风险带；信息只出现一次。
数据
全部来自现有属性：targets: [SendTarget]、receipt: [SendReceiptItem]、scopes: [SendScope]、host-sel、receipt-bad/ok。不新增任何回调。

为什么是右栏，不是底部抽屉？ 终端用户看主机列表的习惯是从上往下扫，右栏与编辑器并排，能在不遮挡命令的前提下提供 7–8 台的垂直容量；底部抽屉会挤压编辑器高度，并且需要一次额外展开。

01

先试危险：点「危险 · rm -rf」，观察行号槽三角与发送条左下角的红色状态；第一次点发送只会进入「再点一次确认」，3 秒内不点会自动解除。

02

再试范围：点右栏顶部「频道 A」，切到「主机」页签可以多选；切段时另一侧选择自动清空，两种范围互斥。应用后目标列表与发送条同步变化，回执会清空。

03

最后试回执：发送后右栏逐台变绿/变红；「重试失败」只保留失败主机，「复制结果」把逐台结果按行写入剪贴板。

边界情况

EDGE CASES
空命令
发送按钮 disabled，Ctrl+Enter 不动作，不弹 toast 噪音。
无目标
右栏空态「没有可送达的标签页」，发送按钮 disabled。
离线主机
保留在列表但置灰、不计数、不参与发送；范围里显示「4 台 · 1 台离线」。
多行 sudo
发送条提示「sudo 行可能被当作密码」；不阻断发送。
续行风险
未闭合引号 / here-doc / 块结构自动切「整段粘贴」，用户可手动改回。
改字解除
任何输入变化立即解除 armed；避免“红色按钮 + 旧命令”错配。
重试
目标收窄到失败主机，回执清空，草稿保留，不自动发送。
关窗
标题栏 × / Esc：隐藏窗口，草稿与范围保留；重开即恢复。

07

落地拆分与验收

只改一个 Slint 文件的布局与样式，分三步走；每一步都能单独截图验收，不会把风险堆到最后。

P1 · 结构重排约 1.5d
  • win-body 改双列：编辑器 + 280px 投递栏
  • ScopeButton 从 footer 移到 rail-head，沿用组件
  • targets 列表 + 当前标签页标识 + 收起态
  • 窗口尺寸 940×600 / min 800×540
P2 · 回执与警告约 1d
  • receipt 逐台行尾状态（ok / fail / pending）
  • footer 汇总 + 重试失败 + 复制结果
  • 危险/风险提示并入 sendbar 左侧状态位，不设独立风险带
  • 行号槽危险三角（只看 danger-token）
P3 · 打磨约 0.5d
  • 命令库从居中改为锚定标题栏按钮
  • 范围弹层两段式（频道 | 主机）+ 主机搜索
  • 亮暗主题对比度与 125% 缩放检查
  • Esc 层级、焦点环、减少动效偏好
