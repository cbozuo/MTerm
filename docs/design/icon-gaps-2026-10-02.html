1. P0 tunnel —— 代码已在用，库里没有

sftp_panel.slint:391 用 \u{E0B6} 作为 Tunnels 面板的 tab 图标， 而该面板是一套完整的端口转发实现（tunnel-kind local/dynamic、tunnel-bind/bind-port/host/host-port、 tunnel-add/tunnel-stop，类型目前还用字面量 -L/-D 标注）。 会话对话框里也有「Port forwarding」。库里没有这个码位的图形，迁移会漏。
① 管道 + 箭头推荐
两条平行壁 + 箭头在管内穿过
墨量 0.196最高相关 0.155（plug）
「隧道」直译：管道壁 + 穿行方向。三个候选里相关度最低，且语义最贴
② 两侧边界 + 穿透箭头
两条竖线 + 横箭头穿过
墨量 0.196最高相关 0.266（plug）
「穿透」感更强；但与 split-vertical（框 + 竖线）同一族
③ 中转枢纽（waypoints 形）
中心点 + 四向连接
墨量 0.247最高相关 0.283（split-vertical）
表达「中转到别处」；不过更像「网络拓扑」而非端口转发
推荐 ① 管道 + 箭头：语义是「隧道」（两条平行壁 = 管道）+ 穿行方向， 且它与库里所有图标的最高相关度只有 0.155（vs plug）—— 是三个候选里最干净的。

这三个的优先级取决于是否真的有图标位：
· clear（清空缓冲）是菜单项「Clear buffer」，菜单项通常都带图标 → 建议补。
· key 目前只出现在会话对话框的「Key passphrase」表单字段里，表单字段一般不带图标 —— 除非将来做密钥库/密钥管理（Termius 有，本工具目前没有）。
· route（跳板 / 代理）同理，是「Jump host」「Proxy address」两个表单字段。所以标为"未测"。

4. 明确不该凭「主流有」就加的

主流同类工具确实有这些，但本工具没有对应功能。先加图标会造出空按钮。

6. 建议顺序

序项理由
1补 tunnel（管道 + 箭头） 唯一「代码已在引用、库里没有」的图形缺口，不补会漏
2补 warning + arrow-left/arrow-right 把 3 处字面量换成真图标；三个新形与邻居的相关度都 < 0.30
3统一 resize 手柄（◢ / drag-grip / open-in-full） 不是缺图标，是三种形态并存，属一致性问题
4补 clear（清空缓冲）菜单项需要图标与上下条目对齐
5接入那 13 个已备好的图标比新增更划算
—key / route取决于是否要做密钥库 / 表单是否要图标
